## OpenClaw란

OpenClaw는 오픈 소스 셀프 호스팅 개인 AI 어시스턴트이자 게이트웨이입니다. WhatsApp, Slack, Discord, Telegram, iMessage, WebChat 같은 채팅 채널을 AI 에이전트에 연결합니다. 이 구성은 Capriole AI를 사용자 지정 모델 제공자 세 개로 추가하며, 각 제공자는 Capriole AI가 제공하는 API 프로토콜 하나에 대응합니다.

## 사전 준비

시작하기 전에 다음이 있는지 확인하세요.

- Capriole AI 계정([여기에서 가입](https://capriole.ai))
- Capriole AI API key([키 받기](https://capriole.ai?view=api))

## 설치

공식 설치 스크립트로 OpenClaw를 설치하세요.

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

그런 다음 OpenClaw 자체 설정을 완료하세요.

```bash
openclaw onboard
```

## 구성

### 모델 검증

OpenClaw 2026.4.21 버전은 아래 구성으로 지원 모델 섹션의 모든 모델에서 Capriole AI를 통한 파일 읽기, 파일 쓰기, 최종 답변 검사를 통과합니다.

각 설정의 역할은 다음과 같습니다.

- `capriole-ai-openai`는 GPT 모델을 Responses API로 보냅니다. `capriole-ai-anthropic`은 Claude 모델을 Anthropic Messages로 보냅니다. `capriole-ai-compatible`은 Gemini, Grok, GLM, Kimi 모델을 Chat Completions로 보냅니다.
- `${CAPRIOLE_AI_API_KEY}`는 환경 변수에서 키를 읽습니다.
- `authorization-bearer`를 지정한 `request.auth`는 Anthropic 제공자가 키를 Bearer 토큰으로 보내게 합니다. 이 설정이 없으면 키가 `x-api-key` 헤더로 전송되는데, Capriole AI는 이를 받지 않습니다.
- OpenClaw가 `/v1/messages`를 직접 추가하므로 Anthropic `baseUrl`에는 `/v1`이 없습니다.
- Opus 5.5의 `reasoning`은 `false`입니다. `true`이면 OpenClaw가 thinking 예산을 보내고, Opus 5.5는 `requires adaptive thinking`으로 이를 거부합니다.
- `contextWindow`와 `maxTokens`는 OpenClaw에 각 모델의 한도를 알려 줍니다.
- `agents.defaults.models`는 에이전트가 사용할 수 있는 모델 목록입니다. `agents.defaults.model.primary`는 기본 모델입니다.

## OpenClaw 실행

OpenClaw를 시작하는 모든 터미널에서 키를 내보내세요.

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
```

게이트웨이를 시작하세요.

```bash
openclaw gateway
```

다른 터미널에서 터미널 UI를 여세요.

```bash
openclaw tui
```

게이트웨이 없이 로컬에서 일회성으로 실행하려면 다음을 사용하세요.

```bash
openclaw agent --local --session-id capriole-test --message "Summarize the files in my workspace."
```

## 지원 모델

모델 참조는 `<provider-id>/<model-id>` 형식을 사용합니다.

| 모델 | 모델 참조 | 프로토콜 |
| --- | --- | --- |
| OpenAI latest | `capriole-ai-openai/openai-latest` | Responses |
| GPT-6.1 Sol | `capriole-ai-openai/openai/gpt-6.1-sol` | Responses |
| Claude latest | `capriole-ai-anthropic/claude-latest` | Anthropic Messages |
| Opus 5.5 | `capriole-ai-anthropic/claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `capriole-ai-compatible/google/gemini-3.8-flash` | Chat Completions |
| Grok 4.7 | `capriole-ai-compatible/xai/grok-4.7` | Chat Completions |
| GLM 5.3 Flash | `capriole-ai-compatible/zai/glm-5.3-flash` | Chat Completions |
| Kimi K3.1 Pro | `capriole-ai-compatible/moonshot/kimi-k3.1-pro` | Chat Completions |
| Kimi K3 | `capriole-ai-compatible/moonshot/kimi-k3` | Chat Completions |

`openai-latest`와 `claude-latest`는 항상 각 계열의 최신 플래그십 모델을 가리킵니다.

## 문제 해결

### 인증이 실패하는 이유는 무엇인가요?

`openclaw gateway` 또는 `openclaw agent`를 시작하는 터미널에서 `CAPRIOLE_AI_API_KEY`를 내보내세요. 변수가 설정되지 않으면 OpenClaw는 `missing env var`를 출력합니다.

### Opus 5.5가 `requires adaptive thinking`으로 실패하는 이유는 무엇인가요?

`claude-opus-5-5`의 `reasoning`을 `false`로 설정하세요.

### OpenClaw가 모델이 허용되지 않았거나 없다고 보고하는 이유는 무엇인가요?

`openclaw models list`를 실행하세요. 모델 참조가 `agents.defaults.models`에 있는지, 모델 항목에 `id`와 `name`만이 아니라 위에 표시된 전체 객체가 있는지 확인하세요.

### 새 세션이 설정 대화로 시작하는 이유는 무엇인가요?

이는 Capriole AI 문제가 아니라 OpenClaw의 첫 실행 작업 공간 설정입니다. `openclaw tui`에서 한 번 완료하거나 `openclaw onboard`를 다시 실행하세요.

### 게이트웨이가 시작되지 않는 이유는 무엇인가요?

`openclaw status`, `openclaw gateway status`, `openclaw logs --follow`, `openclaw doctor`를 실행하세요.

## 참고

- 다른 Capriole AI 모델을 추가하려면 같은 계열 모델의 항목을 복사하고 ID를 바꾼 다음, 해당 참조를 `agents.defaults.models`에 추가하세요. `GET https://api.caprioletech.com/v1/models`는 모든 모델 ID를 나열합니다.
