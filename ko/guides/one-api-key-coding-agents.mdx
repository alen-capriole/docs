---

하나의 Capriole AI API key로 Codex, Claude Code, Kilo Code, GitHub Copilot CLI, OpenCode, OpenClaw를 인증할 수 있습니다. 키는 같고, Base URL, 프로토콜, 모델 선택자는 구성하는 클라이언트와 일치해야 합니다.

이 가이드로 하나의 Capriole 계정에서 동작하는 에이전트까지 이동하세요. 개인 Premium은 월 USD 8이며, 500만 과금 API 토큰을 포함하고, 지원되는 Premium 모델 세트에서 무제한 Browser Chat도 잠금 해제합니다. 따라서 하나의 멤버십이 브라우저 작업 공간과 유지 중인 에이전트 경로 여섯 개를 모두 커버할 수 있습니다.

개별 통합 페이지가 완전한 클라이언트 구성의 진실 원천입니다.

## 시작하기 전에

다음이 필요합니다.

- 활성 Capriole AI Premium 또는 자격 있는 Team 접근
- [API 페이지](https://capriole.ai?view=api)의 Capriole AI API key
- 설치된 코딩 에이전트 하나 이상
- 환경 변수를 설정할 수 있는 터미널

<Warning>
API key를 저장소와 커밋된 구성 파일 밖에 두세요. 예제는 자리 표시자로 `YOUR_CAPRIOLE_AI_API_KEY`를 사용합니다.
</Warning>

<Note>
이 가이드는 호환성을 증명하기 위해 키 하나를 재사용합니다. 오래 쓰는 구성이나 팀에는 에이전트 또는 사용자마다 이름이 다른 키를 만드세요. 키를 나누면 유출된 자격 증명의 영향이 줄고, API 페이지에서 사용량을 필터링하거나 접근을 독립적으로 취소할 수 있습니다.
</Note>

## 에이전트를 프로토콜에 맞추기

계정 키는 공유해도 각 클라이언트는 만들어진 전송 프로토콜을 유지합니다.

| 에이전트 | Capriole 프로토콜 | Base URL | 시작 모델 | 전체 구성 |
|---|---|---|---|---|
| Codex | OpenAI Responses | `https://api.caprioletech.com/v1` | `openai-latest` | [Codex 구성](/ko/integrations/codex) |
| Claude Code | Anthropic Messages | `https://api.caprioletech.com` | `claude-latest` | [Claude Code 구성](/ko/integrations/claude-code) |
| Kilo Code | Chat Completions | `https://api.caprioletech.com/v1` | `openai-latest` | [Kilo Code 구성](/ko/integrations/kilo-code) |
| GitHub Copilot CLI | Chat Completions, Responses 또는 Messages | 프로토콜별 | 프로토콜별 | [GitHub Copilot CLI 구성](/ko/integrations/github-copilot-cli) |
| OpenCode | Responses, Chat Completions 또는 Messages | 제공자별 | `openai-latest` 또는 `claude-latest` | [OpenCode 구성](/ko/integrations/opencode) |
| OpenClaw | Responses, Chat Completions 또는 Messages | 제공자별 | `openai-latest` 또는 `claude-latest` | [OpenClaw 구성](/ko/integrations/openclaw) |

Responses 및 Chat Completions 경로의 Base URL에는 `/v1`이 포함됩니다. Anthropic Messages 경로는 API 루트를 사용합니다. 통합 페이지에 클라이언트별 어댑터 값이 문서화된 경우는 예외입니다. 일치하는 통합 페이지에서 정확한 값을 복사하세요.

## 공유 키 설정하기

<Steps>
<Step title="Capriole API key 내보내기">

에이전트를 열기 전에 셸 변수 하나를 설정하세요.

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
```

시크릿을 출력하지 않고 변수가 있는지 확인하세요.

```bash
test -n "$CAPRIOLE_AI_API_KEY" && echo "Capriole API key is set"
```

예상 결과는 `Capriole API key is set`입니다.

</Step>

<Step title="클라이언트 경로 선택하기">

표의 통합 페이지를 열고 유지 중인 구성을 복사하세요. 해당 클라이언트가 토큰을 요청하는 곳마다 `CAPRIOLE_AI_API_KEY`의 같은 값을 사용하세요.

- Codex는 `env_key`를 통해 `CAPRIOLE_AI_API_KEY`에서 키를 읽습니다.
- Claude Code는 `ANTHROPIC_AUTH_TOKEN`을 사용합니다. 시작 전에 공유 변수에서 설정하세요.
- Kilo Code는 제공자 구성에서 `{env:CAPRIOLE_AI_API_KEY}`를 참조합니다.
- GitHub Copilot CLI는 OpenAI 호환 경로에서 `COPILOT_PROVIDER_API_KEY`를, Anthropic Messages에서 `COPILOT_PROVIDER_BEARER_TOKEN`을 사용합니다.
- OpenCode 제공자 항목은 제공자 어댑터에 따라 `apiKey` 또는 `authToken`에 Capriole 키를 사용합니다.
- OpenClaw 제공자 항목은 `CUSTOM_API_KEY`를 참조합니다. 게이트웨이를 시작하기 전에 공유 변수에서 설정하세요.

Claude Code의 경우:

```bash
export ANTHROPIC_AUTH_TOKEN="$CAPRIOLE_AI_API_KEY"
```

OpenClaw의 경우:

```bash
export CUSTOM_API_KEY="$CAPRIOLE_AI_API_KEY"
```

</Step>

<Step title="모델을 호환 경로에 두기">

정확한 모델 버전이 필요하지 않으면 유지 중인 별칭으로 시작하세요.

- OpenAI Responses 경로에는 `openai-latest`를 사용하세요.
- Anthropic Messages 경로에는 `claude-latest`를 사용하세요.
- Chat Completions 호환 경로에는 통합 페이지에 나온 모델을 사용하세요.

[현재 모델 카탈로그](/ko/api-reference/endpoint/get)는 공개 API 모델을 나열합니다. Browser Chat 모델이 모든 API 프로토콜에서 자동으로 유효하지는 않습니다.

</Step>

<Step title="에이전트를 시작하고 확인하기">

테스트 프로젝트에서 구성한 클라이언트를 시작하고 다음을 요청하세요.

```text
Reply with CAPRIOLE_OK and no other text.
```

비어 있지 않은 답을 찾으세요. 이상적으로는 요청한 `CAPRIOLE_OK` 마커입니다. 모델이 정확한 출력 프롬프트를 항상 따르지는 않으므로 문구가 다를 수 있습니다.

그런 다음 [API 페이지](https://capriole.ai?view=api)를 열고 요청이 예상 키와 모델 아래 사용량 보기에 나타나는지 확인하세요. 사용량 기록이 클라이언트가 Capriole을 썼다는 결정적 확인입니다. 클라이언트에 다른 제공자나 fallback이 구성되어 있으면 응답만으로는 충분하지 않습니다. [API keys와 사용량 가이드](/ko/guides/api-keys-usage)에 정확한 필터와 키 수명 주기가 나와 있습니다.

이 검사는 모든 도구나 모델 기능을 테스트하지 않습니다.

</Step>
</Steps>

## 성공의 모습

| 확인 | 예상 결과 |
|---|---|
| 환경 | 클라이언트가 키 없음 경고 없이 시작함 |
| 인증 | 첫 모델 요청이 `401`을 반환하지 않음 |
| 엔드포인트 | 요청이 엔드포인트 또는 프로토콜 오류를 반환하지 않음 |
| 모델 | 클라이언트가 구성한 latest 별칭 또는 구체 ID를 받음 |
| 사용량 | 요청이 측정된 API 트래픽으로 API 사용량 보기에 나타남 |

코딩 에이전트 요청은 자격 있는 개인 또는 Team API 잔액을 사용합니다. 무제한 유료 Browser Chat의 일부가 아닙니다. 큰 자동화 워크로드를 실행하기 전에 [Capriole AI 과금 토큰](/ko/articles/charged-tokens)을 읽으세요.

## 흔한 설정 실패 해결하기

| 증상 | 가능한 원인 | 해결 |
|---|---|---|
| `401` 또는 누락된 Bearer 토큰 | 클라이언트가 Capriole 키를 받지 않음 | 에이전트를 시작하는 같은 셸에서 클라이언트별 변수를 내보내기 |
| `404` 또는 프로토콜 오류 | Base URL이 `/v1`을 잘못 포함하거나 빠뜨림 | 일치하는 통합 페이지에서 정확한 Base URL 복사 |
| 지원되지 않는 모델 | 모델이 해당 프로토콜에 속하지 않음 | Responses는 `openai-latest`, Messages는 `claude-latest`로 시작 |
| 클라이언트가 다른 제공자를 사용함 | 내장 제공자 또는 프로젝트 재정의가 우선함 | 사용자 지정 Capriole 제공자를 선택하고 클라이언트를 다시 시작 |
| 허용량을 쓴 뒤 에이전트가 멈춤 | 코딩 에이전트 트래픽이 API 잔액을 소비함 | API 사용량을 검토하고 자격 있는 유료 접근이 활성인 동안 top-up 추가 |

## 다음 페이지 선택하기

이 경로 뒤의 모델이 필요하면 [코딩 에이전트 호환성 글](/ko/articles/coding-agent-compatibility)을 읽으세요. 직접 애플리케이션 코드는 [OpenAI 및 Anthropic SDK 가이드](/ko/guides/openai-anthropic-sdks)로 이어가세요.

[제한된 무료 Browser Chat에서 현재 플래그십 모델을 써 보세요](https://capriole.ai). 코딩 에이전트가 사용할 API key를 만들 준비가 되면 Premium으로 업그레이드하세요.
