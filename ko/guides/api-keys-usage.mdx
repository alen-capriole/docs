Capriole AI API 페이지는 키 관리와 사용량 회계를 한곳에 둡니다. 이름이 있는 키를 만들고, 비활성화하거나 삭제하고, 시간, 키, 모델, 상태로 요청을 필터링하고, 원시 토큰 사용량과 잔액에서 차감된 과금 토큰을 비교할 수 있습니다.

API 접근에는 활성 Premium 멤버십 또는 자격 있는 Team 접근이 필요합니다. 개인 Premium은 월 USD 8이며, 500만 과금 API 토큰과 지원되는 Premium 모델 세트의 무제한 Browser Chat을 포함합니다. 따라서 같은 계정으로 일상 채팅, 애플리케이션 코드, 코딩 에이전트를 다루며 별도의 제공자 키나 청구 페이지가 필요 없습니다.

## 이름이 있는 API key 만들기

<Steps>
<Step title="API 페이지 열기">

[Capriole AI API](https://capriole.ai?view=api)를 열고 로그인하세요. API 접근이 있는 계정에는 **API keys**, **Playground**, **Usage**가 표시됩니다.

</Step>

<Step title="키를 만들고 이름 지정하기">

**Create key**를 선택하세요. **Name (Optional)** 필드로 `local-codex`, `support-agent`, `test-script`처럼 사용할 클라이언트를 표시할 수 있습니다.

오래 쓰는 클라이언트나 팀 구성원에는 이름이 다른 키를 사용하세요. 요청을 더 쉽게 귀속하고, 모든 자격 증명을 바꾸지 않고 한 클라이언트만 취소할 수 있습니다.

</Step>

<Step title="시크릿을 바로 복사하기">

**Create**를 선택한 다음 **Secret key** 대화 상자에서 값을 복사하세요. Capriole은 생성 직후에만 전체 시크릿을 보여 줍니다. 이후 키 목록에는 마스킹된 값이 표시됩니다.

<Warning>
시크릿을 소스 관리, 스크린샷, 지원 메시지, 클라이언트 쪽 애플리케이션 코드에 두지 마세요. 전체 값을 잃으면 대체 키를 만드세요.
</Warning>

</Step>

<Step title="테스트 요청 한 번 보내기">

[API 빠른 시작](/ko/quickstart) 또는 [OpenAI 및 Anthropic SDK 가이드](/ko/guides/openai-anthropic-sdks)를 따르세요. 요청이 끝나면 **Usage**로 돌아가세요.

모델 응답은 유용하지만, 사용량 행이 더 강한 확인입니다. 예상한 키와 모델로 Capriole이 요청을 받았음을 보여 줍니다.

</Step>
</Steps>

## 현재 잔액 읽기

Usage 섹션은 현재 포함된 할당량과 구매한 온디맨드 토큰을 구분합니다.

| 요약 | 의미 |
|---|---|
| **Included usage** | 현재 멤버십 할당량, 청구 주기, 사용한 토큰, 남은 비율 |
| **On-demand usage** | 구매한 top-up 토큰, 사용량, 남은 잔액 |
| **Total requests** | 선택한 사용량 필터 안의 성공 및 실패 요청 |
| **Charged tokens** | 필터링된 성공 사용량에서 차감된 할당량과 함께 총 토큰 및 캐시 토큰 |

**Time** 필터는 요청 분석과 행을 바꿉니다. 청구 주기를 바꾸거나 선택한 기간에 대해 할당량 요약을 다시 계산하지는 않습니다.

캐시 입력 공식과 반올림 규칙은 [Capriole AI 과금 토큰 설명](/ko/articles/charged-tokens)을 확인하세요.

## 요청 기록 필터링하기

한 번에 한 질문에 답하도록 필터를 사용하세요.

| 필터 | 선택 가능한 값 | 유용한 경우 |
|---|---|---|
| **Time** | Last 24 hours, 7 days, 30 days 또는 all time | 배포나 최근 테스트를 분리할 때 |
| **Key** | 모든 키 또는 이름이 있는 키 하나 | 어떤 클라이언트가 트래픽을 보냈는지 확인할 때 |
| **Model** | 보이는 사용량 기록에 있는 모델 | 모델 경로 간 트래픽을 비교할 때 |
| **Status** | 모든 상태, 성공 또는 오류 | 완료된 호출과 실패를 나눌 때 |
| **Member** | owner 및 admin용 팀 구성원 | 사람별로 팀 트래픽을 검토할 때 |

각 요청 행은 시간, 키, 모델, 입력 토큰, 캐시 토큰, 출력 토큰, 과금 토큰, 총 토큰, 지연 시간, 상태, 오류 메시지를 표시할 수 있습니다. 업스트림 응답이나 실패한 요청이 제공하지 않으면 일부 지표는 없을 수 있습니다.

## 클라이언트가 의도한 키를 썼는지 확인하기

테스트 요청을 보낸 뒤:

1. **Time**을 **Last 24 hours**로 설정하세요.
2. 클라이언트가 사용한 이름이 있는 **Key**를 선택하세요.
3. 여러 모델이 있으면 예상 **Model**을 선택하세요.
4. **Status**를 **Success**로 설정하세요.
5. 새 행의 시간과 토큰 활동이 예상과 맞는지 확인하세요.

이 검사는 흔한 구성 실수를 잡습니다. 코딩 도구는 Capriole 구성이 활성화되지 않아도 내장 또는 fallback 제공자를 통해 응답을 만들 수 있습니다. 일치하는 Capriole 사용량 행이 그 모호함을 제거합니다.

## 키 비활성화, 재활성화, 삭제

| 작업 | 결과 | 되돌릴 수 있나요? |
|---|---|---|
| Deactivate | 해당 키를 쓰는 새 요청이 인증되지 않음 | 예, 키를 다시 켜면 됩니다 |
| Reactivate | 기존 키가 다시 인증할 수 있음 | 예 |
| Delete | 키가 영구 제거됨 | 아니요 |

클라이언트를 조사하거나 트래픽을 잠시 멈출 때는 비활성화를 사용하세요. 키를 교체한 뒤, 또는 자격 증명이 노출되었을 수 있으면 삭제하세요.

목록의 **Created**와 **Last used** 값은 오래된 키를 식별하는 데 도움이 됩니다. 표시 상태가 **Inactive**이면 키가 재활성화될 때까지 취소된 것입니다.

## Team 가시성

Team owner와 admin은 구성원별로 사용량을 필터링하고 구성원 간 요청 또는 과금 토큰을 비교할 수 있습니다. 일반 팀 구성원은 해당 구성원에게 허용된 사용량만 봅니다. Team top-up과 팀 전역 컨트롤도 자격 있는 팀 역할로 제한됩니다.

사용량 필터는 Capriole의 내부 제공자 경로, 업스트림 비용, fallback 진단을 노출하지 않습니다. API 접근 관리에 필요한 고객 대면 모델, 요청 결과, 토큰 회계를 보고합니다.

## 여기서 이어가기

[제한된 무료 Browser Chat에서 GPT-6 Astra, Claude Fable 5.1 또는 Gemini 3.1 Pro를 써 보세요](https://capriole.ai). 키를 만들고 포함된 월간 API 잔액을 쓰려면 Premium으로 업그레이드하세요.
