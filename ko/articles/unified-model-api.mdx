Capriole AI는 지원되는 모델 계열 전반에 계정 하나와 API 키 하나를 제공하며, API는 공식 API 가격보다 최대 92% 저렴합니다. 같은 USD 9 Premium 멤버십에는 GPT-6.2 Astra, Claude Fable 5.1, Claude Opus 5.5, Gemini 4 Carbon과의 무제한 웹 채팅도 포함되어, 계정 하나로 애플리케이션, 코딩 에이전트, 일상 채팅을 모두 커버할 수 있습니다.

Capriole은 세 가지 공개 경로를 유지합니다. OpenAI Responses, OpenAI 호환 Chat Completions, Anthropic Messages입니다.

공유 계정과 청구 계층이 그 프로토콜별 경로 위에 있습니다.

## 이것이 Capriole을 더 유용하게 만드는 이유

하나의 USD 9 Premium 멤버십은 지원되는 Premium 모델 세트의 무제한 웹 채팅, 월 500만 과금 API 토큰, 문서화된 코딩 에이전트 경로 10개를 커버합니다. 애플리케이션은 이미 사용하는 프로토콜을 유지하고, 사용자는 Capriole 계정, 키, 잔액, 청구 페이지 하나만 유지합니다.

이것이 제공자 계정을 따로 모으는 것보다 실용적인 이점입니다. [날짜가 있는 비용 비교](/ko/articles/ai-api-cost-comparison)에서는 매월 API 토큰 5,000,000개가 포함된 개인 Premium 구독료 USD 9를 기준으로 삼았습니다. 같은 500만 토큰 워크로드에서 직접 유료 Standard 가격은 USD 6.75에서 USD 90이고, OpenRouter는 게시된 크레딧 구매 수수료 후 USD 7.55에서 USD 94.95입니다. 현재 플래그십 모델의 공식 가격과 개인 Premium 추가 충전 가격(토큰 5,000,000개에 USD 8) 비교는 [Claude API 가격](/ko/articles/claude-api-pricing), [OpenAI API 가격](/ko/articles/openai-api-pricing), [Gemini API 가격](/ko/articles/gemini-api-pricing)에서 확인하세요.

## 공개 경로

| 경로 | 의도된 계약 | 일반적인 용도 |
|---|---|---|
| `POST /v1/chat/completions` | OpenAI 호환 Chat Completions | 호환 클라이언트와 에이전트 |
| `POST /v1/responses` | OpenAI Responses | Responses 기반 애플리케이션과 Codex |
| `POST /v1/messages` | Anthropic Messages | Claude 네이티브 클라이언트와 Claude Code |

성공적으로 라우팅된 응답과 스트리밍 이벤트는 클라이언트가 요청한 프로토콜에 남습니다. Responses 페이로드는 돌아오는 길에 Chat Completions로 변환되지 않습니다. Anthropic Messages 스트림은 OpenAI 출력으로 다시 포장되지 않습니다.

이로써 Responses, Messages, Chat Completions 클라이언트가 기대하는 프로토콜별 동작이 유지됩니다.

공유 계층은 접근과 회계를 처리합니다. 각 공개 경로는 클라이언트가 기대하는 요청 및 응답 계약을 유지합니다. 모델 그룹은 계층이 아니라 경로별 호환성 집합입니다. 각 계약을 구현하면 모델이 지원 경로 둘 이상에 나타날 수 있습니다.

## 엔드포인트 하나로 부족한 이유

모델 계열은 필드 이름 이상에서 서로 다릅니다.

OpenAI Responses는 출력을 타입이 있는 이벤트와 항목으로 표현합니다. Anthropic Messages는 자체 콘텐츠 블록과 스트리밍 이벤트를 사용합니다. Chat Completions는 또 다른 요청 및 응답 형태를 가집니다. Reasoning 제어, 도구 호출, 사용량 데이터, 오류, 토큰 계산 동작도 다릅니다.

얕은 어댑터는 간단한 텍스트 프롬프트를 동작하게 할 수 있습니다. 코딩 에이전트와 프로덕션 클라이언트는 빠진 세부 정보를 빨리 드러냅니다. 스트리밍 순서, 도구 결과 턴, 사용량 메타데이터, 모델별 제어에 의존합니다.

따라서 Capriole은 하나의 인증 및 청구 계층 뒤에 프로토콜을 유지하는 여러 경로를 소유합니다.

## 키 하나, 명시적 모델 선택

모든 공개 생성 경로는 같은 Capriole API 키와 계정 잔액을 사용합니다. 요청한 모델은 여전히 선택한 프로토콜에 속해야 합니다.

예를 들어 Responses 경로는 유지 중인 OpenAI 별칭, 지원되는 Responses 호환 OpenAI 모델, 그리고 `xai/` 접두사를 붙여 보낸 Grok 모델을 받습니다. Messages 경로는 유지 중인 Claude 별칭과 지원되는 Claude Messages 모델 ID를 받습니다. 호환 채팅 경로는 더 넓은 공개 채팅 모델 집합을 노출할 수 있습니다.

각 경로는 전달 전에 모델 ID를 검증합니다. 유효하지 않은 ID에는 검증 오류가 반환되므로, 클라이언트에서 모델이나 엔드포인트를 수정한 뒤 다시 시도할 수 있습니다.

## Latest 별칭과 재현 가능한 ID

Capriole은 지원하는 공개 경로에 `openai-latest`, `claude-latest`, `google-latest` 같은 유지 중인 별칭을 노출합니다.

별칭은 업스트림 전달 전에 해석됩니다. 사용량, 할당량, 대체 경로 전환 기록은 모호한 “latest” 버킷이 아니라 해석된 정규 모델에 붙습니다.

지원 릴리스와 함께 Capriole의 유지 중인 기본값이 움직이게 하려면 별칭을 사용하세요. 정확한 버전이 결과의 일부이고 재현 가능해야 하면 구체적인 모델 ID를 사용하세요.

[모델 목록 엔드포인트](/ko/api-reference/endpoint/get)가 현재 공개 목록입니다.

## 대체 경로 전환은 응답이 시작되기 전에 일어납니다

지원 경로에서 Capriole은 응답 바이트가 보내지기 전에 첫 소스가 실패하면 다른 구성된 소스를 시도할 수 있습니다.

스트리밍이 시작되면 같은 소스를 사용합니다.

지원되는 소스로 대체 경로 전환이 일어나도 요청한 모델 키는 유지됩니다. Capriole은 전달 소스를 바꾸며, 사용자가 명시한 모델 선택은 바꾸지 않습니다.

웹 채팅은 별도로 선택적 모델 자동 전환과 [대화 안에서의 수동 모델 변경](/ko/articles/switch-models-mid-chat)을 제공할 수 있습니다. 이는 작업 공간 동작이며, API 자체의 대체 경로 규칙과는 별개입니다.

## 사용량은 계속 보입니다

프로그래밍 워크로드는 측정됩니다. Capriole은 일치하는 프로토콜이 제공한 메타데이터에서 사용량을 기록하며, 사용량을 사용할 수 있으면 완료된 스트리밍 응답도 포함합니다.

Premium은 현재 **월 5,000,000 과금 API 토큰**을 포함합니다. Capriole은 이 잔액에서 캐시되지 않은 입력과 출력을 100%, 캐시된 입력을 10%로 계산합니다. 추가 토큰 팩은 충전으로 구매할 수 있습니다.

[과금 토큰 글](/ko/articles/charged-tokens)에 정확한 공식, 올림 규칙, 재현 가능한 예시가 있습니다.

웹 채팅과 자동화 API 워크로드는 별도 허용량을 사용합니다. 수백만 토큰을 처리하는 코딩 에이전트는 보이는 과금 토큰 잔액에서 가져갑니다.

## 통합 계층이 실제로 제공하는 것

유용한 공통 계층은 하나의 응답 스키마가 아닙니다. 주변 제품 계약입니다.

- Capriole 계정과 API 키 하나
- 보이는 API 잔액 하나
- 유지 중인 모델 별칭
- 선택한 프로토콜에 대한 검증
- 출력이 시작되기 전의 지원 소스 대체 경로 전환
- 해석된 모델에 대한 사용량 회계
- 애플리케이션과 코딩 에이전트를 위한 문서화된 설정

클라이언트는 프로토콜에 의존하므로 프로토콜은 명시적으로 남습니다.

## 호환성을 테스트하는 방법

Capriole은 프로토콜 계약과 대표적인 실제 클라이언트 흐름이 모두 통과한 뒤에야 경로를 지원으로 문서화합니다. 성공한 텍스트 프롬프트는 초기 검사입니다. 스트리밍, 도구 결과 턴, 별칭 해석, 사용량 회계, 네거티브 프로토콜 테스트가 나머지 증거를 제공합니다.

집중된 공개 경로 및 파일 변환 스위트는 프로덕션 실시간 호출이 아니라 제어된 업스트림 응답에 대해 **68개의 자동 테스트**를 완료했습니다. 별도의 로컬 업스트림 및 코딩 에이전트 실행은 mocked 엔드포인트가 증명할 수 없는 동작을 확인합니다.

| 테스트 레인 | 검증된 증거 | 현재 경계 |
|---|---|---|
| OpenAI Responses | 비스트리밍 출력, SSE 완료, function call, 상태 없는 function-result 후속, `openai-latest` | OpenAI 모델과 `xai/` 접두사가 붙은 Grok 모델 |
| Chat Completions | 비스트리밍 출력, SSE 완료, tool call, tool-result 후속, 유지 중인 latest 별칭 세 개 모두 | 선택한 모델이 호환 경로를 지원해야 함 |
| Anthropic Messages | 비스트리밍 출력, Anthropic SSE, `tool_use`, `tool_result`, `claude-latest` | Claude Messages 모델만 |
| Latest 별칭 | 엔드포인트 게이팅, 정규 해석, 정규 사용량 행, 대표적인 클라이언트 실행 | 별칭은 입력 선택자이며 별도 사용량 모델을 만들지 않음 |
| 웹 채팅의 파일 | 이미지, PDF, 텍스트, DOCX, PPTX, CSV, XLS, XLSX의 파일 종류 감지, 변환, 모델 페이로드 조립 | 이 증거는 웹 채팅 작업 공간에 속함 |

스트림 검사는 전체 응답을 소비하고 각 프로토콜 고유의 종료 이벤트를 요구합니다. Responses는 완료 이벤트로 끝나고, Chat Completions는 `[DONE]`에 도달하며, Messages는 `message_stop`에 도달합니다. 도구 테스트는 도구 결과를 다시 보내고 최종 assistant 턴을 요구합니다.

검증 테스트는 각 엔드포인트에서 지원하는 모델 별칭을 확인합니다. `google-latest`는 Chat Completions에, `openai-latest`는 Responses 또는 Chat Completions에 사용하세요.

브라우저 채팅에서 파일을 첨부하려면 [지원 파일 형식과 업로드 방법](/ko/guides/files-web-search)을 확인하세요.

## 이미 가진 클라이언트부터 시작하기

애플리케이션이 Chat Completions를 사용하면 [Chat Completions 레퍼런스](/ko/api-reference/endpoint/chat-completions)를 따르세요. Responses 기반이면 [Responses 레퍼런스](/ko/api-reference/endpoint/responses)를 사용하세요. Claude 네이티브 클라이언트는 [Messages 레퍼런스](/ko/api-reference/endpoint/messages)를 사용해야 합니다.

첫 요청은 [API 빠른 시작](/ko/quickstart)부터 시작하세요. Python 개발자는 [OpenAI 및 Anthropic SDK 가이드](/ko/guides/openai-anthropic-sdks)를 따를 수 있습니다. 코딩 에이전트 사용자는 [코딩 에이전트용 하나의 API](/ko/articles/coding-agent-compatibility)에서 유지 중인 클라이언트 행렬을 볼 수 있습니다. [LLM 게이트웨이 보안 위험](/ko/articles/llm-gateway-security)에서는 어떤 게이트웨이든 코드를 보내기 전에 확인할 점을 정리합니다.

Capriole의 역할은 클라이언트가 실제로 말하는 프로토콜을 존중하면서 계정과 접근 파편화를 제거하는 것입니다. [무료 웹 채팅에서 지원 플래그십 모델을 써 본 다음](https://www.capriole.ai/ko), [USD 9 Premium으로 업그레이드해 API 키를 만드세요](https://www.capriole.ai/ko?view=api).
