서드파티 LLM 게이트웨이를 쓰면 프롬프트와 코드를 보는 회사가 하나 더 늘어납니다. 이 회사는 그 내용을 로그에 남길 수 있고, 도구가 쓰는 API key를 보관하며, 각 요청을 내가 고르지 않았을 수도 있는 모델 제공사로 전달합니다. 게이트웨이로 소스 코드를 보내기 전에 무엇을 얼마나 오래 저장하는지, 콘텐츠로 학습하는지, 어떤 회사와 국가가 요청을 받는지, 키는 어떻게 폐기하는지, 제공사에 장애가 나면 어떻게 되는지 확인하세요.

Capriole AI도 이런 게이트웨이 중 하나입니다. 월 USD 9에 GPT-6 Astra, Claude Fable 5.1, Claude Opus 5.5, Gemini 4 Argon과의 웹 채팅을 무제한으로 제공하며, 앱과 코딩 에이전트에 쓰는 API는 공식 API 가격보다 최대 92% 저렴합니다. 아래에서는 질문마다 Capriole AI 자체 문서에 근거한 답을 붙였으며, 제공하지 않는 것도 함께 밝힙니다.

## 위험, 확인할 질문, Capriole AI의 답변

| 위험 | 확인할 질문 | Capriole AI의 답변 |
|---|---|---|
| 콘텐츠 로그 기록 | 요청과 응답 내용을 저장하나요? 얼마나 오래, 누가 읽을 수 있나요? | API는 요청이나 응답 내용을 보관하지 않고, 요청마다 시간, 모델, 토큰 수 같은 사용 기록만 남깁니다. [API가 보관하는 정보](/ko/guides/privacy-and-security#api가-보관하는-정보) |
| 학습 | 게이트웨이가 내 콘텐츠로 학습하나요? 요청을 전달받는 제공사는요? | Capriole AI는 채팅, 파일, API 콘텐츠를 AI 모델 학습에 사용하지 않습니다. 각 제공사는 자체 약관에 따라 요청을 처리합니다. [학습](/ko/guides/privacy-and-security#콘텐츠는-학습에-쓰이지-않습니다) |
| 업스트림 노출 | 각 요청을 어떤 회사가, 누구의 약관에 따라 받나요? | 답변하는 모델 제공사 또는 그 모델을 호스팅하는 클라우드 플랫폼이 받습니다. 그 과정에서 인프라 제공사가 요청을 전달합니다. [데이터를 받는 곳](/ko/guides/privacy-and-security#데이터를-받는-곳) |
| 데이터 위치 | 서버와 데이터베이스는 어디에 있나요? 제공사는 어디에서 데이터를 처리하나요? | 주 서버와 데이터베이스는 인도에 있고, 제공사는 미국을 비롯한 다른 국가에서 데이터를 처리합니다. 연결은 암호화됩니다. [보안](/ko/guides/privacy-and-security#보안) |
| 키 오용 | 키를 비활성화하고 삭제할 수 있나요? 키별 사용량을 볼 수 있나요? | 예. 키마다 이름을 붙일 수 있고, 전체 시크릿은 한 번만 표시되며, 키를 비활성화하거나 삭제하고 키별로 사용량을 필터링할 수 있습니다. [키 관리](/ko/guides/api-keys-usage#키-비활성화-재활성화-삭제) |
| 지출 폭주 | 지출에 상한이 있나요? | API 사용량은 선불 토큰 잔액에서 차감되며, 잔액이 바닥나면 에이전트가 멈춥니다. Team에서는 소유자와 관리자가 멤버별로 상한을 설정할 수 있습니다. [알림 토큰과 한도 토큰](/ko/guides/team-plan#알림-토큰과-한도-토큰-설정하기) |
| 팀 접근 | 팀에서 누가 누구의 사용량을 볼 수 있나요? | Team 소유자와 관리자는 각 멤버의 이메일, 역할, Team API 사용량을 봅니다. [데이터를 받는 곳](/ko/guides/privacy-and-security#데이터를-받는-곳) |
| 알림 없는 fallback | 게이트웨이는 언제 fallback하며, 선택한 모델은 유지되나요? | 응답이 시작되기 전에만 일어나며, 요청한 모델은 그대로 유지됩니다. [Fallback](/ko/articles/unified-model-api#fallback은-응답이-시작되기-전에-일어납니다) |

게이트웨이는 프롬프트 인젝션이나 코딩 에이전트가 내 컴퓨터에서 하는 일까지 막아 주지는 않습니다. 에이전트는 여전히 로컬에서 파일을 읽고 명령을 실행하므로, 에이전트 자체의 권한 설정도 게이트웨이만큼 중요합니다.

웹 채팅 기록은 API와 별개이며, 계정에 보관할지, 브라우저에만 둘지, 아예 저장하지 않을지 직접 고릅니다. 전체 내용은 [개인정보와 데이터 관리 가이드](/ko/guides/privacy-and-security)와 [개인정보 처리방침](/ko/legal/privacy)에 있습니다.

## Capriole AI가 제공하지 않는 것

Capriole AI는 개인과 소규모 팀을 위해 만들어졌습니다. SAML 싱글 사인온이 없고, SOC 2나 ISO 27001 같은 규정 준수 인증을 공개하지 않으며, 전용 지원 SLA를 제공하지 않습니다. 코드가 사내 네트워크를 벗어나기 전에 회사가 이 중 하나라도 요구한다면, Capriole AI는 그 요건을 충족하지 못합니다.

## 게이트웨이로 소스 코드를 보내기 전에

1. **먼저 시크릿을 제거하세요.** `.env` 파일, 자격 증명, 개인 키는 보내는 파일과 맥락에서 빼세요.
2. **도구마다 별도의 키를 주고 테스트하세요.** 민감한 내용이 없는 프로젝트에서 첫 요청을 보내고, 사용량 행에 예상한 키와 모델이 표시되는지 확인한 다음, 더 이상 쓰지 않는 키는 비활성화하세요. 각 단계는 [API Keys와 사용량 가이드](/ko/guides/api-keys-usage)에서 설명합니다.
3. **제공사 약관도 확인하세요.** 게이트웨이의 정책은 게이트웨이에만 적용됩니다. 답변하는 모델 제공사는 자체 약관에 따라 요청을 처리합니다.

[코딩 에이전트에 API key 하나 사용하기](/ko/guides/one-api-key-coding-agents) 가이드는 에이전트 10개를 설정하며, [Claude Code](/ko/integrations/claude-code)와 [Codex](/ko/integrations/codex) 페이지는 각 클라이언트의 구성을 다룹니다.
