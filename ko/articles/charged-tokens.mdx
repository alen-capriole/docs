과금 토큰은 Capriole AI API 잔액에서 차감되는 단위입니다. 개인 Premium은 USD 8 작업 공간 멤버십의 일부로 월 500만을 포함합니다. 캐시되지 않은 입력과 출력은 100%로 계산됩니다. 캐시된 입력은 10%로 계산되며, 다음 정수 토큰으로 올림합니다.

공개 API와 코딩 에이전트 트래픽에 적용됩니다. 무제한 Premium Browser Chat은 이 API 잔액을 소비하지 않습니다.

## 공식

Capriole은 지원되는 각 프로토콜을 총 입력 토큰 수와, 선택한 제공자가 보고하면 캐시된 입력 수로 정규화합니다. 캐시된 입력은 총 입력의 하위 집합입니다.

```text
uncached_input = input_tokens - cached_input

charged_tokens =
  uncached_input
  + ceil(cached_input × 0.1)
  + output_tokens
```

제공자가 캐시된 입력을 보고하지 않으면 모든 입력 토큰이 100%로 계산됩니다. Capriole은 사용량 메타데이터가 보고하지 않은 cache hit를 추론하지 않습니다.

| 프로토콜 | 정규화된 입력 | 캐시 하위 집합 |
|---|---|---|
| OpenAI Responses | `input_tokens` | `input_tokens_details.cached_tokens` |
| OpenAI Chat Completions | `prompt_tokens` | `prompt_tokens_details.cached_tokens` |
| Anthropic Messages | `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` | `cache_read_input_tokens` |

Anthropic Messages에서 cache creation은 100% 입력으로 남습니다. 보고된 cache reads만 10% 과금 토큰 처리를 받습니다.

## 재현 가능한 예시 세 가지

| 예시 | 총 입력 | 캐시된 입력 | 출력 | 계산 | 과금 토큰 |
|---|---:|---:|---:|---|---:|
| cache hit 없음 | 800 | 0 | 200 | `800 + 0 + 200` | 1,000 |
| 대부분 캐시된 프롬프트 | 10,000 | 8,000 | 500 | `2,000 + ceil(800) + 500` | 3,300 |
| 크게 보고된 cache hit | 228,807 | 228,224 | 90 | `583 + ceil(22,822.4) + 90` | 23,496 |

세 번째 요청은 원시 입력+출력 토큰이 228,897입니다. 제공자가 입력 토큰 228,224개를 캐시됨으로 보고했기 때문에 과금 토큰 23,496개를 차감합니다.

반올림은 기록된 각 요청의 캐시된 부분에 적용됩니다. 따라서 캐시된 입력 토큰 하나는 `ceil(0.1)` 후 토큰 하나를 청구하고, 캐시된 입력 토큰 열 개도 토큰 하나를 청구합니다.

## 500만 과금 토큰에 몇 요청이 들어가는지 추정하기

원시 컨텍스트 크기로 추측하지 말고 자체 API 사용량의 평균 과금 토큰 값을 사용하세요.

```text
estimated_requests = floor(5,000,000 / average_charged_tokens_per_request)
```

| 요청당 평균 과금 토큰 | 500만 과금 토큰으로 가능한 요청 수 |
|---:|---:|
| 1,000 | 5,000 |
| 5,000 | 1,000 |
| 25,000 | 200 |
| 100,000 | 50 |

이 행은 계획용 산술이며 전형적인 워크로드 주장이 아닙니다. 짧은 분류 호출과 긴 코딩 에이전트 턴은 자릿수가 다를 수 있습니다. 출력 길이, 반복 컨텍스트, 제공자가 보고한 cache hit, 도구 결과 모두 측정된 평균을 바꿉니다.

## 과금 토큰과 제공자 가격은 다른 단위를 사용합니다

공식 제공자는 입력, 캐시된 입력, 캐시 쓰기, 출력, 도구, 긴 컨텍스트에 대해 별도의 가격을 게시할 수 있습니다. Capriole의 과금 토큰 잔액은 지원되는 공개 API 경로에 하나의 공식을 쓰는 고객 할당량 단위입니다.

| 단위 | 답하는 질문 |
|---|---|
| 제공자 입력 및 출력 가격 | 제공자가 자체 가격표로 얼마를 청구하는지 |
| 원시 API 사용량 토큰 | 응답이 보고한 입력, 출력, 캐시 토큰 수 |
| Capriole 과금 토큰 | Capriole이 계정의 API 잔액에서 얼마나 차감하는지 |

과금 토큰에 제공자가 게시한 입력 또는 출력 요율을 곱하지 마세요. 단위는 다른 청구 시스템을 설명합니다.

[날짜가 있는 API 비용 비교](/ko/articles/ai-api-cost-comparison)는 이 공식을 고정된 500만 토큰 워크로드에 적용한 다음 각 서비스의 현금 비용을 비교합니다.

## 개인 및 Team 잔액 경계

| 접근 | 포함된 API 잔액 | Top-up 기본 가격 | 현재 규칙 |
|---|---:|---:|---|
| Personal Premium | 활성 월간 할당량 기간당 과금 토큰 500만 | 500만당 USD 8 | 공개 API와 개인 top-up에는 활성 Premium 접근이 필요합니다. 여러 팩 구매는 표시된 볼륨 할인(최대 15%)을 받습니다 |
| Team | 활성 월간 할당량 기간당 공유 과금 토큰 5,000만 | 5,000만당 USD 80 | 월 USD 70에 좌석 다섯 개가 포함됩니다. owner와 admin은 1~5개 팩을 살 수 있으며, 표시된 볼륨 할인은 최대 10%입니다 |

포함된 할당량이 일치하는 개인 또는 Team top-up 지갑보다 먼저 소비됩니다. 구매한 top-up 잔액은 월간 할당량 기간과 유료 접근 공백을 넘어 유지됩니다. 소비하려면 자격 있는 활성 유료 접근이 여전히 필요합니다. Browser Chat은 API 회계와 별개입니다. 코딩 에이전트는 API 트래픽으로 계산되어 과금 토큰을 차감합니다.

월 500만은 전체 USD 8 Premium 작업 공간 멤버십의 일부입니다. 무제한 API 플랜이 아니며 독립 API 가격으로 제시해서는 안 됩니다.

Top-up은 프로그래밍 사용량을 확장합니다. Browser Chat 허용량, 모델 호환성, 자격 있는 활성 개인 또는 Team 접근 요구 사항은 바꾸지 않습니다.

## API가 기록하는 내용

Capriole은 프로토콜 정규화 사용량과 과금 사용량을 별도 필드로 유지합니다. 성공한 공개 API 요청은 다음을 기록할 수 있습니다.

- 정규화된 입력 토큰
- 출력 토큰
- 정규화된 입력+출력 토큰
- 제공자가 보고한 캐시된 입력 토큰
- 할당량에서 차감된 과금 토큰
- 해석된 모델과 요청 상태

Capriole 네이티브 `POST /v1/chat` 응답은 `usage` 안에 `cached_tokens`와 `charged_tokens`를 노출합니다. 프로토콜 호환 Responses, Chat Completions, Messages 엔드포인트는 업스트림 응답 형태를 유지하고, Capriole은 계정 사용량에 맞는 과금 토큰 값을 기록합니다.

## 캐시된 입력이 청구를 줄였는지 확인하기

Capriole AI [API 페이지](https://capriole.ai?view=api)를 연 다음 **Key**, **Model**, **Status** 필터로 요청을 분리하세요. 사용량 표에서 다음 열을 비교하세요.

| 열 | 확인하는 내용 |
|---|---|
| **Input tokens** | 캐시된 입력을 분리하기 전의 프로토콜 정규화 입력 |
| **Cached tokens** | 제공자가 캐시됨으로 보고한 입력 |
| **Charged tokens** | 캐시 입력 공식을 적용한 뒤 차감된 할당량 |
| **Total tokens** | 프로토콜 정규화 입력과 출력의 합 |

양수 캐시 토큰 값은 호환 제공자 사용량 메타데이터가 cache hit를 보고했음을 확인합니다. 모든 반복 요청이 같은 제공자 캐시에 적중한다고 증명하지는 않습니다. 제공자 라우팅, 캐시 수명, 요청 구조, 모델 동작이 결과를 바꿀 수 있습니다.

Capriole 네이티브 `POST /v1/chat`에서는 `usage.cached_tokens`와 `usage.charged_tokens`로 같은 확인이 가능합니다. 다른 프로토콜 응답은 업스트림 스키마를 유지하므로, 경로 간 요청을 비교하는 일관된 위치는 계정 사용량 표입니다.

## 자주 묻는 질문

### 캐시된 입력은 항상 90% 할당량 할인을 받나요?

선택한 제공자가 호환 사용량 메타데이터에서 캐시된 입력을 보고할 때만 받습니다. 누락된 캐시 메타데이터는 cache hit로 취급되지 않습니다.

### reasoning 토큰이 한 번 더 더해지나요?

아닙니다. 제공자가 보고한 출력 사용량에 이미 경로가 사용하는 출력 회계가 들어 있습니다. Capriole은 이 공식에서 출력 위에 별도의 reasoning 토큰 청구를 더하지 않습니다.

### Premium에서 API 사용량은 무제한인가요?

아닙니다. Premium Browser Chat은 지원되는 Premium 모델 세트에서 무제한입니다. API와 코딩 에이전트 요청은 포함된 과금 토큰 잔액과 사용 가능한 top-up 잔액을 사용합니다.

### 코딩은 어디서 시작해야 하나요?

가장 작은 원시 요청은 [API 빠른 시작](/ko/quickstart)을, 프로토콜 네이티브 Python 및 TypeScript 클라이언트는 [OpenAI 및 Anthropic SDK 가이드](/ko/guides/openai-anthropic-sdks)를 사용하세요. 아직 구독하지 않았다면 업그레이드 전에 [제한된 무료 Browser Chat에서 플래그십 모델을 써 보세요](https://capriole.ai).

이 페이지의 Capriole 플랜, 할당량, top-up, 과금 토큰 사실은 자사 문서로 유지됩니다.
