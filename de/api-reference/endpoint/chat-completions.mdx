title: "Chat completions"
description: "Erstellen Sie OpenAI-kompatible Chat Completions mit Capriole AI Modellen."

---

Verwenden Sie diesen Endpunkt, wenn Ihre Anwendung, Ihr SDK oder Ihr Gateway das Anfrage- und Antwortformat von OpenAI Chat Completions erwartet.

Senden Sie eine Standard-Chat-Completions-Nutzlast mit `model` und `messages`. Capriole AI löst Latest-Aliase vor der Upstream-Weiterleitung zur ausgewählten Anbietermodell-ID auf, leitet kompatible Felder wie `messages`, `tools`, `tool_choice`, `response_format` und `stream` weiter und gibt den Upstream-JSON- oder SSE-Stream unverändert zurück, mit Ausnahme der unten beschriebenen GLM-SSE-Korrektur und der Heartbeat-Kommentare. Bei Streaming-Anfragen setzt Capriole AI vor der Weiterleitung `stream_options.include_usage=true`, damit die Nutzung erfasst werden kann.

Bei manchen SSE-Antworten mit `model="zai/glm-5.3-flash"` entfernt Capriole AI nur das leere Legacy-Feld `function_call={"name":"","arguments":""}` aus den Deltas. Echte oder teilweise übertragene Funktionsaufrufe, `tool_calls`, Text und Nutzungsdaten bleiben erhalten. Diese Ausnahme betrifft weder nicht gestreamte Antworten noch andere Modelle.

`POST /v1/chat/completions` akzeptiert `openai-latest`, `claude-latest`, `google-latest` und öffentliche konkrete Modell-IDs aus `GET /v1/models`. Verwenden Sie einen Latest-Alias, damit Capriole AI das von uns empfohlene Flaggschiff-Modell für diesen Anbieter wählt.

Latest-Aliase sind Eingabe-Kurzformen. Die Nutzung wird für das aufgelöste Modell erfasst, während der Antwortkörper das Modellbenennungsverhalten des gewählten kompatiblen Endpunkts beibehält.

## Kimi K3.1 Pro

Bei Kimi K3.1 Pro sind `temperature` auf 1 und `top_p` auf 0.95 festgelegt. Lassen Sie `temperature`, `top_p`, `n`, `presence_penalty` und `frequency_penalty` bei diesem Modell weg, und senden Sie Anweisungen mit der Rolle `system` statt `developer`.

## Gemini 4 Carbon

`google-latest` wird zu `google/gemini-4-carbon` aufgelöst. Dieser Endpunkt leitet den Rest Ihrer Anfrage unverändert weiter, daher denkt Gemini 4 Carbon auf der Standardstufe von Google, `medium`, die in unserem Test für denselben Prompt etwa das 3- bis 4-Fache der Ausgabe-Tokens von Gemini 4 Argon verbrauchte. `reasoning_effort` von OpenAI ändert die Thinking-Stufe von Carbon nicht. Um sie festzulegen, senden Sie das Feld von Google mit `low`, `medium` oder `high`:

```json
"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}
```

Übergeben Sie mit dem OpenAI Python SDK `extra_body={"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}}`. Laut Google können schwierige Prompts bei Carbon mehrere Minuten dauern, streamen Sie sie daher wie unter [Lange Aufgaben](#lange-aufgaben) beschrieben; für kürzere Wartezeiten setzen Sie `thinking_level` auf `low` oder verwenden Sie `google/gemini-4-argon`.

## Gemini 4 Neon

Wählen Sie Neon mit `google/gemini-4-neon` aus. Google dokumentiert ein gemeinsames Kontextfenster für Eingabe und Ausgabe von 1,048,576 Tokens, ein standardmäßiges synchrones Ausgabelimit von 65,536 Tokens und die Unterstützung von JSON Schema. Die Denkstufen sind `low`, `medium`, `high` (Standard) und `xhigh`. [Googles Modelldokumentation](https://aistudio.google.com/docs/models/gemini-4-neon).

## Websuche

Dieser Endpunkt bietet keine Websuche. Bei Grok-Modellen schlägt eine Anfrage mit einem Feld `web_search_options` oder `search_parameters`, das nicht null ist, mit HTTP 400 fehl:

```json
{
  "detail": "Web search is not supported for xai/grok-4.7 on /v1/chat/completions. Use POST /v1/responses with tools: [{\"type\": \"web_search\"}]."
}
```

Funktionstools, die Ihr Client definiert, werden unverändert weitergeleitet, auch eines mit dem Namen `web_search`. Für die Websuche mit GPT oder Grok verwenden Sie [`POST /v1/responses`](/de/api-reference/endpoint/responses) mit `"tools": [{"type": "web_search"}]`.

## Lange Aufgaben

Setzen Sie für lange Aufgaben wie ausgedehntes Reasoning `"stream": true`. Ohne Streaming kann die Verbindung nach etwa 2 Minuten in ein Timeout laufen. Solange ein Stream auf das Modell wartet, sendet Capriole AI alle 15 Sekunden einen SSE-Kommentar `: heartbeat`, und gestreamte `google/*`-Anfragen können bis zu 20 Minuten auf das erste Token warten. Hat das Modell nach 60 Sekunden noch nicht geantwortet, hat die 200-Antwort bereits begonnen, sodass ein späterer Upstream-Fehler als letztes SSE-Ereignis mit einem `error`-Objekt ankommt.
