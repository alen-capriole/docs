Mit einem einzigen Capriole AI API-Schlüssel nutzen Sie GPT-6 Astra, Claude Fable 5.1 und Opus 5.5 in OpenCode, bis zu 92 % unter den offiziellen API-Preisen.

## Was ist OpenCode

OpenCode ist ein Open-Source-KI-Coding-Agent als Terminaloberfläche, Desktop-App und IDE-Erweiterung. Dieses Setup fügt Capriole AI als einen benutzerdefinierten Anbieter hinzu. Jedes Modell darin verwendet das API-Protokoll, das Capriole AI für die jeweilige Modellfamilie bereitstellt.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Ein Capriole AI-Konto ([Hier registrieren](https://www.capriole.ai/de))
- Premium (USD 8 pro Monat, inklusive unbegrenztem Web-Chat) oder Team, denn API-Schlüssel gibt es nur mit einem dieser Pläne ([Abonnieren](https://www.capriole.ai/de?view=api))
- Einen Capriole AI API-Schlüssel ([Schlüssel abrufen](https://www.capriole.ai/de?view=api))

## Installation

OpenCode 2 und OpenCode 1 verwenden beide den Befehl `opencode`, daher ist immer nur eine der beiden Versionen installiert. Installieren Sie OpenCode 2 mit dem offiziellen Installationsskript:

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

Oder installieren Sie es mit npm:

```bash
npm install -g @opencode/cli
```

Um von OpenCode 1 zu wechseln, führen Sie `opencode upgrade --major` aus. Das Skript `https://opencode.ai/install` und das npm-Paket `opencode-ai` installieren weiterhin OpenCode 1.

Prüfen Sie die Installation:

```bash
opencode --version
```

## Konfiguration

### Modellvalidierung

OpenCode 2.2.5 besteht mit der OpenCode-2-Konfiguration für jedes Modell im Abschnitt „Unterstützte Modelle“ eine Prüfung aus Dateilesen und abschließender Antwort über Capriole AI. OpenCode 1.19.3 besteht mit der OpenCode-1-Konfiguration eine Prüfung aus Dateilesen, Dateischreiben und abschließender Antwort.

### OpenCode 2

Erstellen oder aktualisieren Sie `~/.config/opencode/opencode.json`:

```json

  "agents": {
    "title": {
      "model": "capriole-ai/zai/glm-5.3-flash"
    }
  },
  "providers": {
    "capriole-ai": {
      "name": "Capriole AI",
      "env": ["CAPRIOLE_AI_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://api.caprioletech.com/v1"
      },
      "headers": {
        "Authorization": "Bearer {env:CAPRIOLE_AI_API_KEY}"
      },
      "models": {
        "openai-latest": {
          "name": "OpenAI latest",
          "package": "@opencode/ai/providers/openai-compatible/responses",

            "context": 1050000,
            "output": 128000
          },

            "reasoningEffort": "medium"
          }

          "name": "GPT-6.1 Sol",

            "context": 1050000,

          }

          "name": "Claude latest",

```

Was die einzelnen Einstellungen bewirken:

- `package: "@opencode/ai/providers/openai-compatible"` ist das Standardpaket für den Anbieter, sodass Gemini, Grok, GLM und Kimi Chat Completions verwenden.
- Jedes GPT-Modell überschreibt `package` mit `@opencode/ai/providers/openai-compatible/responses`, das die Responses API verwendet. Jedes Claude-Modell überschreibt es mit `@opencode/ai/providers/anthropic-compatible`, das Anthropic Messages verwendet.
- `env` nennt die Variable, die Ihren Schlüssel enthält. Der `Authorization`-Header sendet den Schlüssel für jedes Paket als Bearer-Token. Ohne diesen Header sendet das Anthropic-Paket den Schlüssel in einem `x-api-key`-Header, den Capriole AI nicht akzeptiert.
- `reasoningEffort` gibt jedem GPT-Modell eine Standardstufe für das Reasoning. Ohne diese Einstellung antworten GPT-Modelle ohne Reasoning.
- `baseURL` enthält für jedes Paket `/v1`. `limit` teilt OpenCode das Kontextfenster und das Ausgabelimit jedes Modells mit.
- `agents.title` legt das Modell fest, das OpenCode für Sitzungstitel verwendet.

## OpenCode ausführen

Setzen Sie Ihren API-Schlüssel und starten Sie OpenCode aus Ihrem Projektverzeichnis:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
opencode service restart
opencode
```

OpenCode 2 sendet Modellanfragen aus einem Hintergrunddienst, der den Schlüssel beim Start liest. Mit `opencode service restart` übernimmt er den eben gesetzten Schlüssel. In OpenCode 1 lassen Sie diesen Schritt weg.

Verwenden Sie `/models`, um das Modell zu wechseln. Für einen nicht interaktiven Lauf verwenden Sie `opencode run`:

```bash
opencode run -m capriole-ai/claude-latest "Explain this repository."
```

Modellreferenzen haben die Form `capriole-ai/<model-id>`.

| OpenAI latest | `openai-latest` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | Chat Completions |

## Fehlerbehebung

### Warum gibt OpenCode einen Authentifizierungsfehler zurück?

Bestätigen Sie, dass `CAPRIOLE_AI_API_KEY` in derselben Shell exportiert ist, bevor Sie OpenCode starten, und dass der `Authorization`-Header unter `headers` (OpenCode 2) oder `options.headers` (OpenCode 1) vorhanden ist. Meldet OpenCode 2 `Missing Bearer token`, wurde sein Hintergrunddienst ohne den Schlüssel gestartet: Führen Sie in dieser Shell `opencode service restart` aus.

### Warum schlagen Claude-Anfragen mit `Unsupported Claude Messages model` fehl?

Claude-Modelle, die das Anthropic-Paket verwenden, benötigen die Claude-IDs ohne Präfix, etwa `claude-opus-5-5`. Die IDs mit dem Präfix `anthropic/` sind für Chat Completions gedacht.

### Warum schlagen GPT-Anfragen fehl?

Bestätigen Sie, dass jedes GPT-Modell `"package": "@opencode/ai/providers/openai-compatible/responses"` (OpenCode 2) oder `"provider": { "npm": "@ai-sdk/openai" }` (OpenCode 1) enthält, damit seine Anfragen die Responses API verwenden.

### Warum werden keine Capriole AI-Modelle angezeigt?

Bestätigen Sie, dass die Modellreferenz `capriole-ai/<model-id>` verwendet, etwa `capriole-ai/moonshot/kimi-k3`, und dass `disabled_providers` `capriole-ai` nicht blockiert. OpenCode 1 ignoriert die OpenCode-2-Form mit `providers`.

### Warum greifen Konfigurationsänderungen nicht?

Prüfen Sie, ob eine projektbezogene `opencode.json` oder eine `OPENCODE_CONFIG`-Überschreibung vorhanden ist, und starten Sie OpenCode dann neu.

### Warum treten Fehler mit Anbieterpaketen auf?

Leeren Sie `~/.cache/opencode` und starten Sie OpenCode neu, damit es die Anbieterpakete neu installiert.

## Hinweise

- Bewahren Sie Ihren Schlüssel in der Umgebung auf. Fügen Sie ihn nicht in `opencode.json` ein.
- Um ein weiteres Capriole AI-Modell hinzuzufügen, kopieren Sie den Eintrag eines Modells derselben Familie und ändern Sie die ID. `GET https://api.caprioletech.com/v1/models` listet alle Modell-IDs auf.
