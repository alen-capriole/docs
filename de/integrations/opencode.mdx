## Was ist OpenCode

OpenCode ist ein Open-Source-KI-Coding-Agent als Terminaloberfläche, Desktop-App und IDE-Erweiterung. Mit einer Anbieterkonfiguration kann es unterstützte Modellanfragen über die OpenAI-kompatiblen und Anthropic-kompatiblen Endpunkte von Capriole AI senden.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Ein Capriole AI-Konto ([Hier registrieren](https://capriole.ai))
- Einen Capriole AI API-Schlüssel ([Schlüssel abrufen](https://capriole.ai?view=api))

## Installation

Installieren Sie OpenCode mit dem offiziellen Installationsskript:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Oder installieren Sie es mit npm:

```bash
npm install -g opencode-ai
```

Prüfen Sie die Installation:

```bash
opencode --version
```

## OpenCode ausführen

Nachdem Sie `YOUR_CAPRIOLE_AI_API_KEY` in der Konfiguration ersetzt haben, starten Sie OpenCode:

```bash
opencode
```

Verwenden Sie `/models`, um OpenAI latest, GPT 5.6 Thinking, GPT 5.6, GPT 5.5, GPT 5.4 mini, Fable 5, Opus 5, Grok 4.5, GLM 5.2, Kimi K3, Claude latest, Opus 4.8, Opus 4.7, Opus 4.6 oder Sonnet 4.6 auszuwählen. Verwenden Sie `Ctrl+T`, um Modellvarianten zu durchlaufen.

## Fehlerbehebung

### Warum gibt OpenCode einen Authentifizierungsfehler zurück?

Bestätigen Sie, dass sowohl `apiKey` als auch `authToken` in `~/.config/opencode/opencode.json` Ihren Capriole AI API-Schlüssel verwenden und nicht `YOUR_CAPRIOLE_AI_API_KEY`.

### Warum schlagen GPT-Anfragen fehl?

Bestätigen Sie, dass der GPT-Anbieter `npm: "@ai-sdk/openai"` und `baseURL: "https://api.caprioletech.com/v1"` verwendet, damit Anfragen die Responses API nutzen.

### Warum schlagen Grok-, GLM- oder Kimi-Anfragen fehl?

Bestätigen Sie, dass `capriole-ai-compatible` `npm: "@ai-sdk/openai-compatible"` und `baseURL: "https://api.caprioletech.com/v1"` verwendet, damit beide Modelle Chat Completions nutzen.

### Warum schlagen Anthropic-Anfragen fehl?

Bestätigen Sie, dass der Anthropic-Anbieter `npm: "@ai-sdk/anthropic"`, `authToken` und `baseURL: "https://api.caprioletech.com/v1"` verwendet.

### Warum erscheinen Capriole AI-Modelle nicht?

Bestätigen Sie, dass die Modellreferenz `<providerId>/<modelId>` verwendet, etwa `capriole-ai-openai/openai-latest`, `capriole-ai-compatible/moonshot/kimi-k3` oder `capriole-ai-anthropic/claude-latest`, und dass `enabled_providers` die Capriole AI-Anbieter enthält, während `disabled_providers` sie nicht blockiert.

### Warum erscheinen Modellvarianten nicht?

Bestätigen Sie, dass Sie OpenCode nach der Aktualisierung von `~/.config/opencode/opencode.json` neu gestartet haben, öffnen Sie dann `/models` und drücken Sie `Ctrl+T`, um Varianten zu durchlaufen.

### Warum greifen Konfigurationsänderungen nicht?

Prüfen Sie auf projektbezogene `opencode.json`- oder `OPENCODE_CONFIG`-Überschreibungen und starten Sie OpenCode anschließend neu.

### Warum erscheinen Fehler zur Anbieterinitialisierung oder zu Anbieterpaketen?

Prüfen Sie bei `ProviderInitError` zuerst die Anbieterkonfiguration. Löschen Sie bei Fehlern zu Anbieterpaketen `~/.cache/opencode` und starten Sie OpenCode neu, damit Anbieterpakete neu installiert werden.

## Hinweise

- Der Anthropic-Anbieter verwendet `authToken`, damit der AI SDK Anthropic-Anbieter die Authentifizierung `Authorization: Bearer` sendet.
- OpenCode 1.14.48 schließt Shell-Tool-Workflows mit Grok 4.5, GLM 5.2 und Kimi K3 über `@ai-sdk/openai-compatible` ab.
- OpenCode-Varianten sind clientseitige Modelleinstellungen. Sie erzeugen keine neuen Capriole AI API-Modell-IDs.
