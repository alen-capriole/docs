## Was ist OpenCode

OpenCode ist ein Open-Source-KI-Coding-Agent als Terminaloberfläche, Desktop-App und IDE-Erweiterung. Dieses Setup fügt Capriole AI als einen benutzerdefinierten Anbieter hinzu. Jedes Modell darin verwendet das API-Protokoll, das Capriole AI für die jeweilige Modellfamilie bereitstellt.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Ein Capriole AI-Konto ([Hier registrieren](https://capriole.ai))
- Einen Capriole AI API-Schlüssel ([Schlüssel abrufen](https://capriole.ai?view=api))

## Installation

Installieren Sie OpenCode mit dem offiziellen Installationsskript:

```bash
curl -fsSL https://opencode.ai/install | bash
```

Oder installieren Sie es mit npm:

```bash
npm install -g opencode-ai
```

Prüfen Sie die Installation:

```bash
opencode --version
```

## Konfiguration

### Modellvalidierung

OpenCode 1.19.3 besteht mit der folgenden Konfiguration für jedes Modell im Abschnitt „Unterstützte Modelle“ eine Prüfung aus Dateilesen, Dateischreiben und abschließender Antwort über Capriole AI.

Erstellen oder aktualisieren Sie `~/.config/opencode/opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "capriole-ai/claude-latest",
  "small_model": "capriole-ai/zai/glm-5.3-flash",
  "provider": {
    "capriole-ai": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Capriole AI",
      "options": {
        "baseURL": "https://api.caprioletech.com/v1",
        "apiKey": "{env:CAPRIOLE_AI_API_KEY}",
        "headers": {
          "Authorization": "Bearer {env:CAPRIOLE_AI_API_KEY}"
        }
      },
      "models": {
        "openai-latest": {
          "name": "OpenAI latest",
          "provider": {
            "npm": "@ai-sdk/openai"
          },
          "limit": {
            "context": 1050000,
            "output": 128000
          },
          "options": {
            "forceReasoning": true
          }
        },
        "openai/gpt-6.1-sol": {
          "name": "GPT-6.1 Sol",
          "provider": {
            "npm": "@ai-sdk/openai"
          },
          "limit": {
            "context": 1050000,
            "output": 128000
          },
          "options": {
            "forceReasoning": true
          }
        },
        "claude-latest": {
          "name": "Claude latest",
          "provider": {
            "npm": "@ai-sdk/anthropic"
          },
          "limit": {
            "context": 1000000,
            "output": 128000
          }
        },
        "claude-opus-5-5": {
          "name": "Opus 5.5",
          "provider": {
            "npm": "@ai-sdk/anthropic"
          },
          "limit": {
            "context": 1000000,
            "output": 128000
          }
        },
        "google/gemini-3.8-flash": {
          "name": "Gemini 3.8 Flash",
          "limit": {
            "context": 1048576,
            "output": 65536
          }
        },
        "xai/grok-4.7": {
          "name": "Grok 4.7",
          "limit": {
            "context": 500000,
            "output": 128000
          }
        },
        "zai/glm-5.3-flash": {
          "name": "GLM 5.3 Flash",
          "limit": {
            "context": 1000000,
            "output": 128000
          }
        },
        "moonshot/kimi-k3.1-pro": {
          "name": "Kimi K3.1 Pro",
          "limit": {
            "context": 1048576,
            "output": 131072
          }
        },
        "moonshot/kimi-k3": {
          "name": "Kimi K3",
          "limit": {
            "context": 1048576,
            "output": 131072
          }
        }
      }
    }
  }
}
```

Was die einzelnen Einstellungen bewirken:

- `npm: "@ai-sdk/openai-compatible"` ist das Standardpaket für den Anbieter, sodass Gemini, Grok, GLM und Kimi Chat Completions verwenden.
- Jedes GPT-Modell überschreibt `provider.npm` mit `@ai-sdk/openai`, das die Responses API verwendet. Jedes Claude-Modell überschreibt es mit `@ai-sdk/anthropic`, das Anthropic Messages verwendet.
- `baseURL` enthält für jedes Paket `/v1`.
- `{env:CAPRIOLE_AI_API_KEY}` liest Ihren Schlüssel aus der Umgebung. Der `Authorization`-Header sendet ihn für jedes Paket als Bearer-Token. Ohne diesen Header sendet das Anthropic-Paket den Schlüssel in einem `x-api-key`-Header, den Capriole AI nicht akzeptiert.
- `limit` teilt OpenCode das Kontextfenster und das Ausgabelimit jedes Modells mit, damit es den Kontext verfolgen und die Sitzung rechtzeitig komprimieren kann.
- `small_model` ist das Modell, das OpenCode für leichte Aufgaben wie Sitzungstitel verwendet.

## OpenCode ausführen

Setzen Sie Ihren API-Schlüssel und starten Sie OpenCode aus Ihrem Projektverzeichnis:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
opencode
```

Verwenden Sie `/models`, um das Modell zu wechseln. Für einen nicht interaktiven Lauf verwenden Sie `opencode run`:

```bash
opencode run -m capriole-ai/claude-latest "Explain this repository."
```

## Unterstützte Modelle

Modellreferenzen haben die Form `capriole-ai/<model-id>`.

| Modell | Modell-ID | Protokoll |
| --- | --- | --- |
| OpenAI latest | `openai-latest` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | Chat Completions |
| Kimi K3.1 Pro | `moonshot/kimi-k3.1-pro` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | Chat Completions |

`openai-latest` und `claude-latest` zeigen immer auf unser neuestes Flaggschiff-Modell der jeweiligen Familie.

## Fehlerbehebung

### Warum gibt OpenCode einen Authentifizierungsfehler zurück?

Bestätigen Sie, dass `CAPRIOLE_AI_API_KEY` in derselben Shell exportiert ist, bevor Sie OpenCode starten, und dass der `Authorization`-Header unter `options.headers` vorhanden ist.

### Warum schlagen Claude-Anfragen mit `Unsupported Claude Messages model` fehl?

Claude-Modelle, die `@ai-sdk/anthropic` verwenden, benötigen die Claude-IDs ohne Präfix, etwa `claude-opus-5-5`. Die IDs mit dem Präfix `anthropic/` sind für Chat Completions gedacht.

### Warum schlagen GPT-Anfragen fehl?

Bestätigen Sie, dass jedes GPT-Modell `"provider": { "npm": "@ai-sdk/openai" }` enthält, damit seine Anfragen die Responses API verwenden.

### Warum werden keine Capriole AI-Modelle angezeigt?

Bestätigen Sie, dass die Modellreferenz `capriole-ai/<model-id>` verwendet, etwa `capriole-ai/moonshot/kimi-k3`, und dass `disabled_providers` `capriole-ai` nicht blockiert.

### Warum greifen Konfigurationsänderungen nicht?

Prüfen Sie, ob eine projektbezogene `opencode.json` oder eine `OPENCODE_CONFIG`-Überschreibung vorhanden ist, und starten Sie OpenCode dann neu.

### Warum treten Fehler mit Anbieterpaketen auf?

Leeren Sie `~/.cache/opencode` und starten Sie OpenCode neu, damit es die Anbieterpakete neu installiert.

## Hinweise

- Bewahren Sie Ihren Schlüssel in der Umgebung auf. Fügen Sie ihn nicht in `opencode.json` ein.
- Um ein weiteres Capriole AI-Modell hinzuzufügen, kopieren Sie den Eintrag eines Modells derselben Familie und ändern Sie die ID. `GET https://api.caprioletech.com/v1/models` listet alle Modell-IDs auf.
- Offizielle Referenzen: [OpenCode-Installation](https://opencode.ai/docs), [OpenCode-Konfiguration](https://opencode.ai/docs/config), [OpenCode-Anbieter](https://opencode.ai/docs/providers), [OpenCode-Modelle](https://opencode.ai/docs/models) und [OpenCode-Fehlerbehebung](https://opencode.ai/docs/troubleshooting).
