## Was ist Codex

Codex ist der Coding-Agent von OpenAI für die Softwareentwicklung. Er kann Capriole AI über einen benutzerdefinierten Modellanbieter nutzen, der Anfragen an die Responses-kompatible API von Capriole AI sendet.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Ein Capriole AI-Konto ([Hier registrieren](https://capriole.ai))
- Einen Capriole AI API-Schlüssel ([Schlüssel abrufen](https://capriole.ai?view=api))

## Installation

### Codex CLI

```bash
npm install -g @openai/codex
```

### Codex app

Laden Sie die App von [OpenAI Codex](https://developers.openai.com/codex) herunter.

## Konfiguration

Erstellen oder aktualisieren Sie `~/.codex/config.toml`:

```toml
model = "gpt-6-astra"
model_reasoning_effort = "high"
model_provider = "capriole_ai"

[model_providers.capriole_ai]
name = "Capriole AI"
base_url = "https://api.caprioletech.com/v1"
wire_api = "responses"
env_key = "CAPRIOLE_AI_API_KEY"
env_key_instructions = "Export CAPRIOLE_AI_API_KEY before starting Codex"
```

## Codex ausführen

Setzen Sie Ihren API-Schlüssel und starten Sie Codex:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
codex
```

## Unterstützte Modelle

Codex nutzt die OpenAI-Modelle von Capriole AI über die Responses API. Verwenden Sie die folgenden nativen Modell-IDs mit der integrierten Modellauswahl und den Reasoning-Einstellungen von Codex. Sie benötigen kein eigenes `model_catalog_json`. Nur von Capriole AI unterstützte Modelle können aufgerufen werden.

- `gpt-6-astra`
- `gpt-5.6-terra`
- `gpt-5.6-luna`
- `gpt-5.5`

Die API akzeptiert auch IDs mit dem Präfix `openai/` sowie `openai-latest`. Der Alias `openai-latest` folgt dem von Capriole AI empfohlenen OpenAI-Flaggschiff-Modell.

## Fehlerbehebung

### Warum gibt Codex einen Authentifizierungsfehler zurück?

Bestätigen Sie, dass `CAPRIOLE_AI_API_KEY` in derselben Shell exportiert ist, bevor Sie `codex` ausführen.

### Warum findet Codex das Modell nicht?

Bestätigen Sie, dass `model_provider = "capriole_ai"` gesetzt ist und dass `model` `openai-latest` oder eine unterstützte Capriole AI OpenAI-Modell-ID ist.

### Warum schlagen Anfragen mit Endpunkt- oder Protokollfehlern fehl?

Bestätigen Sie, dass unter `[model_providers.capriole_ai]` `base_url = "https://api.caprioletech.com/v1"` und `wire_api = "responses"` gesetzt sind.

### Warum ignoriert Codex den Capriole AI-Anbieter?

Verwenden Sie keine reservierte integrierte Anbieter-ID wie `openai`; behalten Sie die benutzerdefinierte Anbieter-ID als `capriole_ai`.

### Warum greifen Konfigurationsänderungen nicht?

Bestätigen Sie, dass `~/.codex/config.toml` die aktive Benutzerkonfigurationsdatei ist, vertrauen Sie dem Projekt, bevor Sie sich auf eine projektspezifische `.codex/config.toml` stützen, und starten Sie Codex anschließend neu.

## Hinweise

- Die Konfiguration verwendet `env_key`, damit Ihr API-Schlüssel in Ihrer Shell-Umgebung bleibt und nicht in der Konfigurationsdatei liegt.
- Offizielle Referenzen: [Codex CLI](https://developers.openai.com/codex/cli), [Codex-Konfigurationsgrundlagen](https://developers.openai.com/codex/config-basic), [Codex-Konfigurationsreferenz](https://developers.openai.com/codex/config-reference) und [Beispielkonfiguration](https://developers.openai.com/codex/config-sample).
