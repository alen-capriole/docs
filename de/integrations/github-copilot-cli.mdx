## Was ist GitHub Copilot CLI

GitHub Copilot CLI ist ein terminalnativer Coding-Assistent. Sein BYOK-Anbietermodus kann einen OpenAI Chat Completions-kompatiblen Endpunkt nutzen und so Modellanfragen an Capriole AI senden.

Dies ist eine direkte Modellanbieter-Einrichtung für Copilot CLI. Sie ist von Microsoft 365 Copilot getrennt.

Diese Seite dokumentiert Capriole AI endpunktkompatible BYOK-Werte. Validieren Sie Ihre installierte Copilot CLI mit einem Streaming-Prompt und einer lokalen Tool-Anfrage, bevor Sie diese Werte für produktive Coding-Agent-Workflows verwenden.

## Voraussetzungen

Bevor Sie beginnen, stellen Sie sicher, dass Sie Folgendes haben:

- Ein Capriole AI-Konto ([Hier registrieren](https://capriole.ai))
- Einen Capriole AI API-Schlüssel ([Schlüssel abrufen](https://capriole.ai?view=api))
- GitHub Copilot CLI installiert

## Installation

Installieren Sie GitHub Copilot CLI mit npm:

```bash
npm install -g @github/copilot
```

Prüfen Sie die Installation:

```bash
copilot --version
```

Eine GitHub-Authentifizierung ist nicht erforderlich, wenn `COPILOT_PROVIDER_BASE_URL` für den BYOK-Modus gesetzt ist.

## Konfiguration

### Modellvalidierung

GitHub Copilot CLI 1.0.82: `anthropic/claude-fable-5-1`, `google/gemini-3.8-flash` und `zai/glm-5.3-flash` bestehen lokale Prüfungen mit Datei-Lesewerkzeug und abschließender Antwort. `claude-latest` wird zu Fable 5.1 aufgelöst. Bisherige konkrete Modell-IDs bleiben verfügbar.

Die neuen Chat Completions-Prüfungen verwenden `COPILOT_PROVIDER_MODEL_ID="gpt-5.4"`; Fable 5.1 besteht auch die Prüfung über Anthropic Messages mit `claude-latest`.

`xai/grok-4.6` akzeptiert Chat Completions-Anfragen, besteht aber die Coding-Agent-Aufgabenprüfung nicht und ist daher nicht in der folgenden Konfiguration enthalten. Direkte Anbieterprüfungen zeigen auch bei Grok 4.5 inkonsistente Werkzeugnutzung; eine abgeschlossene API-Anfrage belegt keine korrekte Agent-Antwort.

Setzen Sie Capriole AI als OpenAI-kompatiblen Modellanbieter:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
```

Wählen Sie OpenAI latest auf Chat Completions:

```bash
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

Oder wählen Sie GPT 5.4 Mini auf Chat Completions:

```bash
export COPILOT_PROVIDER_MODEL_ID="gpt-5.4"
export COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-5.4-mini"
```

`COPILOT_PROVIDER_MODEL_ID` ist die clientseitige Modellkennung; `COPILOT_PROVIDER_WIRE_MODEL` ist die an Capriole AI gesendete Modell-ID. Verwenden Sie für GPT-6 Astra `gpt-6-astra` mit `openai-latest`. Copilot CLI 1.0.82 akzeptiert diese benutzerdefinierte ID, enthält aber kein Astra-Profil. Ohne explizite Überschreibung gelten die Standardkonfiguration und Standard-Tokenlimits des Clients. Siehe `copilot help providers`.

Lokale Tests mit dieser Astra-Kennung schließen das Dateilesen über Chat Completions ab. Responses liefert bei einem absoluten Pfad den richtigen Inhalt, zeigt aber auch Fehler bei relativen Pfaden und lange Wartezeiten. Eine andere Client-Kennung behebt diese Aufgabenprobleme nicht; prüfen Sie Ihren eigenen Ablauf vor dem Einsatz.

## Dauerhafte Einrichtung

GitHub Copilot CLI speichert allgemeine CLI-Einstellungen in der eigenen Konfiguration, BYOK-Anbietereinstellungen sind jedoch Umgebungsvariablen. Für eine einfache dauerhafte Einrichtung legen Sie ein Capriole AI-Profil in Ihrer Shell-Konfiguration ab.

Fügen Sie dieses endpunktkompatible OpenAI latest Responses-Profil zu `~/.zshrc` hinzu und validieren Sie es mit Ihrer installierten Copilot CLI, bevor Sie es für Coding-Agent-Workflows verwenden:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
alias capriole-copilot="copilot --stream on"
```

Laden Sie Ihre Shell neu:

```bash
source ~/.zshrc
```

Führen Sie anschließend aus:

```bash
capriole-copilot
```

Für einen einmaligen Prompt:

```bash
capriole-copilot -p "Explain this repository structure." --allow-all-tools
```

Um Profile zu wechseln, ändern Sie nur `COPILOT_PROVIDER_WIRE_API`, `COPILOT_PROVIDER_MODEL_ID`, `COPILOT_PROVIDER_WIRE_MODEL` und für Claude Messages zusätzlich `COPILOT_PROVIDER_TYPE`, `COPILOT_PROVIDER_BASE_URL` und `COPILOT_PROVIDER_BEARER_TOKEN`.

## GitHub Copilot CLI ausführen

Starten Sie eine interaktive Sitzung:

```bash
copilot --stream on
```

Führen Sie eine einmalige Anfrage aus:

```bash
copilot -p "Explain this repository structure." --allow-all-tools --stream on
```

Für skriptgesteuerte Nutzung lassen Sie Streaming aktiviert. Die passenden Capriole AI-Endpunkte unterstützen Streaming; validieren Sie den installierten Copilot CLI-Pfad vor dem produktiven Rollout.

## Fehlerbehebung

### Warum gibt Copilot CLI einen Authentifizierungsfehler zurück?

Bestätigen Sie, dass `CAPRIOLE_AI_API_KEY` exportiert ist und dass `COPILOT_PROVIDER_API_KEY` in derselben Shell darauf zeigt, bevor Sie Copilot CLI starten.

### Warum schlagen Anfragen mit Endpunktfehlern fehl?

Bestätigen Sie für OpenAI-kompatible Chat Completions oder Responses, dass `COPILOT_PROVIDER_BASE_URL` `https://api.caprioletech.com/v1` ist.

Bestätigen Sie für Anthropic Messages, dass `COPILOT_PROVIDER_BASE_URL` `https://api.caprioletech.com` ohne `/v1` ist.

### Warum sagt Copilot CLI, dass das Modell fehlt?

Setzen Sie `COPILOT_PROVIDER_MODEL_ID` und `COPILOT_PROVIDER_WIRE_MODEL`. Verwenden Sie für GPT-6 Astra entsprechend `gpt-6-astra` und `openai-latest`.

### Warum sollte Streaming aktiviert bleiben?

Die BYOK-Anforderungen von GitHub legen fest, dass Modelle Streaming und Tool-/Function Calling unterstützen müssen. Belassen Sie Copilot CLI auf dem Streaming-Pfad, damit lokale Tool-Aufrufe vor dem Rollout gegen Capriole AI validiert werden können.

## Hinweise

- Capriole AI stellt Copilot CLI BYOK-Beispiele über die Profilformen Chat Completions, Responses und Anthropic Messages bereit.
- Das Chat Completions-Profil verwendet `POST /v1/chat/completions`, das Responses-Profil `POST /v1/responses` und das Anthropic-Profil `POST /v1/messages`.
- GitHub Copilot CLI führt Coding-Tools lokal aus. Capriole AI verarbeitet nur die Modellanfragen.
- GitHub Copilot CLI hat keine Wire API für die native Capriole AI-Route `POST /v1/chat`.
