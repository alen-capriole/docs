サードパーティの LLM ゲートウェイを使うと、あなたのプロンプトとコードを目にする会社が 1 社増えます。その会社はそれらをログに残すかもしれず、ツールが使う API キーを保持し、各リクエストをあなたが選んでいないかもしれないモデル プロバイダーに転送します。ゲートウェイ経由でソース コードを送る前に、何をどれだけの期間保存するのか、コンテンツを学習に使うのか、どの会社とどの国がリクエストを受け取るのか、キーをどう無効化するのか、プロバイダーに障害が起きたらどうなるのかを確認してください。

Capriole AI もそうしたゲートウェイの 1 つです。月額 USD 8 で GPT-6 Astra、Claude Fable 5.1、Claude Opus 5.5、Gemini 4 Argon とのウェブチャットが無制限になり、アプリやコーディング エージェント向けの API は公式 API 価格より最大 92% 安く使えます。以下では、各質問に対する Capriole AI の回答を、提供していないものも含めて、自社のドキュメントに基づいて示します。

## リスク、確認すべきこと、Capriole AI の回答

| リスク | 確認すべきこと | Capriole AI の回答 |
|---|---|---|
| コンテンツのログ記録 | リクエストとレスポンスの内容を保存するか？保存期間と、読める人は？ | API はリクエストやレスポンスの内容を保持せず、各リクエストの時刻、モデル、トークン数などの使用量記録だけを残します。[API が保持するデータ](/ja/guides/privacy-and-security#api-が保持するデータ) |
| 学習利用 | ゲートウェイはコンテンツを学習に使うか？転送先のプロバイダーはどうか？ | Capriole AI は、あなたのチャット、ファイル、API の内容を AI モデルの学習に使いません。各プロバイダーは自社の規約に基づいてリクエストを扱います。[学習利用](/ja/guides/privacy-and-security#コンテンツは学習に使われません) |
| 上流への露出 | 各リクエストをどの会社が、誰の規約のもとで受け取るか？ | それに答えるモデル プロバイダーか、そのモデルをホストするクラウド プラットフォームです。途中のリクエストはインフラ プロバイダーを経由します。[データを受け取る相手](/ja/guides/privacy-and-security#データを受け取る相手) |
| データの所在地 | サーバーとデータベースはどこにあるか？プロバイダーはどこでデータを処理するか？ | 主要なサーバーとデータベースはインドにあり、プロバイダーは米国を含むほかの国でもデータを処理します。接続は暗号化されています。[セキュリティ](/ja/guides/privacy-and-security#セキュリティ) |
| キーの悪用 | キーを無効化・削除でき、キーごとの使用量を確認できるか？ | はい。キーごとに名前を付けられ、完全なシークレットは一度だけ表示されます。キーの無効化や削除、キーごとの使用量の絞り込みもできます。[キーの管理](/ja/guides/api-keys-usage#キーを無効化、再有効化、または削除する) |
| 支出の暴走 | 支出に上限はあるか？ | API の利用は前払いのトークン残高から引かれ、残高がなくなるとエージェントは止まります。Team では、所有者と管理者がメンバーごとに上限を設定できます。[アラート トークンと上限トークン](/ja/guides/team-plan#アラート-トークンと上限トークンを設定する) |
| チームのアクセス | チームの誰が、誰の使用量を見られるか？ | Team の所有者と管理者は、各メンバーのメールアドレス、役割、Team の API 使用量を見られます。[データを受け取る相手](/ja/guides/privacy-and-security#データを受け取る相手) |
| 予告のないフォールバック | ゲートウェイはいつフォールバックするか？選んだモデルは維持されるか？ | レスポンスが始まる前だけで、リクエストしたモデルは維持されます。[フォールバック](/ja/articles/unified-model-api#フォールバックはレスポンス開始前に起きる) |

ゲートウェイは、プロンプト インジェクションや、コーディング エージェントがあなたのマシン上で行う操作からは守ってくれません。エージェントは引き続きローカルでファイルを読み、コマンドを実行するため、エージェント自身の権限設定はゲートウェイの設定と同じくらい重要です。

ウェブチャットの履歴は API とは別で、アカウントに保存するか、ブラウザだけに保存するか、まったく保存しないかを選べます。全文は[プライバシーとデータ管理ガイド](/ja/guides/privacy-and-security)と[プライバシーポリシー](/ja/legal/privacy)をご覧ください。

## Capriole AI が提供していないもの

Capriole AI は個人と小規模チーム向けに作られています。SAML シングル サインオンはなく、SOC 2 や ISO 27001 などのコンプライアンス認証も公開しておらず、専用のサポート SLA もありません。コードを社内ネットワークの外に出す前にこれらのいずれかが必要な会社では、Capriole AI はその要件を満たしません。

## ゲートウェイにソース コードを送る前に

1. **まずシークレットを取り除く。** `.env` ファイル、認証情報、秘密鍵を、送信するファイルとコンテキストに含めないでください。
2. **ツールごとに専用のキーを用意してテストする。** 機密情報を含まないプロジェクトから最初のリクエストを送り、使用量の行に想定どおりのキーとモデルが表示されることを確認し、使わなくなったキーは無効にしてください。各手順は [API キーと使用量のガイド](/ja/guides/api-keys-usage)で説明しています。
3. **プロバイダーの規約も確認する。** ゲートウェイのポリシーが適用されるのはゲートウェイだけです。回答するモデル プロバイダーは、自社の規約に基づいてリクエストを扱います。

[1 つの API キーでコーディング エージェントを使う](/ja/guides/one-api-key-coding-agents)ガイドでは 10 のエージェントを設定でき、[Claude Code](/ja/integrations/claude-code) と [Codex](/ja/integrations/codex) のページでは各クライアントの設定を説明しています。
