Capriole AI は、最先端モデル チャット、公開 API 許容量、対応コーディング エージェント向けの統一ワークスペースです。サインアウト中の訪問者と Free ユーザーは、サブスクライブ前に GPT-5.6 Thinking、Claude Fable 5、Gemini 3.1 Pro を試せます。USD 8 の Premium は、無制限の Browser Chat、500 万の課金 API トークン、維持されている 6 つのエージェント統合を追加します。

始まりは、私たちが Capriole Charts に AI 機能を追加していたときです。

私たちは最先端モデルへの信頼できるアクセスが必要で、自前の作業を支えられるまでセットアップを安定させるのに長い時間をかけました。それが耐えたとき、同じアクセス レイヤーが Charts の外でも有用だと分かりました。

ChatGPT、Claude、Gemini を使うことは、通常 3 つの製品を訪れることを意味しました。それぞれに独自のサブスクリプション、インターフェイス、履歴、会話の扱い方がありました。API アクセスは別のアカウントと残高のセットを追加しました。コーディング エージェントは、さらに多くのキーと設定をもたらしました。

私たちは、そのインフラを独立した製品として使えるようにすることに決めました。

最初の AI 体験は Charts の中にありました。作業が広がるにつれ、一般チャットとモデル アクセス レイヤーには明らかに広い用途がありました。私たちは、そのワークスペースを Capriole AI として分離し、Charts は自身の製品コンテキストに結びついた AI 機能を残しました。

## 別々の製品のコスト

毎月複数の会社に支払うことは高価です。管理も面倒です。

質問は 1 つのチャットで始まり、別のモデルのほうが有用になる地点に達する場合があります。移動は、プロンプトをコピーし、まだ意味のあるコンテキスト部分を運び、別のインターフェイスに慣れることを意味しました。時間を節約するはずの製品を、ユーザーが調整しなければなりませんでした。

Capriole AI は、対応する最先端モデルを 1 つのウェブチャットに置きます。1 つのモデルで会話を始め、新しい製品を開いたりスレッドを作り直したりせずに、別のモデルへ変えられます。ファイル、ウェブ検索、チャット履歴、モデル選択は同じワークスペースに残ります。

## 異なるモデルを 1 つの製品のように感じさせる

すべてのモデル プロバイダーには独自の前提があります。メッセージ形式は異なります。コンテキスト上限と推論制御も異なります。ファイル、ツール、ストリーミング イベント、トークン会計、エラー レスポンスは、それぞれ独自の扱いが必要です。

公式 AI 製品は、自社モデルをうまく動かせば足ります。Capriole AI は、複数プロバイダーの主要モデルを 1 つの会話内で一貫して振る舞わせる必要があります。

モデル セレクターは仕事の最も小さな部分でした。私たちはプロトコル アダプター、モデル エイリアス、コンテキスト管理、ストリーミング動作、自動フォールバック、エラー処理を作り、磨き続けました。新しいモデル リリースは、同じインターフェイスに属する前に、別ラウンドの互換作業が必要なことがよくあります。

差は実際のリクエストに現れます。1 つのモデル系統は OpenAI Responses イベントを使い、別の系統は Anthropic Messages を期待する場合があります。トークン使用量とエラーは異なる形状で届きます。長いスレッドは、次のモデルが安全に続けられる前にコンテキストを圧縮する必要がある場合があります。モデル切り替えが何事もなく感じられる前に、それらのケースが一緒に動く必要があります。

その作業のほとんどはインターフェイスの背後に残ります。ユーザーは会話の途中で ChatGPT モデルから Claude または Gemini へ切り替え、同じスレッドで続けられます。

同じ Capriole AI アカウントは、Browser Chat、公開 API、維持されている 6 つのコーディング エージェント統合にまたがります。[Codex](/ja/integrations/codex)、[Claude Code](/ja/integrations/claude-code)、[Kilo Code](/ja/integrations/kilo-code)、[GitHub Copilot CLI](/ja/integrations/github-copilot-cli)、[OpenCode](/ja/integrations/opencode)、[OpenClaw](/ja/integrations/openclaw) です。latest モデル エイリアスは、プロバイダー固有のモデル名を追わずに、対応する API とエージェント設定を簡単にします。互換プロトコル経路は私たちが扱うため、エージェント接続が別のプロバイダー統合プロジェクトにはなりません。

## 日常利用向けに価格設定したメンバーシップ

私たちは、高価な AI メンバーシップの集まりを、手頃な 1 つのアカウントに置き換えるために Capriole AI を作りました。

Premium は **月額 USD 8** です。対応する Premium モデル群の無制限 Browser Chat を含みます。見守る Browser Chat クレジット残高はなく、モデルを変えるたびに差し引かれる別の許容量もありません。

Premium メンバーは **毎月 500 万の課金 API トークン** も受け取り、追加使用量はトップアップで利用できます。私たちの [日付付きコスト比較](/ja/articles/ai-api-cost-comparison) では、テストした 3 つのモデル ワークロードそれぞれで Capriole は USD 8 です。直接の有料 Standard 価格は USD 15 から USD 90、OpenRouter は公開のクレジット購入手数料後に USD 15.83 から USD 94.95 です。

テストはあらゆる可能なワークロードではなく、1 つの固定トークン構成を使います。それでも、私たちがメンバーシップをこう作った理由は示します。検証されたより低い API 合計は、推論だけを買うのではなく、完全なワークスペースの中に入ります。

そのため、1 つのアカウントで日常思考に使うチャットと、構築に使う API をカバーできます。Premium ではブラウザは無制限のまま、API は明確で見える使用量残高を保ちます。

## プライバシーは製品内の選択であるべき

保存する調査スレッドと、機密資料を含む会話は、同じストレージ方針を必要としません。

| モード | 永続化 | 主なトレードオフ |
|---|---|---|
| Synced | デバイス間で利用できるアカウント履歴 | 連続性のためにチャットとアップロード ファイル状態が保存される |
| Local | 現在のブラウザのみ | デバイス間の履歴はない。アップロードは無効 |
| No Storage | 現在のページ セッションのみ | 更新または離脱でチャットは失われる。アップロードは無効 |

No Storage を有効にするときは、既存のサーバーおよびローカル チャット履歴を削除する前に、まず確認を求めます。すべてのモードが、引き続きリクエストを Capriole と選択したモデル サービスへ送ります。変えるのは履歴の永続化であり、モデル リクエスト経路ではありません。完全な境界は [チャット ストレージ ガイド](/ja/guides/chat-storage) が説明します。

私たちはプライバシーをワークスペース内の制御にし、各選択の結果をその横で説明しました。

## 私たちが簡単にしたかったこと

Capriole AI は、強いモデルへのアクセスが欲しく、AI アクセスを別の管理仕事にしたくない人向けです。

目標が単にタスクに合うモデルを使うことなら、いくつかの高価なメンバーシップはほとんど意味がありません。有用な会話は、そのモデルが変わっても続けられるべきです。コーディング エージェントは、毎回同じプロバイダー設定を作り直さずに接続できるべきです。

私たちは、お金を節約し、セットアップを減らし、作業の変化に合わせてモデル選択を開いたままにする、1 つのワークスペースが欲しかったのです。別々のサブスクリプション、キー、履歴、インターフェイスが邪魔になっていたとき、私たちが欲しかった製品が、今の Capriole です。

このようなワークスペースと、より広いモデル ゲートウェイのあいだで決めているなら、[Capriole AI と OpenRouter の比較](/ja/articles/capriole-ai-vs-openrouter) が、各製品がどこに合うかを説明します。

[Capriole AI を開く](https://capriole.ai) と、制限付きの無料チャットで現在の旗艦セットを試せます。無制限の Browser Chat、含まれる API 残高、同じアカウントの下で維持されているコーディング エージェント経路が必要なときは、USD 8 の Premium にアップグレードしてください。開発者は [API クイックスタート](/ja/quickstart) で続けられます。
