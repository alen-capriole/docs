Capriole AI は、別々の AI サブスクリプションを USD 9 の 1 つのメンバーシップに置き換えます。**GPT-6.2 Astra、Claude Fable 5.1、Claude Opus 5.5、Gemini 4 Carbon** とのウェブチャットが無制限になり、API も公式 API 価格より最大 92% 安く使えます。サインアウト中の訪問者と Free ユーザーは、支払い前に無料のウェブチャットで同じ旗艦モデルを試せます。

Premium は **月額 USD 9** で、対応する Premium モデル群の無制限のウェブチャットを提供します。**毎月 500 万の課金 API トークン**、10 のコーディング エージェント向けセットアップ ガイド、モデル切り替え、ファイル、ウェブ検索、チャットをまたぐメモリ、明示的なチャット ストレージ制御も含みます。

結果は、複数のサブスクリプション、インターフェイス、履歴、プロバイダー キー、残高ではなく、対応する最先端モデル向けの 1 つのアカウントです。

## 問題は月額請求より大きい

複数の AI 製品を使うことは、通常、複数のブラウザ タブ、請求ページ、履歴、インターフェイス、制御セットを意味します。使用量の測り方も製品ごとに異なります。たとえば Claude Pro と Max では、チャットと Claude Code が [5 時間と週の上限](/ja/articles/claude-usage-limits)を共有します。1 つの製品で始まったタスクが、あとで別のモデルを必要とする場合があります。移動は小さな移行になります。有用なコンテキストをコピーし、ファイルを再添付し、タスクを再び説明し、次のインターフェイスがどの制御を出すかを学びます。

API 作業はプロバイダー アカウント、キー、残高、モデル名、互換でないリクエスト形式を追加します。コーディング エージェントは別の設定レイヤーを追加します。これらの手順は個別には難しくありませんが、合わせてモデル選択をアカウント管理に変えます。

Capriole AI は共通部分を 1 つのワークスペースに集めます。対応モデルとチャットし、会話内でモデルを変え、ファイルまたはウェブ検索を使い、スレッドを同じインターフェイスに保てます。製品はその切り替えの背後でプロトコルとコンテキストの差を扱います。

## USD 9 の 1 つのメンバーシップが置き換えるもの

| プランの部分 | 含まれるもの | 使い方 |
|---|---|---|
| Premium のウェブチャット | 対応する Premium モデル群の無制限チャット | 対応する日常作業では、1 つの Capriole ワークスペースが別々のプロバイダー チャット インターフェイスを置き換えます |
| 月次 API 利用枠 | 5,000,000 課金 API トークン | コーディングエージェントは Capriole AI の API キーを使い、利用量に応じて API トークン残高を消費します。 |
| API チャージ | 追加の token パックを購入できます | チャージは月次サブスクリプションとは別です |
| コーディング エージェント | Capriole API キーを文書化された統合で使えます | [エージェントの設定](/ja/guides/one-api-key-coding-agents) |
| 無料アクセス | アップグレード前の[無料のウェブチャット](/ja/articles/ai-chat-without-login) | 登録前に旗艦モデルを試せます |

Capriole は、上に名前を挙げた旗艦セットを含め、OpenAI、Anthropic、Google、xAI、Z.ai、Moonshot AI の現在対応するモデルを同じワークスペース内で維持します。

ブラウザと API は異なる使用量モデルを持ちます。Premium のウェブチャットには、ユーザーが管理するメッセージごとのトークン残高はありません。プログラム ワークロードは通常のチャット利用を大きく超えて伸びうるため、API リクエストは計量されます。

ウェブチャットとコーディングエージェントには同じ Premium アカウントを使えます。API ページでトークン使用量を確認できます。

特定のプランから乗り換えるなら、Premium を [ChatGPT Plus](/ja/articles/chatgpt-plus-alternative)、[Claude と ChatGPT](/ja/articles/claude-vs-chatgpt)、[Poe](/ja/articles/capriole-ai-vs-poe)、[TypingMind](/ja/articles/capriole-ai-vs-typingmind)、[Magai](/ja/articles/capriole-ai-vs-magai)、[Venice](/ja/articles/capriole-ai-vs-venice) と比べてみてください。

## 1 つの会話、異なるモデルの強み

異なるモデル系統は、同じタスクの異なる部分に有用です。スレッドは調査から始まり、慎重な文章へ移り、コードまたは構造化分析で終わる場合があります。別々の製品では、ユーザーがコンテキストを運ぶ必要があります。

Capriole は、選択モデルが変わるあいだも会話を 1 つのワークスペースに残せます。見える操作はモデル選択です。その下では、メッセージ形式、コンテキスト上限、推論制御、ファイル、ツール、ストリーミング イベント、トークン会計、エラーがすべて異なる扱いを必要とする場合があります。

Capriole はその適応を製品の一部として維持するため、選択モデルを変えても、ユーザーがスレッドまたは統合を作り直す必要はありません。

Capriole は、対応する API とエージェント ワークフロー向けに latest モデル エイリアスも提供します。ユーザーがすべての正確なモデル識別子をすぐに更新しなくても、設定がプロバイダー系統向けの Capriole 推奨現在モデルに従えます。

## 同じアカウントはブラウザを離れられる

対象となる有料アクセスは、ウェブチャットだけでなく Capriole の公開 API も解除します。[API クイックスタート](/ja/quickstart) が最初のリクエストを扱い、維持ガイドは 10 のコーディング エージェントを扱います。[Codex](/ja/integrations/codex)、[Claude Code](/ja/integrations/claude-code)、[GitHub Copilot CLI](/ja/integrations/github-copilot-cli)、[OpenCode](/ja/integrations/opencode)、[OpenClaw](/ja/integrations/openclaw)、[Kilo Code](/ja/integrations/kilo-code)、[Cline](/ja/integrations/cline)、[Qwen Code](/ja/integrations/qwen-code)、[Crush](/ja/integrations/crush)、[Pi](/ja/integrations/pi) です。

各クライアントは引き続き独自の能力と期待を持ちます。利点は、対応クライアントが各系統向けの別モデル プロバイダー設定を必要とせず、1 つの Capriole アカウントと互換 API 経路を使えることです。

## チャット履歴の置き場所を選ぶ

すべての会話が同じストレージ方針に値するわけではありません。

| モード | チャット履歴が残る場所 |
|---|---|
| Synced | Capriole アカウント ストレージ |
| Local | このブラウザのローカル ストレージ |
| No Storage | 現在のページ セッションのみ |

既定のアカウントストレージを使うと、端末間でチャットを同期し、ファイルをアップロードできます。

Local 履歴は、そのブラウザのサイト データを消すまで更新後も残ります。No Storage 履歴は、ページが更新されるかユーザーが離れると失われます。有効化時は、既存のサーバーおよびローカル チャット履歴を削除する前に確認を求めます。

3 モードすべてが、各リクエストを引き続き Capriole と選択したモデル サービスへ送ります。機密または規制対象データを使う前に、[チャット ストレージ ガイド](/ja/guides/chat-storage) を読んでください。

Server Storage を使うログイン済みアカウントでは、GPT Image 2.6、Nano Banana 2.1、Seedream 5.5 による無料の画像生成も利用できます。詳しくは [画像生成ガイド](/ja/guides/files-web-search) をご覧ください。
