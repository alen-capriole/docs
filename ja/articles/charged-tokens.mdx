課金トークンは、Capriole AI API 残高から差し引かれる単位です。個人 Premium は、USD 9 のワークスペース メンバーシップの一部として、毎月 500 万を含みます。キャッシュなし入力と出力は 100% で数えます。キャッシュ入力は 10% で数え、次の整数トークンへ切り上げます。

公開 API とコーディング エージェントのトラフィックに適用され、その料金は公式 API 価格より最大 92% 安くなります。Premium の無制限のウェブチャットはこの API 残高を消費しません。

## 計算式

Capriole は、対応する各プロトコルを入力トークンの合計数に正規化し、選択したプロバイダーが報告する場合はキャッシュ入力数も正規化します。キャッシュ入力は合計入力の部分集合です。

```text
uncached_input = input_tokens - cached_input

charged_tokens =
  uncached_input
  + ceil(cached_input × 0.1)
  + output_tokens
```

プロバイダーがキャッシュ入力を報告しない場合、すべての入力トークンは 100% で数えられます。

| プロトコル | 正規化後の入力 | キャッシュ部分集合 |
|---|---|---|
| OpenAI Responses | `input_tokens` | `input_tokens_details.cached_tokens` |
| OpenAI Chat Completions | `prompt_tokens` | `prompt_tokens_details.cached_tokens` |
| Anthropic Messages | `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` | `cache_read_input_tokens` |

Anthropic Messages では、キャッシュ作成（cache creation）は引き続き 100% の入力として数えます。10% の課金トークン扱いになるのは、報告されたキャッシュ読み取り（cache reads）だけです。

## 再現可能な 3 つの例

| 例 | 入力合計 | キャッシュ入力 | 出力 | 計算 | 課金トークン |
|---|---:|---:|---:|---|---:|
| キャッシュ ヒットなし | 800 | 0 | 200 | `800 + 0 + 200` | 1,000 |
| ほとんどキャッシュされたプロンプト | 10,000 | 8,000 | 500 | `2,000 + ceil(800) + 500` | 3,300 |
| 報告されたキャッシュ ヒットが大きい | 228,807 | 228,224 | 90 | `583 + ceil(22,822.4) + 90` | 23,496 |

3 番目のリクエストは、生の入力 + 出力トークンが 228,897 です。プロバイダーが 228,224 入力トークンをキャッシュ済みと報告したため、23,496 課金トークンを差し引きます。

丸めは、記録された各リクエストのキャッシュ部分に対して行われます。そのため、キャッシュ入力トークン 1 個は `ceil(0.1)` のあと 1 トークン課金され、キャッシュ入力トークン 10 個も 1 トークン課金されます。

## 500 万課金トークンで何件のリクエストが入るか見積もる

生のコンテキスト サイズから推測せず、自分の API 使用量の平均課金トークン値を使ってください。

```text
estimated_requests = floor(5,000,000 / average_charged_tokens_per_request)
```

| リクエストあたりの平均課金トークン | 500 万課金トークンから得られるリクエスト数 |
|---:|---:|
| 1,000 | 5,000 |
| 5,000 | 1,000 |
| 25,000 | 200 |
| 100,000 | 50 |

これらの行は計画用の算術であり、典型的なワークロードの主張ではありません。短い分類呼び出しと長いコーディング エージェントのターンは、桁が違う場合があります。出力の長さ、繰り返されるコンテキスト、プロバイダーが報告するキャッシュ ヒット、ツール結果は、いずれも実測平均を変えます。

## 課金トークンとプロバイダー価格は異なる単位を使う

公式プロバイダーは、入力、キャッシュ入力、キャッシュ書き込み、出力、ツール、または長いコンテキストに別々の価格を公開する場合があります。Capriole の課金トークン残高は、対応する公開 API ルート全体で 1 つの計算式を使う顧客クォータ単位です。

| 単位 | 答えること |
|---|---|
| プロバイダーの入力と出力の価格 | プロバイダーが自身の価格表の下でいくら請求するか |
| 生の API 使用量トークン | レスポンスが報告する入力、出力、キャッシュ トークンの数 |
| Capriole の課金トークン | Capriole がアカウントの API 残高からいくら差し引くか |

課金トークンに、プロバイダーが公開する入力または出力レートを掛けないでください。単位は異なる請求システムを表します。

[日付付き API コスト比較](/ja/articles/ai-api-cost-comparison) は、この計算式を固定の 500 万トークン ワークロードに適用し、各サービスの現金コストを比較します。[Claude API の料金](/ja/articles/claude-api-pricing)、[OpenAI API の料金](/ja/articles/openai-api-pricing)、[Gemini API の料金](/ja/articles/gemini-api-pricing) では、現在の 100 万トークンあたりの公式料金を、Capriole の 500 万トークンあたり USD 8 と比較しています。

## 個人と Team の残高境界

| アクセス | 含まれる API 残高 | チャージの基本価格 | 現在の規則 |
|---|---:|---:|---|
| 個人 Premium | 有効な月次クォータ期間ごとに 500 万課金トークン | 500 万あたり USD 8 | 公開 API と個人チャージには有効な Premium アクセスが必要です。複数パックの購入には、表示されるボリューム割引が最大 15% まで適用されます |
| Team | 有効な月次クォータ期間ごとに共有 5,000 万課金トークン | 5,000 万あたり USD 80 | USD 70/月 に [5 シート](/ja/guides/team-plan)が含まれます。所有者と管理者は 1 から 5 パックまで購入でき、表示されるボリューム割引は最大 10% です |

含まれるクォータは、対応する個人または Team のチャージ ウォレットより先に消費されます。購入したチャージ残高は、月次クォータ期間と有料アクセスの空白をまたいで残ります。消費するには、対象となる有効な有料アクセスが引き続き必要です。ウェブチャットは API 会計とは別です。コーディング エージェントは API トラフィックとして数えられ、課金トークンを差し引きます。

月額 USD 9 の Premium には、毎月 5,000,000 トークン分の API 利用枠が含まれます。

## API が記録すること

Capriole は、プロトコル正規化済み使用量と課金使用量を別フィールドとして保持します。成功した公開 API リクエストは、次を記録できます。

- 正規化後の入力トークン
- 出力トークン
- 正規化後の入力 + 出力トークン
- プロバイダーが報告したキャッシュ入力トークン
- クォータから差し引かれた課金トークン
- 解決後のモデルとリクエスト ステータス

Responses、Chat Completions、Messages エンドポイントは上流のレスポンス形状を保持し、`charged_tokens` フィールドは返しません。Capriole はアカウント使用量向けに対応する課金トークン値を記録します。この値は [API ページ](https://www.capriole.ai/ja?view=api) の使用量テーブルの **課金 tokens** 列で確認できます。

## キャッシュ入力が課金を減らしたかを確認する

Capriole AI の [API ページ](https://www.capriole.ai/ja?view=api) を開き、**キー名**、**モデル**、**ステータス** フィルタでリクエストを切り出します。使用量テーブルの次の列を比較してください。

| 列 | 確認できること |
|---|---|
| **入力 tokens** | キャッシュ入力を分ける前の、プロトコル正規化済み入力 |
| **キャッシュ tokens** | プロバイダーがキャッシュ済みと報告した入力 |
| **課金 tokens** | キャッシュ入力の計算式を適用したあと差し引かれたクォータ |
| **合計 tokens** | プロトコル正規化済みの入力 + 出力 |

正のキャッシュ トークン値は、互換のプロバイダー使用量メタデータがキャッシュ ヒットを報告したことを確認します。プロバイダー ルーティング、キャッシュ寿命、リクエスト構造、モデル動作は結果を変える場合があります。

API レスポンスは上流スキーマを保持するため、ルートをまたいでリクエストを比較する一貫した場所はアカウント使用量テーブルです。

## よくある質問

### キャッシュ入力は常に 90% のクォータ割引を受けますか？

プロバイダーの使用量データにキャッシュ読み取りとして記録された入力トークンには 90% の割引が適用されます。ほかの入力トークンは標準料金です。

### reasoning トークンは 2 回加算されますか？

いいえ。プロバイダーが報告する出力使用量には、そのルートが使う出力会計がすでに含まれています。Capriole はこの計算式の出力の上に、別の reasoning トークン課金を加算しません。

### Premium では API やコーディングエージェントの利用量をどう計算しますか？

Premium にはアプリやコーディングエージェントで使える API 利用枠が毎月 5,000,000 トークン分含まれます。追加の 5,000,000 トークンは USD 8 です。

### コーディングはどこから始めるべきですか？

最小の生リクエストには [API クイックスタート](/ja/quickstart)、プロトコルネイティブの Python と TypeScript クライアントには [OpenAI と Anthropic の SDK ガイド](/ja/guides/openai-anthropic-sdks) を使ってください。まだサブスクライブしていない場合は、アップグレード前に [無料ウェブチャットで旗艦モデルを試す](https://www.capriole.ai/ja) ことができます。
