アプリケーション、SDK、またはエージェントが OpenAI Responses のリクエストとレスポンス形式を期待する場合は、このエンドポイントを使ってください。

`model` と `input` を含む標準の Responses ペイロードを送信します。Capriole AI は上流へ送る前に latest エイリアスを選択した上流モデル ID に解決し、`instructions`、`tools`、`reasoning`、`previous_response_id`、`stream` などの互換フィールドを転送し、上流の JSON または SSE ストリームをそのまま返します。

`POST /v1/responses` は `openai-latest`、`openai/gpt-6-astra`、`openai/gpt-6.1-sol`、`openai/gpt-6-sol`、`openai/gpt-6-luna`、`openai/gpt-5.6-terra`、`openai/gpt-5.6-luna`、`openai/gpt-5.5` を受け付けます。推奨する旗艦 OpenAI Responses モデルを Capriole AI に選ばせるには、`openai-latest` を使ってください。

`gpt-6-astra` のように、`openai/` プレフィックスのないネイティブ OpenAI ID も送信できます。ネイティブ ID とプレフィックス付き ID は、ルーティング、料金、利用枠の計算に同じモデルレコードを使います。

このエンドポイントは Grok モデル `xai/grok-4.7`、`xai/grok-4.6`、`xai/grok-4.5` も受け付けます。Grok の ID は必ず `xai/` プレフィックス付きで送信してください。`grok-4.7` のようなプレフィックスのない ID はネイティブ OpenAI ID として扱われ、拒否されます。Grok のリクエストは形式を変換せずに xAI 自身の Responses API へ転送されます。

このエンドポイントでは、ほかのモデルはサポートされません。対象は `claude-latest`、`google-latest`、`anthropic/claude-fable-5-1` や `google/gemini-4-argon` などの Claude と Gemini のモデル ID、そして GLM と Kimi のモデル (`zai/glm-5.3-flash`、`zai/glm-5.2`、`moonshot/kimi-k3.1-pro`、`moonshot/kimi-k3`) です。公開モデルをすべて呼べる 1 つの OpenAI 互換エンドポイントが必要な場合は、`POST /v1/chat/completions` を使ってください。

## ウェブ検索

組み込みの `web_search` ツールを追加すると、GPT または Grok モデルがウェブを検索できます。

```bash
curl https://api.caprioletech.com/v1/responses \
  -X POST \
  -H "Authorization: Bearer YOUR_CAPRIOLE_AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "xai/grok-4.7",
    "input": "Summarize the latest AI news.",
    "tools": [{"type": "web_search"}],
    "stream": true
  }'
```

ウェブ検索では取得した検索結果がリクエストの入力トークンに加算されるため、検索を伴う回答はプロンプトだけの場合よりはるかに多くの入力トークンを使うことがあります。

`POST /v1/chat/completions` はウェブ検索を提供しません。

## 長時間のタスク

ウェブ検索や長い推論などの長時間タスクでは `"stream": true` を設定してください。ストリーミングを使わない場合、約 2 分で接続がタイムアウトすることがあります。
