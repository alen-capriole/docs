## Claude Code とは

Claude Code は、コードベースの読み取り、ファイル編集、コマンド実行、開発ツールとの統合を行う Anthropic のエージェント型コーディング ツールです。このセットアップでは、Claude Code のゲートウェイ設定（API エンドポイント、認証トークン、各エイリアスのモデル）を使って、接続先を Capriole AI にします。

## 前提条件

始める前に、次を用意してください。

- Capriole AI アカウント（[こちらから登録](https://capriole.ai)）
- Capriole AI API キー（[キーを取得](https://capriole.ai?view=api)）

## インストール

公式のネイティブ インストーラーで Claude Code をインストールします。

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

または、Homebrew でインストールします。

```bash
brew install --cask claude-code
```

または、npm でインストールします（Node.js 22 以降）。

```bash
npm install -g @anthropic-ai/claude-code
```

インストールを確認します。

```bash
claude --version
```

## 設定

### モデルの検証

Claude Code 2.1.304 は、下記の設定を使い、「対応モデル」のすべてのモデルで、Capriole AI 経由のファイル読み取り、ファイル書き込み、最終回答の確認に合格しています。

`~/.claude/settings.json` を作成または更新します。

```json
{
  "model": "claude-fable-5-1",
  "env": {
    "ANTHROPIC_BASE_URL": "https://api.caprioletech.com",
    "ANTHROPIC_AUTH_TOKEN": "YOUR_CAPRIOLE_AI_API_KEY",
    "ANTHROPIC_DEFAULT_OPUS_MODEL": "claude-opus-5-5",
    "ANTHROPIC_DEFAULT_SONNET_MODEL": "claude-fable-5-1",
    "ANTHROPIC_DEFAULT_HAIKU_MODEL": "claude-sonnet-4-6"
  }
}
```

各設定の役割は次のとおりです。

- `model` は新しいセッションのデフォルト モデルです。`/model` で選んだモデルは保存され、次回も使われます。
- `ANTHROPIC_BASE_URL` はリクエストの送信先を Capriole AI にします。`/v1` は付けないでください。Claude Code が `/v1/messages` を自動で付加します。
- `ANTHROPIC_AUTH_TOKEN` はキーを Bearer トークンとして送ります。Capriole AI ではこの形式が必須です。
- 3 つの `ANTHROPIC_DEFAULT_*_MODEL` の値は、`opus`、`sonnet`、`haiku` の各エイリアスを Capriole AI が提供するモデルに割り当てます。`haiku` は、Claude Code が簡単なバックグラウンド処理に使うモデルです。

一度きりのシェル設定では、エンドポイントとトークンをエクスポートしてから、モデルを渡します。

```bash
export ANTHROPIC_BASE_URL="https://api.caprioletech.com"
export ANTHROPIC_AUTH_TOKEN="YOUR_CAPRIOLE_AI_API_KEY"
claude --model claude-fable-5-1
```

## Claude Code を実行する

プロジェクト ディレクトリから Claude Code を起動します。

```bash
claude
```

セッション中は `/model` でモデルを切り替えます。たとえば `/model opus` で Opus 5.5 に切り替わります。非対話で実行するには、print モードを使います。

```bash
claude -p "Explain this repository."
```

## 対応モデル

Claude Code は Anthropic Messages プロトコルを使うため、Capriole AI の Claude モデルに対応しています。

- `claude-fable-5-1`（Fable 5.1、推奨のデフォルト）
- `claude-opus-5-5`（Opus 5.5）
- `claude-fable-5`
- `claude-opus-5`
- `claude-opus-4-8`
- `claude-opus-4-7`
- `claude-opus-4-6`
- `claude-sonnet-4-6`
- `claude-latest`（常に最新の Claude 旗艦モデルを指します。現在は Fable 5.1）

Claude Code は `claude-latest` をモデル名として認識しないため、コンテキスト ウィンドウを 200K とみなします。モデル本来のコンテキスト ウィンドウを使うには、`claude-fable-5-1` などの具体的な ID を使ってください。

## トラブルシューティング

### Claude Code が認証エラーを返すのはなぜですか？

`ANTHROPIC_API_KEY` ではなく `ANTHROPIC_AUTH_TOKEN` を使ってください。`ANTHROPIC_API_KEY` はキーを `x-api-key` ヘッダーで送りますが、Capriole AI は Bearer トークンしか受け付けません。

### エンドポイント エラーでリクエストが失敗するのはなぜですか？

`ANTHROPIC_BASE_URL` が `/v1` なしの `https://api.caprioletech.com` であることを確認してください。

### 起動のたびに Claude Code が別のモデルに戻るのはなぜですか？

設定とシェルから `ANTHROPIC_MODEL` を削除してください。これが設定されていると、Claude Code は次回の起動時に、`/model` で保存したモデルではなくそのモデルに戻ります。

### `/model opus` や `/model sonnet` が失敗するのはなぜですか？

3 つの `ANTHROPIC_DEFAULT_*_MODEL` の値を残してください。これらがないと、Claude Code は Anthropic 独自のエイリアス先を送ります。たとえば `sonnet` は `claude-sonnet-5-5` をリクエストしますが、Capriole AI はこのモデルを提供していないため、リクエストは `Unsupported Claude Messages model` で失敗します。

### Claude Code が設定した思考レベルを使わないのはなぜですか？

Claude Code は思考レベルをモデルごとに保存します。そのモデルを使用中に `/effort` で選んでください。ユーザー設定のトップレベルにある `effortLevel` は Opus 5.5 には適用されません。

### トークンカウントが失敗するのはなぜですか？

Capriole AI は `/v1/messages/count_tokens` を選択した上流に転送します。その上流がトークンカウントに対応していない場合、Claude Code は代わりにトークン数を推定し、セッションはそのまま動作します。

## 注意事項

- `~/.claude/settings.json` は、すべてのプロジェクトでユーザー アカウントに適用されます。`YOUR_CAPRIOLE_AI_API_KEY` は Capriole AI API キーに置き換えてください。
- Claude Code は Anthropic Messages プロトコルしか扱わないため、Gemini、Grok、GLM、Kimi のモデルは Claude Code では動作しません。これらのモデルには OpenCode、Kilo Code、または他のマルチプロトコル対応エージェントを使ってください。
- 公式リファレンス: [Claude Code セットアップ](https://code.claude.com/docs/en/setup)、[モデル設定](https://code.claude.com/docs/en/model-config)、[LLM ゲートウェイ設定](https://code.claude.com/docs/en/llm-gateway-connect)。
