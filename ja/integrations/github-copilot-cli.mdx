Capriole AI の API キー 1 つで、GitHub Copilot CLI から GPT-6 Astra、Claude Fable 5.1、Opus 5.5 を公式 API 価格より最大 92% 安く使えます。

## GitHub Copilot CLI とは

GitHub Copilot CLI は、ターミナル向けの GitHub のコーディング エージェントです。BYOK（bring-your-own-key）モードでは、環境変数で設定したプロバイダーにモデル リクエストを送ります。このセットアップでは、その送信先を Capriole AI にします。

## 前提条件

始める前に、次を用意してください。

- Capriole AI アカウント（[こちらから登録](https://www.capriole.ai/ja)）
- Premium プラン（月額 USD 8、無制限の Web チャットも含む）または Team プラン。API キーにはどちらかが必要です（[購読する](https://www.capriole.ai/ja?view=api)）
- Capriole AI API キー（[キーを取得](https://www.capriole.ai/ja?view=api)）

## インストール

npm で GitHub Copilot CLI をインストールします。

```bash
npm install -g @github/copilot
```

インストールを確認します。

```bash
copilot --version
```

`COPILOT_PROVIDER_BASE_URL` が設定されている場合、GitHub へのサインインは不要です。

## 設定

### モデルの検証

GitHub Copilot CLI 1.0.100 は、下記のプロファイルを使い、「対応モデル」のすべてのモデルで、Capriole AI 経由のファイル読み取り、ファイル書き込み、最終回答の確認に合格しています。

Copilot CLI は一度に 1 つのプロバイダーしか使わないため、使いたいモデル ファミリーのプロファイルを選んでください。各プロファイルでは 2 つのモデル値を設定します。

- `COPILOT_PROVIDER_WIRE_MODEL` は、Copilot が送信する Capriole AI のモデル ID です。
- `COPILOT_PROVIDER_MODEL_ID` は、Copilot が認識しているモデルです。Copilot はこれを基に、ツール、プロンプト、トークン上限を選びます。

### GPT モデル

GPT モデルは Responses API を使います。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

GPT-6.1 Sol では、`COPILOT_PROVIDER_MODEL_ID="gpt-6.1-sol"` と `COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-6.1-sol"` を設定します。

### Claude モデル

Claude モデルは Anthropic Messages を使います。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="anthropic"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com"
export COPILOT_PROVIDER_BEARER_TOKEN="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"
export COPILOT_PROVIDER_WIRE_MODEL="claude-latest"
```

Opus 5.5 では、`COPILOT_PROVIDER_WIRE_MODEL="claude-opus-5-5"` を設定します。

- `COPILOT_PROVIDER_BEARER_TOKEN` はキーを Bearer トークンとして送ります。`COPILOT_PROVIDER_API_KEY` を使うとキーが `x-api-key` ヘッダーで送られますが、Capriole AI はこれを受け付けません。
- Copilot が `/v1/messages` を自動で付加するため、ベース URL には `/v1` を付けません。
- `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"` はそのままにしてください。`claude-sonnet-4` などの古いプロファイルでは Copilot が思考予算を送り、Opus 5.5 はそれを `requires adaptive thinking` で拒否します。

### Gemini、Grok、GLM、Kimi モデル

これらのモデルは Chat Completions を使います。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
export COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"
export COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3"
```

他のモデルでは、`COPILOT_PROVIDER_WIRE_MODEL` を `google/gemini-3.8-flash`、`xai/grok-4.7`、または `zai/glm-5.3-flash` に変更します。

`COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"` はそのままにしてください。`gpt-5.4` などの GPT プロファイルでは、これらのモデルが受け付けないツール タイプを Copilot が送ります。

Kimi K3.1 Pro では、`COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"` と `COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3.1-pro"` を設定してください。`claude-sonnet-4` プロファイルは `temperature: 0` を送りますが、Kimi K3.1 Pro はこれを受け付けません。

プロファイルを保持するには、その行を `~/.zshrc` または `~/.bashrc` に追加してから、新しいターミナルを開きます。

## GitHub Copilot CLI を実行する

プロジェクト ディレクトリから Copilot CLI を起動します。

```bash
copilot
```

非対話で実行するには、`-p` でプロンプトを渡します。

```bash
copilot -p "Explain this repository." --allow-all-tools
```

| モデル | `COPILOT_PROVIDER_WIRE_MODEL` | `COPILOT_PROVIDER_MODEL_ID` | プロトコル |
| --- | --- | --- | --- |
| OpenAI latest | `openai-latest` | `gpt-6-astra` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | `gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | `claude-opus-4.6` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | `claude-opus-4.6` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | `claude-sonnet-4` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | `claude-sonnet-4` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | `claude-sonnet-4` | Chat Completions |
| Kimi K3.1 Pro | `moonshot/kimi-k3.1-pro` | `claude-opus-4.6` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | `claude-sonnet-4` | Chat Completions |

`openai-latest` と `claude-latest` は、常に各ファミリーの最新の旗艦モデルを指します。現在は GPT-6 Astra と Claude Fable 5.1 です。

## トラブルシューティング

### Copilot CLI が認証エラーを返すのはなぜですか？

同じシェルで `CAPRIOLE_AI_API_KEY` がエクスポートされていることを確認してください。Claude モデルでは、`COPILOT_PROVIDER_API_KEY` ではなく `COPILOT_PROVIDER_BEARER_TOKEN` を使ってください。

### エンドポイント エラーでリクエストが失敗するのはなぜですか？

GPT、Gemini、Grok、GLM、Kimi のモデルでは、`COPILOT_PROVIDER_BASE_URL` は `https://api.caprioletech.com/v1` です。Claude モデルでは、`/v1` なしの `https://api.caprioletech.com` です。

### Opus 5.5 が `requires adaptive thinking` で失敗するのはなぜですか？

`COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"` を設定してください。

### Gemini、Grok、GLM、Kimi のリクエストがツール エラーで失敗するのはなぜですか？

`COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`（Kimi K3.1 Pro では `"claude-opus-4.6"`）を設定してください。GPT プロファイルでは、OpenAI モデルしか受け付けないツール タイプが送られます。

## 注意事項

- Copilot CLI はコーディング ツールをお使いのコンピューター上で実行します。Capriole AI が処理するのはモデル リクエストだけです。
- `copilot help providers` を実行すると、すべての BYOK 環境変数を確認できます。
- 同じキーを他のコーディング エージェントでも使うには、[1 つの API キーでコーディング エージェントを使う](/ja/guides/one-api-key-coding-agents)を参照してください。
- 公式リファレンス: [GitHub Copilot CLI のインストール](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)、[Copilot CLI で BYOK モデルを使う](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models)。
