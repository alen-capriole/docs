## Codex とは

Codex は、ソフトウェア開発向けの OpenAI のコーディング エージェントです。Capriole AI の Responses 互換 API にリクエストを送るカスタム モデル プロバイダーを設定すると、Capriole AI を利用できます。

## 前提条件

始める前に、次を用意してください。

- Capriole AI アカウント（[こちらから登録](https://capriole.ai)）
- Capriole AI API キー（[キーを取得](https://capriole.ai?view=api)）

## インストール

### Codex CLI

公式インストーラーで Codex CLI をインストールします。

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

または、npm でインストールします。

```bash
npm install -g @openai/codex
```

インストールを確認します。

```bash
codex --version
```

### Codex app

[OpenAI Codex](https://developers.openai.com/codex) からアプリをダウンロードしてください。

## 設定

### モデルの検証

Codex CLI 0.160.1 は、下記の設定を使い、Capriole AI 経由のファイル読み取り、ファイル書き込み、最終回答の確認に合格しています。

`~/.codex/config.toml` を作成または更新します。

```toml
model = "gpt-6-astra"
model_reasoning_effort = "high"
model_provider = "capriole_ai"

[model_providers.capriole_ai]
name = "Capriole AI"
base_url = "https://api.caprioletech.com/v1"
wire_api = "responses"
env_key = "CAPRIOLE_AI_API_KEY"
env_key_instructions = "Export CAPRIOLE_AI_API_KEY before starting Codex"
```

各設定の役割は次のとおりです。

- `model` はデフォルト モデルです。セッション中は `/model`、コマンドラインでは `--model` で変更できます。
- `model_provider` は、その下で定義している Capriole AI プロバイダーを選択します。
- Codex が `/responses` を自動で付加するため、`base_url` には `/v1` を含めます。
- `wire_api = "responses"` は Responses API を使います。Codex がカスタム プロバイダーで対応しているプロトコルはこれだけです。
- `env_key` は環境変数からキーを読み取り、Bearer トークンとして送ります。

## Codex を実行する

API キーを設定してから、プロジェクト ディレクトリから Codex を起動します。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
codex
```

非対話で実行するには、`codex exec` を使います。

```bash
codex exec "Explain this repository."
```

## 対応モデル

Codex は Responses API 経由で Capriole AI の OpenAI モデルを使えます。以下のネイティブ モデル ID を使うと、Codex 標準のモデル選択と推論設定を利用できます。独自の `model_catalog_json` は不要です。呼び出せるのは Capriole AI が対応しているモデルのみです。

- `gpt-6-astra`
- `gpt-6.1-sol`
- `gpt-6-sol`
- `gpt-6-luna`
- `gpt-5.6-terra`
- `gpt-5.6-luna`
- `gpt-5.5`

`gpt-6.1-sol` には Codex 0.159.2 以降を使ってください。それより前のバージョンにはこのモデルのメタデータがなく、汎用設定にフォールバックします。

API は `openai/` プレフィックス付きの ID と `openai-latest` も受け付けます。`openai-latest` エイリアスは、Capriole AI が推奨する OpenAI の旗艦モデルに追従します。

Capriole AI は Grok を Responses API で提供しているため、Codex は同じプロバイダー経由で `xai/grok-4.7` も実行できます。

Codex に組み込まれているメタデータは、OpenAI のネイティブ モデル ID 用のものだけです。`openai-latest` と `xai/grok-4.7` では `Model metadata ... not found` と表示され、フォールバック設定が使われます。セッションはそのまま動作しますが、最良の結果を得るには `gpt-6-astra` などのネイティブ ID を使ってください。

## トラブルシューティング

### Codex が認証エラーを返すのはなぜですか？

`codex` を実行する前に、同じシェルで `CAPRIOLE_AI_API_KEY` がエクスポートされていることを確認してください。

### Codex がモデルを見つけられないのはなぜですか？

`model_provider = "capriole_ai"` が設定されており、`model` が「対応モデル」に記載した ID のいずれかであることを確認してください。

### エンドポイントまたはプロトコル エラーでリクエストが失敗するのはなぜですか？

`[model_providers.capriole_ai]` の下に `base_url = "https://api.caprioletech.com/v1"` と `wire_api = "responses"` が設定されていることを確認してください。

### Codex が Capriole AI プロバイダーを無視するのはなぜですか？

`openai` などの予約済み組み込みプロバイダー ID は使わないでください。カスタム プロバイダー ID は `capriole_ai` のままにしてください。

### 設定の変更が反映されないのはなぜですか？

`~/.codex/config.toml` が有効なユーザー設定ファイルであることを確認し、プロジェクトスコープの `.codex/config.toml` に頼る前にプロジェクトを信頼してから、Codex を再起動してください。

## 注意事項

- この設定は `env_key` を使うため、API キーは設定ファイルではなくシェル環境に残ります。
- 公式リファレンス: [Codex CLI](https://developers.openai.com/codex/cli)、[Codex 設定の基本](https://developers.openai.com/codex/config-basic)、[Codex 設定リファレンス](https://developers.openai.com/codex/config-reference)、[設定サンプル](https://developers.openai.com/codex/config-sample)。
