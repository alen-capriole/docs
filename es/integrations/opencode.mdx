Con una sola clave API de Capriole AI, usas GPT-6 Astra, Claude Fable 5.1 y Opus 5.5 en OpenCode pagando hasta un 92% menos que los precios oficiales de la API.

## Qué es OpenCode

OpenCode es un agente de programación de IA de código abierto disponible como interfaz de terminal, app de escritorio y extensión de IDE. Esta configuración añade Capriole AI como un único proveedor personalizado. Cada uno de sus modelos usa el protocolo de API que Capriole AI sirve para esa familia de modelos.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://www.capriole.ai/es))
- Un plan Premium (USD 8 al mes, también incluye chat web ilimitado) o un plan Team, necesario para la clave API ([Suscríbete](https://www.capriole.ai/es?view=api))
- Una clave API de Capriole AI ([Obtén tu clave](https://www.capriole.ai/es?view=api))

## Instalación

OpenCode 2 y OpenCode 1 usan el mismo comando `opencode`, así que solo puedes tener uno instalado a la vez. Instala OpenCode 2 con el script de instalación oficial:

```bash
curl -fsSL https://opencode.ai/v2/install | bash
```

O instálalo con npm:

```bash
npm install -g @opencode/cli
```

Para pasar de OpenCode 1, ejecuta `opencode upgrade --major`. El script `https://opencode.ai/install` y el paquete npm `opencode-ai` siguen instalando OpenCode 1.

Verifica la instalación:

```bash
opencode --version
```

## Configuración

### Validación de modelos

OpenCode 2.2.5 supera una prueba de lectura de archivos y respuesta final a través de Capriole AI con todos los modelos de la sección Modelos compatibles, usando la configuración de OpenCode 2. OpenCode 1.19.3 supera una prueba de lectura de archivos, escritura de archivos y respuesta final con la configuración de OpenCode 1.

```json
  },
  "providers": {
    "capriole-ai": {
      "name": "Capriole AI",
      "env": ["CAPRIOLE_AI_API_KEY"],
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "https://api.caprioletech.com/v1"
      },
      "headers": {
        "Authorization": "Bearer {env:CAPRIOLE_AI_API_KEY}"
      },
      "models": {
        "openai-latest": {
          "name": "OpenAI latest",
          "package": "@opencode/ai/providers/openai-compatible/responses",

            "context": 1050000,

            "reasoningEffort": "medium"

```

Qué hace cada ajuste:

- `package: "@opencode/ai/providers/openai-compatible"` es el paquete por defecto del proveedor, así que Gemini, Grok, GLM y Kimi usan Chat Completions.
- Cada modelo GPT sustituye `package` por `@opencode/ai/providers/openai-compatible/responses`, que usa la API Responses. Cada modelo Claude lo sustituye por `@opencode/ai/providers/anthropic-compatible`, que usa Anthropic Messages.
- `env` indica la variable que guarda tu clave. La cabecera `Authorization` envía la clave como token Bearer con todos los paquetes. Sin ella, el paquete de Anthropic envía la clave en una cabecera `x-api-key`, que Capriole AI no acepta.
- `reasoningEffort` da a cada modelo GPT un nivel de razonamiento por defecto. Sin él, los modelos GPT responden sin razonar.
- `baseURL` incluye `/v1` para todos los paquetes. `limit` indica a OpenCode la ventana de contexto y el límite de salida de cada modelo.
- `agents.title` define el modelo que OpenCode usa para los títulos de sesión.

## Ejecutar OpenCode

Define tu clave API y luego inicia OpenCode desde el directorio de tu proyecto:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
opencode service restart
opencode
```

OpenCode 2 envía las solicitudes a los modelos desde un servicio en segundo plano que lee la clave al iniciarse, así que `opencode service restart` hace que tome la clave que acabas de definir. En OpenCode 1, omite este paso.

Usa `/models` para cambiar de modelo. Para una ejecución no interactiva, usa `opencode run`:

```bash
opencode run -m capriole-ai/claude-latest "Explain this repository."
```

## Modelos compatibles

Las referencias de modelo usan el formato `capriole-ai/<model-id>`.

| Modelo | ID de modelo | Protocolo |
| --- | --- | --- |
| OpenAI latest | `openai-latest` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | Chat Completions |
| Kimi K3.1 Pro | `moonshot/kimi-k3.1-pro` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | Chat Completions |

`openai-latest` y `claude-latest` siempre apuntan a nuestro modelo insignia más reciente de cada familia, actualmente GPT-6 Astra y Claude Fable 5.1.

## Solución de problemas

### ¿Por qué OpenCode devuelve un error de autenticación?

Confirma que `CAPRIOLE_AI_API_KEY` está exportada en el mismo shell antes de iniciar OpenCode y que la cabecera `Authorization` está presente en `headers` (OpenCode 2) u `options.headers` (OpenCode 1). Si OpenCode 2 devuelve `Missing Bearer token`, su servicio en segundo plano se inició sin la clave: ejecuta `opencode service restart` en ese shell.

### ¿Por qué las solicitudes de Claude fallan con `Unsupported Claude Messages model`?

Los modelos Claude que usan el paquete de Anthropic necesitan los IDs de Claude sin prefijo, como `claude-opus-5-5`. Los IDs con el prefijo `anthropic/` son para Chat Completions.

### ¿Por qué fallan las solicitudes de GPT?

Confirma que cada modelo GPT tiene `"package": "@opencode/ai/providers/openai-compatible/responses"` (OpenCode 2) o `"provider": { "npm": "@ai-sdk/openai" }` (OpenCode 1), para que sus solicitudes usen la API Responses.

### ¿Por qué no aparecen los modelos de Capriole AI?

Confirma que la referencia de modelo usa `capriole-ai/<model-id>`, como `capriole-ai/moonshot/kimi-k3`, y que `disabled_providers` no bloquea `capriole-ai`. OpenCode 1 ignora el formato `providers` de OpenCode 2.

### ¿Por qué no se aplican los cambios de configuración?

Comprueba si hay un `opencode.json` a nivel de proyecto o una anulación con `OPENCODE_CONFIG` y luego reinicia OpenCode.

### ¿Por qué aparecen errores de paquetes de proveedor?

Borra `~/.cache/opencode` y reinicia OpenCode para que reinstale los paquetes de proveedor.
