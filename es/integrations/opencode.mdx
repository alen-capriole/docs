## Qué es OpenCode

OpenCode es un agente de programación de IA de código abierto disponible como interfaz de terminal, app de escritorio y extensión de IDE. Con la configuración de proveedor, puede enviar solicitudes de modelo compatibles a través de los endpoints compatibles con OpenAI y Anthropic de Capriole AI.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://capriole.ai))
- Una clave API de Capriole AI ([Obtén tu clave](https://capriole.ai?view=api))

## Instalación

Instala OpenCode con el script oficial de instalación:

```bash
curl -fsSL https://opencode.ai/install | bash
```

O instálalo con npm:

```bash
npm install -g opencode-ai
```

Verifica la instalación:

```bash
opencode --version
```

## Ejecutar OpenCode

Después de reemplazar `YOUR_CAPRIOLE_AI_API_KEY` en la configuración, inicia OpenCode:

```bash
opencode
```

Usa `/models` para seleccionar OpenAI latest, GPT 5.6 Thinking, GPT 5.6, GPT 5.5, GPT 5.4 mini, Fable 5, Opus 5, Grok 4.5, GLM 5.2, Kimi K3, Claude latest, Opus 4.8, Opus 4.7, Opus 4.6 o Sonnet 4.6. Usa `Ctrl+T` para recorrer las variantes de modelo.

## Solución de problemas

### ¿Por qué OpenCode devuelve un error de autenticación?

Confirma que tanto `apiKey` como `authToken` en `~/.config/opencode/opencode.json` usan tu clave API de Capriole AI en lugar de `YOUR_CAPRIOLE_AI_API_KEY`.

### ¿Por qué fallan las solicitudes de GPT?

Confirma que el proveedor GPT usa `npm: "@ai-sdk/openai"` y `baseURL: "https://api.caprioletech.com/v1"` para que las solicitudes usen la API Responses.

### ¿Por qué fallan las solicitudes de Grok, GLM o Kimi?

Confirma que `capriole-ai-compatible` usa `npm: "@ai-sdk/openai-compatible"` y `baseURL: "https://api.caprioletech.com/v1"` para que ambos modelos usen Chat Completions.

### ¿Por qué fallan las solicitudes de Anthropic?

Confirma que el proveedor Anthropic usa `npm: "@ai-sdk/anthropic"`, `authToken` y `baseURL: "https://api.caprioletech.com/v1"`.

### ¿Por qué no aparecen los modelos de Capriole AI?

Confirma que la referencia del modelo usa `<providerId>/<modelId>`, como `capriole-ai-openai/openai-latest`, `capriole-ai-compatible/moonshot/kimi-k3` o `capriole-ai-anthropic/claude-latest`, y que `enabled_providers` incluye los proveedores de Capriole AI mientras que `disabled_providers` no los bloquea.

### ¿Por qué no aparecen las variantes de modelo?

Confirma que reiniciaste OpenCode después de actualizar `~/.config/opencode/opencode.json`, luego abre `/models` y pulsa `Ctrl+T` para recorrer las variantes.

### ¿Por qué no se aplican los cambios de configuración?

Revisa si hay anulaciones de `opencode.json` a nivel de proyecto o de `OPENCODE_CONFIG` y luego reinicia OpenCode.

### ¿Por qué aparecen errores de inicialización de proveedor o de paquetes de proveedor?

Para `ProviderInitError`, verifica primero la configuración del proveedor. Para errores de paquetes de proveedor, limpia `~/.cache/opencode` y reinicia OpenCode para que se reinstalen los paquetes de proveedor.

## Notas

- El proveedor Anthropic usa `authToken` para que el proveedor Anthropic del AI SDK envíe autenticación `Authorization: Bearer`.
- OpenCode 1.14.48 completa flujos de trabajo de herramientas de shell con Grok 4.5, GLM 5.2 y Kimi K3 a través de `@ai-sdk/openai-compatible`.
- Las variantes de OpenCode son ajustes de modelo del lado del cliente. No crean IDs de modelo nuevos de la API de Capriole AI.
