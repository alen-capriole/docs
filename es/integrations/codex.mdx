## Qué es Codex

Codex es el agente de programación de OpenAI para desarrollo de software. Puede usar Capriole AI mediante un proveedor de modelo personalizado configurado para enviar solicitudes a la API compatible con Responses de Capriole AI.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://capriole.ai))
- Una clave API de Capriole AI ([Obtén tu clave](https://capriole.ai?view=api))

## Instalación

### Codex CLI

Instala Codex CLI con el instalador oficial:

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

O instálalo con npm:

```bash
npm install -g @openai/codex
```

Verifica la instalación:

```bash
codex --version
```

### App de Codex

Descarga la app desde [OpenAI Codex](https://developers.openai.com/codex).

## Configuración

### Validación de modelos

Codex CLI 0.160.1 supera una prueba de lectura de archivos, escritura de archivos y respuesta final a través de Capriole AI con la configuración siguiente.

Crea o actualiza `~/.codex/config.toml`:

```toml
model = "gpt-6-astra"
model_reasoning_effort = "high"
model_provider = "capriole_ai"

[model_providers.capriole_ai]
name = "Capriole AI"
base_url = "https://api.caprioletech.com/v1"
wire_api = "responses"
env_key = "CAPRIOLE_AI_API_KEY"
env_key_instructions = "Export CAPRIOLE_AI_API_KEY before starting Codex"
```

Qué hace cada ajuste:

- `model` es el modelo por defecto. Cámbialo con `/model` dentro de una sesión o con `--model` en la línea de comandos.
- `model_provider` selecciona el proveedor de Capriole AI definido debajo.
- `base_url` incluye `/v1`, porque Codex añade `/responses` por su cuenta.
- `wire_api = "responses"` usa la API Responses, el único protocolo que Codex admite para proveedores personalizados.
- `env_key` lee tu clave del entorno y la envía como token Bearer.

## Ejecutar Codex

Define tu clave API y luego inicia Codex desde el directorio de tu proyecto:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
codex
```

Para una ejecución no interactiva, usa `codex exec`:

```bash
codex exec "Explain this repository."
```

## Modelos compatibles

Codex usa los modelos OpenAI de Capriole AI a través de la API Responses. Usa los IDs de modelo nativos de abajo con el selector de modelos y los ajustes de razonamiento integrados de Codex. No necesitas un `model_catalog_json` personalizado. Solo puedes invocar modelos compatibles con Capriole AI.

- `gpt-6-astra`
- `gpt-6.1-sol`
- `gpt-6-sol`
- `gpt-6-luna`
- `gpt-5.6-terra`
- `gpt-5.6-luna`
- `gpt-5.5`

Usa Codex 0.159.2 o posterior para `gpt-6.1-sol`. Las versiones anteriores no incluyen sus metadatos de modelo y recurren a una configuración genérica.

La API también acepta las formas con el prefijo `openai/` y `openai-latest`. El alias `openai-latest` sigue el modelo insignia de OpenAI recomendado por Capriole AI.

Codex también puede ejecutar `xai/grok-4.7` a través del mismo proveedor, porque Capriole AI sirve Grok en la API Responses.

Codex solo incluye metadatos integrados para los IDs de modelo nativos de OpenAI. Con `openai-latest` y `xai/grok-4.7`, muestra `Model metadata ... not found` y usa una configuración de respaldo. La sesión sigue funcionando, pero usa un ID nativo como `gpt-6-astra` para obtener los mejores resultados.

## Solución de problemas

### ¿Por qué Codex devuelve un error de autenticación?

Confirma que `CAPRIOLE_AI_API_KEY` está exportada en el mismo shell antes de ejecutar `codex`.

### ¿Por qué Codex no encuentra el modelo?

Confirma que `model_provider = "capriole_ai"` está definido y que `model` es uno de los IDs de la sección Modelos compatibles.

### ¿Por qué las solicitudes fallan con errores de endpoint o de protocolo?

Confirma que `base_url = "https://api.caprioletech.com/v1"` y `wire_api = "responses"` están definidos bajo `[model_providers.capriole_ai]`.

### ¿Por qué Codex ignora el proveedor de Capriole AI?

No uses un ID de proveedor integrado reservado como `openai`; mantén el ID de proveedor personalizado como `capriole_ai`.

### ¿Por qué no se aplican los cambios de configuración?

Confirma que `~/.codex/config.toml` es el archivo de configuración de usuario activo, confía en el proyecto antes de depender de un `.codex/config.toml` a nivel de proyecto y luego reinicia Codex.

## Notas

- La configuración usa `env_key` para que tu clave API permanezca en el entorno del shell en lugar del archivo de configuración.
