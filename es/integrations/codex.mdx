## Qué es Codex

Codex es el agente de programación de OpenAI para desarrollo de software. Puede usar Capriole AI mediante un proveedor de modelo personalizado configurado para enviar solicitudes a la API compatible con Responses de Capriole AI.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://capriole.ai))
- Una clave API de Capriole AI ([Obtén tu clave](https://capriole.ai?view=api))

## Instalación

### Codex CLI

```bash
npm install -g @openai/codex
```

### Codex app

Descarga la app desde [OpenAI Codex](https://developers.openai.com/codex).

## Configuración

Crea o actualiza `~/.codex/config.toml`:

```toml
model = "openai-latest"
model_reasoning_effort = "high"
model_provider = "capriole_ai"

[model_providers.capriole_ai]
name = "Capriole AI"
base_url = "https://api.caprioletech.com/v1"
wire_api = "responses"
env_key = "CAPRIOLE_AI_API_KEY"
env_key_instructions = "Export CAPRIOLE_AI_API_KEY before starting Codex"
```

## Ejecutar Codex

Define tu clave API y luego inicia Codex:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
codex
```

## Modelos compatibles

Codex admite los modelos OpenAI de Capriole AI a través de la API Responses. Usa `openai-latest` en las configuraciones nuevas para que Capriole AI enrute Codex a nuestro modelo insignia recomendado de OpenAI sin cambiar tu config.

- `openai-latest`
- `openai/gpt-5.6-terra`
- `openai/gpt-5.6-luna`
- `openai/gpt-5.5`
- `openai/gpt-5.4-mini`

## Solución de problemas

### ¿Por qué Codex devuelve un error de autenticación?

Confirma que `CAPRIOLE_AI_API_KEY` está exportada en el mismo shell antes de ejecutar `codex`.

### ¿Por qué Codex no encuentra el modelo?

Confirma que `model_provider = "capriole_ai"` está definido y que `model` es `openai-latest` o un ID de modelo OpenAI compatible de Capriole AI.

### ¿Por qué las solicitudes fallan con errores de endpoint o de protocolo?

Confirma que `base_url = "https://api.caprioletech.com/v1"` y `wire_api = "responses"` están definidos bajo `[model_providers.capriole_ai]`.

### ¿Por qué Codex ignora el proveedor de Capriole AI?

No uses un ID de proveedor integrado reservado como `openai`; mantén el ID de proveedor personalizado como `capriole_ai`.

### ¿Por qué no se aplican los cambios de configuración?

Confirma que `~/.codex/config.toml` es el archivo de configuración de usuario activo, confía en el proyecto antes de depender de un `.codex/config.toml` a nivel de proyecto y luego reinicia Codex.

## Notas

- La configuración usa `env_key` para que tu clave API permanezca en el entorno del shell en lugar del archivo de configuración.
