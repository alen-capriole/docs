## Qué es GitHub Copilot CLI

GitHub Copilot CLI es un asistente de programación nativo de terminal. Su modo de proveedor BYOK puede usar un endpoint compatible con OpenAI Chat Completions, lo que le permite enviar solicitudes de modelo a Capriole AI.

Esta es una configuración directa de proveedor de modelo para Copilot CLI. Es independiente de Microsoft 365 Copilot.

Esta página documenta valores BYOK compatibles con el endpoint de Capriole AI. Valida tu Copilot CLI instalado con un prompt streaming y una solicitud de herramienta local antes de usar estos valores en flujos de trabajo de agente de programación en producción.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://capriole.ai))
- Una clave API de Capriole AI ([Obtén tu clave](https://capriole.ai?view=api))
- GitHub Copilot CLI instalado

## Instalación

Instala GitHub Copilot CLI con npm:

```bash
npm install -g @github/copilot
```

Verifica la instalación:

```bash
copilot --version
```

La autenticación de GitHub no es necesaria cuando `COPILOT_PROVIDER_BASE_URL` está definida para el modo BYOK.

## Configuración

### Validación de modelos

GitHub Copilot CLI 1.0.82: `anthropic/claude-fable-5-1`, `google/gemini-3.8-flash` y `zai/glm-5.3-flash` superan las pruebas locales de lectura de archivos y respuesta final. `claude-latest` se resuelve a Fable 5.1. Los IDs concretos anteriores siguen disponibles.

Las pruebas nuevas de Chat Completions usan `COPILOT_PROVIDER_MODEL_ID="gpt-5.4"`; Fable 5.1 también supera las pruebas mediante Anthropic Messages con `claude-latest`.

`xai/grok-4.6` acepta solicitudes de Chat Completions, pero no superó las pruebas de tareas de agentes, por lo que no se incluye en la configuración siguiente. Las pruebas directas al proveedor también detectaron un uso de herramientas inconsistente con Grok 4.5; completar una solicitud API no demuestra que la respuesta del agente sea correcta.

Define Capriole AI como el proveedor de modelo compatible con OpenAI:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
```

Elige OpenAI latest en Chat Completions:

```bash
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

O elige GPT 5.4 Mini en Chat Completions:

```bash
export COPILOT_PROVIDER_MODEL_ID="gpt-5.4"
export COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-5.4-mini"
```

`COPILOT_PROVIDER_MODEL_ID` es el identificador del modelo en el cliente; `COPILOT_PROVIDER_WIRE_MODEL` es el ID enviado a Capriole AI. Para GPT-6 Astra, usa `gpt-6-astra` con `openai-latest`. Copilot CLI 1.0.82 acepta este ID personalizado, pero no incluye un perfil de Astra: usa la configuración y los límites de tokens predeterminados, salvo que los sobrescribas. Consulta `copilot help providers`.

En las pruebas locales con este ID de Astra, Chat Completions completa la lectura de archivos. Responses devuelve el contenido correcto con una ruta absoluta, pero también reproduce errores al resolver rutas relativas y esperas largas. Cambiar el ID no corrige esos problemas de ejecución; valida tu flujo antes de usarlo en producción.

## Configuración persistente

GitHub Copilot CLI guarda los ajustes generales de la CLI en su propia configuración, pero los ajustes del proveedor BYOK son variables de entorno. Para una configuración persistente simple, pon un perfil de Capriole AI en la configuración de tu shell.

Añade este perfil de OpenAI latest Responses compatible con el endpoint a `~/.zshrc` y luego valídalo con tu Copilot CLI instalado antes de usarlo en flujos de trabajo de agente de programación:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
alias capriole-copilot="copilot --stream on"
```

Recarga tu shell:

```bash
source ~/.zshrc
```

Luego ejecuta:

```bash
capriole-copilot
```

Para un prompt de una sola vez:

```bash
capriole-copilot -p "Explain this repository structure." --allow-all-tools
```

Para cambiar de perfil, cambia solo `COPILOT_PROVIDER_WIRE_API`, `COPILOT_PROVIDER_MODEL_ID`, `COPILOT_PROVIDER_WIRE_MODEL` y, para Claude Messages, usa `COPILOT_PROVIDER_TYPE`, `COPILOT_PROVIDER_BASE_URL` y `COPILOT_PROVIDER_BEARER_TOKEN`.

## Ejecutar GitHub Copilot CLI

Inicia una sesión interactiva:

```bash
copilot --stream on
```

Ejecuta una solicitud de una sola vez:

```bash
copilot -p "Explain this repository structure." --allow-all-tools --stream on
```

Para uso con scripts, mantén el streaming habilitado. Los endpoints coincidentes de Capriole AI admiten streaming; valida la ruta de Copilot CLI instalada antes del despliegue en producción.

## Solución de problemas

### ¿Por qué Copilot CLI devuelve un error de autenticación?

Confirma que `CAPRIOLE_AI_API_KEY` está exportada y que `COPILOT_PROVIDER_API_KEY` apunta a ella en el mismo shell antes de iniciar Copilot CLI.

### ¿Por qué las solicitudes fallan con errores de endpoint?

Para Chat Completions o Responses compatibles con OpenAI, confirma que `COPILOT_PROVIDER_BASE_URL` es `https://api.caprioletech.com/v1`.

Para Anthropic Messages, confirma que `COPILOT_PROVIDER_BASE_URL` es `https://api.caprioletech.com` sin `/v1`.

### ¿Por qué Copilot CLI dice que falta el modelo?

Define tanto `COPILOT_PROVIDER_MODEL_ID` como `COPILOT_PROVIDER_WIRE_MODEL`. Para GPT-6 Astra, usa `gpt-6-astra` y `openai-latest`, respectivamente.

### ¿Por qué debe permanecer habilitado el streaming?

Los requisitos BYOK de GitHub indican que los modelos deben admitir streaming y llamadas a herramientas/funciones. Mantén Copilot CLI en la ruta de streaming para poder validar las llamadas a herramientas locales contra Capriole AI antes del despliegue.

## Notas

- Capriole AI expone ejemplos BYOK de Copilot CLI a través de las formas de perfil de Chat Completions, Responses y Anthropic Messages.
- El perfil de Chat Completions usa `POST /v1/chat/completions`, el perfil de Responses usa `POST /v1/responses` y el perfil de Anthropic usa `POST /v1/messages`.
- GitHub Copilot CLI ejecuta las herramientas de programación en local. Capriole AI solo gestiona las solicitudes de modelo.
- GitHub Copilot CLI no tiene una API de transmisión para la ruta nativa `POST /v1/chat` de Capriole AI.
- Referencias oficiales: [GitHub Copilot CLI installation](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli), [GitHub Copilot CLI BYOK](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models) y [GitHub Copilot SDK BYOK](https://docs.github.com/en/copilot/how-tos/copilot-sdk/auth/byok).
