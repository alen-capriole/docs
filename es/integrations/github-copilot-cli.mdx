## Qué es GitHub Copilot CLI

GitHub Copilot CLI es el agente de programación de GitHub para la terminal. Su modo bring-your-own-key (BYOK) envía las solicitudes de modelo a un proveedor que defines con variables de entorno. Esta configuración lo dirige a Capriole AI.

## Requisitos previos

Antes de empezar, asegúrate de tener:

- Una cuenta de Capriole AI ([Regístrate aquí](https://capriole.ai))
- Una clave API de Capriole AI ([Obtén tu clave](https://capriole.ai?view=api))

## Instalación

Instala GitHub Copilot CLI con npm:

```bash
npm install -g @github/copilot
```

Verifica la instalación:

```bash
copilot --version
```

No necesitas iniciar sesión en GitHub cuando `COPILOT_PROVIDER_BASE_URL` está definida.

## Configuración

### Validación de modelos

GitHub Copilot CLI 1.0.100 supera una prueba de lectura de archivos, escritura de archivos y respuesta final a través de Capriole AI con todos los modelos de la sección Modelos compatibles, usando los perfiles siguientes.

Copilot CLI usa un solo proveedor a la vez, así que elige el perfil de la familia de modelos que quieras. Cada perfil define dos valores de modelo:

- `COPILOT_PROVIDER_WIRE_MODEL` es el ID de modelo de Capriole AI que Copilot envía.
- `COPILOT_PROVIDER_MODEL_ID` es un modelo que Copilot conoce. Copilot lo usa para elegir sus herramientas, prompts y límites de tokens.

### Modelos GPT

Los modelos GPT usan la API Responses:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

Para GPT-6.1 Sol, define `COPILOT_PROVIDER_MODEL_ID="gpt-6.1-sol"` y `COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-6.1-sol"`.

### Modelos Claude

Los modelos Claude usan Anthropic Messages:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="anthropic"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com"
export COPILOT_PROVIDER_BEARER_TOKEN="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"
export COPILOT_PROVIDER_WIRE_MODEL="claude-latest"
```

Para Opus 5.5, define `COPILOT_PROVIDER_WIRE_MODEL="claude-opus-5-5"`.

- `COPILOT_PROVIDER_BEARER_TOKEN` envía la clave como token Bearer. `COPILOT_PROVIDER_API_KEY` la enviaría en una cabecera `x-api-key`, que Capriole AI no acepta.
- La URL base no lleva `/v1`, porque Copilot añade `/v1/messages` por su cuenta.
- Mantén `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`. Con un perfil más antiguo como `claude-sonnet-4`, Copilot envía un presupuesto de thinking y Opus 5.5 lo rechaza con `requires adaptive thinking`.

### Modelos Gemini, Grok, GLM y Kimi

Estos modelos usan Chat Completions:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
export COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"
export COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3"
```

Para los demás modelos, cambia `COPILOT_PROVIDER_WIRE_MODEL` a `google/gemini-3.8-flash`, `xai/grok-4.7` o `zai/glm-5.3-flash`.

Mantén `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`. Con un perfil GPT como `gpt-5.4`, Copilot envía tipos de herramienta que estos modelos rechazan.

Para Kimi K3.1 Pro, define `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"` y `COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3.1-pro"`. El perfil `claude-sonnet-4` envía `temperature: 0`, que Kimi K3.1 Pro rechaza.

Para conservar un perfil, añade sus líneas a `~/.zshrc` o `~/.bashrc` y luego abre una terminal nueva.

## Ejecutar GitHub Copilot CLI

Inicia Copilot CLI desde el directorio de tu proyecto:

```bash
copilot
```

Para una ejecución no interactiva, pasa un prompt con `-p`:

```bash
copilot -p "Explain this repository." --allow-all-tools
```

## Modelos compatibles

| Modelo | `COPILOT_PROVIDER_WIRE_MODEL` | `COPILOT_PROVIDER_MODEL_ID` | Protocolo |
| --- | --- | --- | --- |
| OpenAI latest | `openai-latest` | `gpt-6-astra` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | `gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | `claude-opus-4.6` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | `claude-opus-4.6` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | `claude-sonnet-4` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | `claude-sonnet-4` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | `claude-sonnet-4` | Chat Completions |
| Kimi K3.1 Pro | `moonshot/kimi-k3.1-pro` | `claude-opus-4.6` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | `claude-sonnet-4` | Chat Completions |

`openai-latest` y `claude-latest` siempre apuntan a nuestro modelo insignia más reciente de cada familia.

## Solución de problemas

### ¿Por qué Copilot CLI devuelve un error de autenticación?

Confirma que `CAPRIOLE_AI_API_KEY` está exportada en el mismo shell. Para los modelos Claude, usa `COPILOT_PROVIDER_BEARER_TOKEN`, no `COPILOT_PROVIDER_API_KEY`.

### ¿Por qué las solicitudes fallan con errores de endpoint?

Para los modelos GPT, Gemini, Grok, GLM y Kimi, `COPILOT_PROVIDER_BASE_URL` es `https://api.caprioletech.com/v1`. Para los modelos Claude, es `https://api.caprioletech.com` sin `/v1`.

### ¿Por qué Opus 5.5 falla con `requires adaptive thinking`?

Define `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`.

### ¿Por qué las solicitudes de Gemini, Grok, GLM o Kimi fallan con un error de herramientas?

Define `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`, o `"claude-opus-4.6"` para Kimi K3.1 Pro. Un perfil GPT envía tipos de herramienta que solo aceptan los modelos de OpenAI.

## Notas

- Copilot CLI ejecuta las herramientas de programación en tu equipo. Capriole AI solo gestiona las solicitudes de modelo.
- Ejecuta `copilot help providers` para ver todas las variables de entorno de BYOK.
- Referencias oficiales: [Instalar GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli) y [Usar modelos BYOK en Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models).
