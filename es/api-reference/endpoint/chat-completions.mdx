title: "Chat completions"
description: "Crea Chat Completions compatibles con OpenAI con modelos de Capriole AI."

---

Usa este endpoint cuando tu aplicación, SDK o gateway espere el formato de solicitud y respuesta de OpenAI Chat Completions.

Envía un payload estándar de Chat Completions con `model` y `messages`. Capriole AI resuelve los alias latest al ID de modelo del proveedor seleccionado antes del envío a upstream, reenvía campos compatibles como `messages`, `tools`, `tool_choice`, `response_format` y `stream`, y devuelve el JSON o el flujo SSE de upstream sin cambios, salvo la corrección de SSE para GLM y los comentarios de heartbeat que se describen abajo. En solicitudes streaming, Capriole AI establece `stream_options.include_usage=true` antes de reenviar para poder registrar el uso.

En algunas respuestas SSE con `model="zai/glm-5.3-flash"`, Capriole AI elimina únicamente el campo heredado vacío `function_call={"name":"","arguments":""}` de los deltas. Las llamadas reales o parciales, `tool_calls`, el texto y el uso se conservan. Esta excepción no afecta a respuestas sin streaming ni a otros modelos.

`POST /v1/chat/completions` acepta `openai-latest`, `claude-latest`, `google-latest` y los IDs de modelo concretos públicos que devuelve `GET /v1/models`. Usa un alias latest para que Capriole AI elija nuestro modelo insignia recomendado para ese proveedor.

Los alias latest son atajos de entrada. El uso se registra contra el modelo resuelto, mientras que el cuerpo de la respuesta conserva el comportamiento de nombres de modelo del endpoint compatible seleccionado.

## Kimi K3.1 Pro

Kimi K3.1 Pro fija `temperature` en 1 y `top_p` en 0.95. Omite `temperature`, `top_p`, `n`, `presence_penalty` y `frequency_penalty` con este modelo, y envía las instrucciones con el rol `system` en lugar de `developer`.

## Gemini 4 Carbon

`google-latest` se resuelve a `google/gemini-4-carbon`. Este endpoint reenvía el resto de tu solicitud sin cambios, así que Gemini 4 Carbon razona con el nivel predeterminado de Google, `medium`, que en nuestra prueba usó entre 3 y 4 veces los tokens de salida de Gemini 4 Argon con el mismo prompt. El `reasoning_effort` de OpenAI no cambia el nivel de razonamiento de Carbon. Para definirlo, envía el campo de Google con `low`, `medium` o `high`:

```json
"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}
```

Con el SDK de OpenAI para Python, pasa `extra_body={"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}}`. Google advierte que los prompts difíciles en Carbon pueden tardar varios minutos, así que transmítelos en streaming como se describe en [Tareas largas](#tareas-largas); para esperar menos, establece `thinking_level` en `low` o usa `google/gemini-4-argon`.

## Gemini 4 Neon

Usa `google/gemini-4-neon` para seleccionar Neon. Google documenta una ventana de 1.048.576 tokens compartida entre entrada y salida, un límite de salida síncrona predeterminado de 65.536 tokens y compatibilidad con JSON Schema. Los niveles de razonamiento son `low`, `medium`, `high` (predeterminado) y `xhigh`. Consulta la [documentación del modelo de Google](https://aistudio.google.com/docs/models/gemini-4-neon).

## Búsqueda web

Este endpoint no ofrece búsqueda web. Para los modelos Grok, una solicitud con un campo `web_search_options` o `search_parameters` distinto de null falla con HTTP 400:

```json
{
  "detail": "Web search is not supported for xai/grok-4.7 on /v1/chat/completions. Use POST /v1/responses with tools: [{\"type\": \"web_search\"}]."
}
```

Las herramientas de función que define tu cliente, incluso una llamada `web_search`, se reenvían sin cambios. Para buscar en la web con GPT o Grok, usa [`POST /v1/responses`](/es/api-reference/endpoint/responses) con `"tools": [{"type": "web_search"}]`.

## Tareas largas

Para tareas largas, como razonamiento extenso, establece `"stream": true`. Sin streaming, la conexión puede agotar el tiempo de espera después de unos 2 minutos. Mientras una solicitud con streaming espera al modelo, Capriole AI envía un comentario SSE `: heartbeat` cada 15 segundos, y las solicitudes `google/*` con streaming pueden esperar hasta 20 minutos el primer token. Si el modelo no ha respondido en 60 segundos, la respuesta 200 ya ha comenzado, así que un error de upstream posterior llega como un último evento SSE con un objeto `error`.
