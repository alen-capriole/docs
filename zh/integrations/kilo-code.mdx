## Kilo Code 是什么

Kilo Code 是适用于 VS Code 和终端的 AI 编程代理。这套配置把 Capriole AI 添加为一个自定义提供商，其中每个模型都使用 Capriole AI 为该模型系列提供的 API 协议。

## 前置条件

开始前请确保你已经拥有以下内容。

- Capriole AI 账户，可在[此处注册](https://capriole.ai)
- Capriole AI API Key，可在[此处获取](https://capriole.ai?view=api)

## 安装

### Kilo CLI

```bash
npm install -g @kilocode/cli
```

验证安装。

```bash
kilo --version
```

### VS Code 扩展

在 VS Code 的扩展视图中安装 Kilo Code。该扩展与 CLI 读取同一个全局配置文件。

各项设置的作用如下。

- `npm: "@ai-sdk/openai-compatible"` 是该提供商的默认包，因此 Gemini、Grok、GLM 和 Kimi 使用 Chat Completions。
- 每个 GPT 模型都用 `@ai-sdk/openai` 覆盖 `provider.npm`，从而使用 Responses API。每个 Claude 模型都用 `@ai-sdk/anthropic` 覆盖它，从而使用 Anthropic Messages。
- `{env:CAPRIOLE_AI_API_KEY}` 从环境变量读取你的 API Key。`Authorization` 请求头让每个包都以 Bearer Token 形式发送 Key。没有它时，Anthropic 包会在 `x-api-key` 请求头中发送 Key，而 Capriole AI 不接受这种方式。
- `tool_call: true` 允许模型调用 Kilo 的工具。
- `limit` 设置每个模型的上下文窗口和输出上限。没有它时，Kilo 会把两者都视为 `0`，不会压缩长会话。

请把这个提供商保存在全局配置中。Kilo 不会解析项目级配置中的 `{env:...}` 引用。

编辑文件后运行 `kilo config check`。

## 运行 Kilo Code

设置 API Key，然后在项目目录中启动 Kilo。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
kilo
```

指定模型启动。

```bash
kilo -m capriole-ai/openai-latest
```

如需执行一次性请求，请把提示词传给 `kilo run`。

```bash
kilo run -m capriole-ai/claude-latest "Explain this repository."
```

## 支持的模型

模型引用格式为 `capriole-ai/<model-id>`。

| 模型 | 模型 ID | 协议 |
| --- | --- | --- |
| OpenAI latest | `openai-latest` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | Chat Completions |
| Kimi K3.1 Pro | `moonshot/kimi-k3.1-pro` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | Chat Completions |

`openai-latest` 和 `claude-latest` 始终指向各自系列中我们最新的旗舰模型。

## 故障排除

### 为什么 Kilo Code 返回身份验证错误

运行 `kilo` 前，确认已在同一个 Shell 中导出 `CAPRIOLE_AI_API_KEY`，并确认提供商位于 `~/.config/kilo/kilo.jsonc` 中，而不是项目配置中。

### 为什么 Claude 请求因 `Unsupported Claude Messages model` 失败

使用 `@ai-sdk/anthropic` 的 Claude 模型需要不带前缀的 Claude ID，例如 `claude-opus-5-5`。带 `anthropic/` 前缀的 ID 用于 Chat Completions。

### 为什么 Kilo Code 提示缺少模型

确认所选模型使用 `capriole-ai/<model-id>` 格式，并确认 `provider.capriole-ai.models` 中有对应条目。运行 `kilo models capriole-ai` 可以列出 Kilo 已加载的模型。

### 为什么工具调用失败

确认模型条目包含 `"tool_call": true`。

## 说明

- Kilo Code 在你的电脑上运行编程工具。Capriole AI 只处理模型请求。
- 如需添加其他 Capriole AI 模型，请复制同一系列中某个模型的条目并修改 ID。`GET https://api.caprioletech.com/v1/models` 会列出所有模型 ID。
- 官方参考资料包括 [Kilo CLI](https://kilo.ai/docs/cli)、[Kilo 自定义模型](https://kilo.ai/docs/code-with-ai/agents/custom-models)、[Kilo 设置](https://kilo.ai/docs/getting-started/settings)和 [OpenCode 提供商](https://opencode.ai/docs/providers)。
