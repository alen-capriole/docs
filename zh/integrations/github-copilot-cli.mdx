## GitHub Copilot CLI 是什么

GitHub Copilot CLI 是 GitHub 面向终端的编程代理。它的自带密钥（BYOK）模式会把模型请求发送到你通过环境变量设置的提供商。这套配置让它使用 Capriole AI。

## 前置条件

开始前请确保你已经拥有以下内容。

- Capriole AI 账户，可在[此处注册](https://capriole.ai)
- Capriole AI API Key，可在[此处获取](https://capriole.ai?view=api)

## 安装

使用 npm 安装 GitHub Copilot CLI。

```bash
npm install -g @github/copilot
```

验证安装。

```bash
copilot --version
```

设置 `COPILOT_PROVIDER_BASE_URL` 后，无需登录 GitHub。

## 配置

### 模型验证

使用下方各配置方案，GitHub Copilot CLI 1.0.100 经 Capriole AI 调用“支持的模型”一节中的每个模型，都通过了文件读取、文件写入和最终答案检查。

Copilot CLI 一次只使用一个提供商，因此请选择所需模型系列对应的配置方案。每个配置方案都会设置两个模型值。

- `COPILOT_PROVIDER_WIRE_MODEL` 是 Copilot 发送的 Capriole AI 模型 ID。
- `COPILOT_PROVIDER_MODEL_ID` 是 Copilot 认识的模型。Copilot 根据它选择工具、提示词和 Token 上限。

### GPT 模型

GPT 模型使用 Responses API。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

如需使用 GPT-6.1 Sol，请设置 `COPILOT_PROVIDER_MODEL_ID="gpt-6.1-sol"` 和 `COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-6.1-sol"`。

### Claude 模型

Claude 模型使用 Anthropic Messages。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="anthropic"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com"
export COPILOT_PROVIDER_BEARER_TOKEN="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"
export COPILOT_PROVIDER_WIRE_MODEL="claude-latest"
```

如需使用 Opus 5.5，请设置 `COPILOT_PROVIDER_WIRE_MODEL="claude-opus-5-5"`。

- `COPILOT_PROVIDER_BEARER_TOKEN` 以 Bearer Token 形式发送 Key。`COPILOT_PROVIDER_API_KEY` 会在 `x-api-key` 请求头中发送 Key，而 Capriole AI 不接受这种方式。
- Base URL 不含 `/v1`，因为 Copilot 会自行添加 `/v1/messages`。
- 保持 `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`。如果使用 `claude-sonnet-4` 等较旧的模型配置，Copilot 会发送思考预算，Opus 5.5 会以 `requires adaptive thinking` 拒绝请求。

### Gemini、Grok、GLM 和 Kimi 模型

这些模型使用 Chat Completions。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
export COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"
export COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3"
```

如需使用其他模型，请把 `COPILOT_PROVIDER_WIRE_MODEL` 改为 `google/gemini-3.8-flash`、`xai/grok-4.7` 或 `zai/glm-5.3-flash`。

保持 `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`。如果使用 `gpt-5.4` 等 GPT 模型配置，Copilot 会发送这些模型不接受的工具类型。

如需长期保留某个配置方案，请把它的各行添加到 `~/.zshrc` 或 `~/.bashrc`，然后打开新的终端。

## 运行 GitHub Copilot CLI

在项目目录中启动 Copilot CLI。

```bash
copilot
```

如需非交互式运行，请通过 `-p` 传入提示词。

```bash
copilot -p "Explain this repository." --allow-all-tools
```

## 支持的模型

| 模型 | `COPILOT_PROVIDER_WIRE_MODEL` | `COPILOT_PROVIDER_MODEL_ID` | 协议 |
| --- | --- | --- | --- |
| OpenAI latest | `openai-latest` | `gpt-6-astra` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | `gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | `claude-opus-4.6` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | `claude-opus-4.6` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | `claude-sonnet-4` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | `claude-sonnet-4` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | `claude-sonnet-4` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | `claude-sonnet-4` | Chat Completions |

`openai-latest` 和 `claude-latest` 始终指向各自系列中我们最新的旗舰模型。

## 故障排除

### 为什么 Copilot CLI 返回身份验证错误

确认已在同一个 Shell 中导出 `CAPRIOLE_AI_API_KEY`。对于 Claude 模型，请使用 `COPILOT_PROVIDER_BEARER_TOKEN`，不要使用 `COPILOT_PROVIDER_API_KEY`。

### 为什么请求出现端点错误

对于 GPT、Gemini、Grok、GLM 和 Kimi 模型，`COPILOT_PROVIDER_BASE_URL` 是 `https://api.caprioletech.com/v1`。对于 Claude 模型，它是不含 `/v1` 的 `https://api.caprioletech.com`。

### 为什么 Opus 5.5 因 `requires adaptive thinking` 失败

设置 `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`。

### 为什么 Gemini、Grok、GLM 或 Kimi 请求出现工具错误

设置 `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`。GPT 模型配置会发送只有 OpenAI 模型才接受的工具类型。

## 说明

- Copilot CLI 在你的电脑上运行编程工具。Capriole AI 只处理模型请求。
- 运行 `copilot help providers` 可以查看所有 BYOK 环境变量。
- 官方参考资料包括[安装 GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli)和[在 Copilot CLI 中使用 BYOK 模型](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models)。
