只需一个 Capriole AI API Key，就能在 OpenClaw 中使用 GPT-6 Astra、Claude Fable 5.1 和 Opus 5.5，价格比官方 API 最多低 92%。

## OpenClaw 是什么

OpenClaw 是开源、自托管的个人 AI 助手和 Gateway，可以把 WhatsApp、Slack、Discord、Telegram、iMessage 和 WebChat 等聊天渠道连接到 AI 智能体。这套配置把 Capriole AI 添加为三个自定义模型提供商，分别对应 Capriole AI 提供的每种 API 协议。

## 前置条件

开始前请确保你已经拥有以下内容。

- Capriole AI 账户，可在[此处注册](https://www.capriole.ai/zh)
- Premium 套餐（每月 USD 8，还包含无限网页聊天）或 Team 套餐，API Key 需要其中之一，可在[此处订阅](https://www.capriole.ai/zh?view=api)
- Capriole AI API Key，可在[此处获取](https://www.capriole.ai/zh?view=api)

## 安装

使用官方安装脚本安装 OpenClaw。

```bash
curl -fsSL https://openclaw.ai/install.sh | bash
```

然后完成 OpenClaw 自身的设置。

```bash
openclaw onboard
```

各项设置的作用如下。

- `capriole-ai-openai` 把 GPT 模型请求发送到 Responses API。`capriole-ai-anthropic` 把 Claude 模型请求发送到 Anthropic Messages。`capriole-ai-compatible` 把 Gemini、Grok、GLM 和 Kimi 模型请求发送到 Chat Completions。
- `${CAPRIOLE_AI_API_KEY}` 从环境变量读取你的 API Key。
- `request.auth` 使用 `authorization-bearer` 时，Anthropic 提供商会以 Bearer Token 形式发送 Key。没有它时，Key 会放在 `x-api-key` 请求头中，而 Capriole AI 不接受这种方式。
- Anthropic 的 `baseUrl` 不含 `/v1`，因为 OpenClaw 会自行添加 `/v1/messages`。
- Opus 5.5 的 `reasoning` 为 `false`。设为 `true` 时，OpenClaw 会发送思考预算，Opus 5.5 会以 `requires adaptive thinking` 拒绝请求。
- `contextWindow` 和 `maxTokens` 告诉 OpenClaw 每个模型的限制。
- `agents.defaults.models` 是智能体可以使用的模型列表。`agents.defaults.model.primary` 是默认模型。

## 运行 OpenClaw

在每个用来启动 OpenClaw 的终端中导出 API Key。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
```

启动 Gateway。

```bash
openclaw gateway
```

在另一个终端中打开终端界面。

```bash
openclaw tui
```

如需不经过 Gateway、在本地执行一次性运行，请使用以下命令。

```bash
openclaw agent --local --session-id capriole-test --message "Summarize the files in my workspace."
```

## 支持的模型

模型引用格式为 `<provider-id>/<model-id>`。

| 模型 | 模型引用 | 协议 |
| --- | --- | --- |
| OpenAI latest | `capriole-ai-openai/openai-latest` | Responses |
| GPT-6.1 Sol | `capriole-ai-openai/openai/gpt-6.1-sol` | Responses |
| Claude latest | `capriole-ai-anthropic/claude-latest` | Anthropic Messages |
| Opus 5.5 | `capriole-ai-anthropic/claude-opus-5-5` | Anthropic Messages |
| Gemini 3.8 Flash | `capriole-ai-compatible/google/gemini-3.8-flash` | Chat Completions |
| Grok 4.7 | `capriole-ai-compatible/xai/grok-4.7` | Chat Completions |
| GLM 5.3 Flash | `capriole-ai-compatible/zai/glm-5.3-flash` | Chat Completions |
| Kimi K3.1 Pro | `capriole-ai-compatible/moonshot/kimi-k3.1-pro` | Chat Completions |
| Kimi K3 | `capriole-ai-compatible/moonshot/kimi-k3` | Chat Completions |

`openai-latest` 和 `claude-latest` 始终指向各自系列中我们最新的旗舰模型，目前分别是 GPT-6 Astra 和 Claude Fable 5.1。

## 故障排除

### 为什么身份验证失败

在启动 `openclaw gateway` 或 `openclaw agent` 的终端中导出 `CAPRIOLE_AI_API_KEY`。未设置该变量时，OpenClaw 会输出 `missing env var`。

### 为什么 Opus 5.5 因 `requires adaptive thinking` 失败

将 `claude-opus-5-5` 的 `reasoning` 设为 `false`。

### 为什么 OpenClaw 提示模型不被允许或缺失

运行 `openclaw models list`。确认模型引用位于 `agents.defaults.models` 中，并确认模型条目包含上面示例中的完整对象，而不只有 `id` 和 `name`。

### 为什么新会话以设置对话开始

这是 OpenClaw 首次运行时的工作区设置，不是 Capriole AI 的问题。在 `openclaw tui` 中完成一次即可，也可以重新运行 `openclaw onboard`。

### 为什么 Gateway 无法启动

运行 `openclaw status`、`openclaw gateway status`、`openclaw logs --follow` 和 `openclaw doctor`。

## 说明

- 如需添加其他 Capriole AI 模型，请复制同一系列中某个模型的条目，修改 ID，并把它的模型引用添加到 `agents.defaults.models`。`GET https://api.caprioletech.com/v1/models` 会列出所有模型 ID。
- 想在其他编程智能体中使用同一个 API Key，请参阅[使用一个 API Key 配置编程智能体](/zh/guides/one-api-key-coding-agents)。
