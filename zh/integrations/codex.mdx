## Codex 是什么

Codex 是 OpenAI 面向软件开发的编程代理。你可以配置自定义模型提供商，让 Codex 通过 Capriole AI 的 Responses 兼容 API 使用 Capriole AI。

## 前置条件

开始前请确保你已经拥有以下内容。

- Capriole AI 账户，可在[此处注册](https://capriole.ai)
- Capriole AI API Key，可在[此处获取](https://capriole.ai?view=api)

## 安装

### Codex CLI

```bash
npm install -g @openai/codex
```

### Codex app

从 [OpenAI Codex](https://developers.openai.com/codex) 下载应用。

## 配置

创建或更新 `~/.codex/config.toml`。

```toml
model = "openai-latest"
model_reasoning_effort = "high"
model_provider = "capriole_ai"

[model_providers.capriole_ai]
name = "Capriole AI"
base_url = "https://api.caprioletech.com/v1"
wire_api = "responses"
env_key = "CAPRIOLE_AI_API_KEY"
env_key_instructions = "Export CAPRIOLE_AI_API_KEY before starting Codex"
```

## 运行 Codex

设置 API Key，然后启动 Codex。

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
codex
```

## 支持的模型

Codex 通过 Responses API 使用 Capriole AI 提供的 OpenAI 模型。新配置建议使用 `openai-latest`，这样 Capriole AI 可以把 Codex 路由到当前推荐的 OpenAI 旗舰模型，无需修改配置。

- `openai-latest`
- `openai/gpt-5.6-terra`
- `openai/gpt-5.6-luna`
- `openai/gpt-5.5`
- `openai/gpt-5.4-mini`

## 故障排除

### 为什么 Codex 返回身份验证错误

运行 `codex` 前，确认已在同一个 Shell 中导出 `CAPRIOLE_AI_API_KEY`。

### 为什么 Codex 找不到模型

确认已经设置 `model_provider = "capriole_ai"`，并确认 `model` 是 `openai-latest` 或 Capriole AI 支持的 OpenAI 模型 ID。

### 为什么请求出现端点或协议错误

确认 `[model_providers.capriole_ai]` 下设置了 `base_url = "https://api.caprioletech.com/v1"` 和 `wire_api = "responses"`。

### 为什么 Codex 忽略 Capriole AI 提供商

不要使用 `openai` 等保留的内置提供商 ID。自定义提供商 ID 请保持为 `capriole_ai`。

### 为什么配置修改没有生效

确认 `~/.codex/config.toml` 是当前用户配置文件。使用项目级 `.codex/config.toml` 前先信任该项目，然后重新启动 Codex。

## 说明

- 此配置使用 `env_key`，API Key 会保留在 Shell 环境中，不会写入配置文件。
- 官方参考资料包括 [Codex CLI](https://developers.openai.com/codex/cli)、[Codex 配置基础](https://developers.openai.com/codex/config-basic)、[Codex 配置参考](https://developers.openai.com/codex/config-reference)和[配置示例](https://developers.openai.com/codex/config-sample)。
