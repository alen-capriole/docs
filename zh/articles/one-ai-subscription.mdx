Capriole AI 用一个低价工作区，解决日常管理多个 AI 订阅的麻烦。未登录访客和 Free 用户可以在付费前，通过有限的浏览器聊天试用 **GPT-6 Astra、Claude Fable 5.1 和 Gemini 3.1 Pro**。

Premium 每月收费 **USD 8**，包含受支持 Premium 模型范围内的无限浏览器聊天。此外还有每月 **500 万计费 API token**、六项持续维护的编程智能体集成、模型切换、文件、网页搜索，以及明确的聊天存储控制。

用户只需一个账户就能使用受支持的前沿模型，不必分别管理多个订阅、界面、历史记录、提供商密钥和余额。

## 麻烦不只来自每月账单

使用多个 AI 产品，往往意味着多个浏览器标签页、账单页面、历史记录、界面和控制方式。一项任务可能从某个产品开始，后来需要另一个模型。此时的迁移就像一次小型搬家，需要复制有用的上下文、重新附加文件、再解释一遍任务，还要熟悉下一个界面提供了哪些控制项。

API 工作会增加提供商账户、密钥、余额、模型名称和不兼容的请求格式。编程智能体又带来一层配置。单独看，每一步都不难，叠在一起却会把模型选择变成账户管理工作。

Capriole AI 把常用部分放进同一个工作区。你可以和受支持的模型聊天，在对话中切换模型，使用文件或网页搜索，并让线程留在同一个界面。产品会处理切换背后的协议和上下文差异。

Capriole 在同一个工作区中维护 OpenAI、Anthropic、Google、xAI、Z.AI 和 Moonshot AI 当前受支持的模型，其中包括上面列出的旗舰组合。

浏览器和 API 采用不同的用量模式。Premium 浏览器聊天没有需要用户逐条管理的消息 token 余额。API 请求需要计量，因为程序化工作负载可能远高于普通聊天。

这项方案适合每天聊天，同时偶尔或适度使用 API 与编程智能体的人。两类额度各自清楚。Premium 下的浏览器聊天无限，自动化工作则使用可见的计费 token 余额。

## 同一段对话使用不同模型的长处

不同模型家族适合同一项任务的不同阶段。一段对话可以从研究开始，随后进入严谨写作，最后完成代码或结构化分析。使用独立产品时，上下文只能由用户自己搬运。

Capriole 让对话留在同一个工作区，同时允许更改所选模型。用户看到的是一次模型选择，底层可能需要分别处理消息格式、上下文限制、推理控制、文件、工具、流式事件、token 计量和错误。

Capriole 把这些适配作为产品的一部分持续维护。因此，更改所选模型后，用户无需重建线程或集成。

Capriole 还为受支持的 API 和智能体工作流提供最新模型别名。配置可以跟随 Capriole 为某个提供商家族推荐的当前模型，用户不必立即更新每一个精确模型标识符。

## 同一个账户也能用于浏览器之外

符合条件的付费访问会同时解锁 Capriole 公共 API 和浏览器聊天。[API 快速入门](/zh/quickstart)介绍如何发出第一个请求，持续维护的指南则支持六种编程智能体，包括 [Codex](/zh/integrations/codex)、[Claude Code](/zh/integrations/claude-code)、[Kilo Code](/zh/integrations/kilo-code)、[GitHub Copilot CLI](/zh/integrations/github-copilot-cli)、[OpenCode](/zh/integrations/opencode) 和 [OpenClaw](/zh/integrations/openclaw)。

这并不会让所有编程智能体变得相同。每个客户端仍有自己的能力和要求。它带来的好处很直接。受支持的客户端可以使用同一个 Capriole 账户和兼容的 API 路径，无需为每个模型家族分别配置提供商。

## 选择聊天历史保存在哪里

不同对话适合不同的存储策略。

| 模式 | 聊天历史保存位置 | 跨设备 | 上传 |
|---|---|---|---|
| Synced | Capriole 账户存储 | 支持 | 可用 |
| Local | 当前浏览器的本地存储 | 不支持 | 禁用 |
| No Storage | 仅保存在当前页面会话的内存中 | 不支持 | 禁用 |

Local 历史在页面刷新后仍然存在，直至该浏览器的网站数据被清除。No Storage 历史会在页面刷新或用户离开后丢失。首次启用时，系统会先请求确认，再删除已有的服务端和本地聊天历史。

三种模式都会把每个请求发送给 Capriole 和所选模型服务。它们控制聊天历史的持久化方式，不代表完全没有运行记录，也不能取代所选提供商的数据政策。处理敏感或受监管数据前，请阅读[聊天存储指南](/zh/guides/chat-storage)。
