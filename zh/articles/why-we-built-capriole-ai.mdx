Capriole AI 是一个统一工作区，提供前沿模型聊天、公共 API 额度和受支持的编程智能体。未登录访客和 Free 用户可以先试用 GPT-6 Astra、Claude Fable 5.1 和 Gemini 3.1 Pro。每月 USD 8 的 Premium 方案则提供无限浏览器聊天、500 万计费 API token，以及六项持续维护的智能体集成。

这件事始于我们为 Capriole Charts 增加 AI 功能的时候。

我们需要稳定地使用前沿模型，也花了很长时间把整套配置打磨到足以支撑自身工作的程度。它稳定运行之后，我们意识到 Charts 之外的用户同样需要这层访问能力。

使用 ChatGPT、Claude 和 Gemini 通常意味着打开三个不同的产品。它们各有订阅、界面、历史记录和对话处理方式。API 访问又会增加一批账户与余额，编程智能体还会带来更多密钥和配置。

于是，我们决定把这套基础设施做成一个独立产品。

最初的 AI 体验位于 Charts 内。随着开发继续推进，通用聊天与模型访问层显然适用于更广泛的场景。我们把这部分拆分成 Capriole AI，Charts 则继续保留与自身产品场景紧密相关的 AI 功能。

## 使用多个独立产品的代价

每月向多家公司付费很昂贵，管理这些服务也很繁琐。

一个问题可能从某个聊天产品开始，进行到一半时换一个模型会更合适。迁移时，用户要复制提示词，带走仍然有用的上下文，再适应另一套界面。本应节省时间的产品，最后反而需要用户亲自协调。

Capriole AI 把受支持的前沿模型放进同一个网页聊天界面。你可以用一个模型开始对话，随后切换到另一个模型，无需打开新产品或重建整个线程。文件、网页搜索、聊天历史和模型选择都留在同一工作区。

## 让不同模型呈现为一个完整产品

每家模型提供商都有自己的假设。消息格式、上下文限制和推理控制各不相同。文件、工具、流式事件、token 计量和错误响应也都需要分别处理。

官方 AI 产品只需把自家的模型做好。Capriole AI 需要让多家提供商的领先模型在同一段对话中协调工作。

模型选择器只是其中最小的一部分。我们构建并持续改进协议适配器、模型别名、上下文管理、流式响应、自动 fallback 和错误处理。新模型发布后，往往还要完成一轮兼容工作，才能把它放进同一套界面。

这些差异会直接出现在真实请求中。一个模型家族可能使用 OpenAI Responses 事件，另一个则要求 Anthropic Messages。token 用量和错误信息的结构也不同。长对话在切换模型继续之前，可能需要压缩上下文才能安全处理。只有把这些情况衔接好，模型切换才能变得平常自然。

大部分工作都藏在界面背后。用户可以在对话进行到一半时，从 ChatGPT 模型切换到 Claude 或 Gemini，并在同一个线程里继续。

同一个 Capriole AI 账户可以用于浏览器聊天、公共 API 和六项持续维护的编程智能体集成，包括 [Codex](/zh/integrations/codex)、[Claude Code](/zh/integrations/claude-code)、[Kilo Code](/zh/integrations/kilo-code)、[GitHub Copilot CLI](/zh/integrations/github-copilot-cli)、[OpenCode](/zh/integrations/opencode) 和 [OpenClaw](/zh/integrations/openclaw)。最新模型别名简化了受支持的 API 与智能体配置，用户无需追踪不同提供商的特定模型名称。兼容的协议路径由我们处理，连接智能体无需再做一次提供商集成项目。

## 适合日常使用的会员价格

我们打造 Capriole AI，是希望用一个价格亲民的账户替代一组昂贵的 AI 会员。

Premium 每月收费 **USD 8**，包含受支持 Premium 模型范围内的无限浏览器聊天。用户无需盯着浏览器聊天余额，每次切换模型也不会扣除另一份单独额度。

Premium 会员每月还会获得 **500 万计费 API token**，用完后可以购买 top-up。在我们的[定期更新成本对比](/zh/articles/ai-api-cost-comparison)中，三个测试模型的工作负载在 Capriole 都是 USD 8。直接使用官方付费 Standard 定价的成本在 USD 15 至 USD 90 之间，OpenRouter 加上其公开的充值手续费后则在 USD 15.83 至 USD 94.95 之间。

该测试使用一种固定的 token 构成，无法代表所有工作负载。它仍然说明了我们采用这种会员设计的原因。经过核验的较低 API 总价包含在一个完整工作区中，购买的不只是推理调用。

一个账户因此可以同时覆盖日常思考所用的聊天，以及产品开发所用的 API。Premium 下的浏览器聊天仍然无限，API 用量则有清晰可见的余额。

## 隐私应当是产品里的明确选择

一段需要保存的研究对话，与一段含有敏感资料的对话，并不需要采用相同的存储策略。

| 模式 | 持久化方式 | 主要取舍 |
|---|---|---|
| Synced | 可跨设备查看账户历史 | 存储聊天和上传文件状态，以便持续使用 |
| Local | 仅限当前浏览器 | 没有跨设备历史，且禁用上传 |
| No Storage | 仅限当前页面会话 | 刷新或离开页面后对话即丢失，且禁用上传 |

首次启用 No Storage 时，系统会先请求确认，再删除已有的服务端和本地聊天历史。所有模式都会把请求发送给 Capriole 和所选模型服务。它们改变的是历史记录持久化方式，不会改变模型请求路径。[聊天存储指南](/zh/guides/chat-storage)解释了完整边界。

我们把隐私做成工作区中的一项控制，并在选项旁说明每种选择的后果。

## 我们想让哪些事情更简单

Capriole AI 面向希望使用强大模型，又不愿把 AI 使用变成另一项管理工作的用户。

如果目标只是为任务选择合适的模型，同时购买多个昂贵会员并不合理。模型发生变化时，一段有用的对话应该能够继续。连接编程智能体也不该每次都从头搭建相同的提供商配置。

我们想做出这样一个工作区。它可以省钱、减少配置，也允许用户根据任务变化继续选择模型。过去，分散的订阅、密钥、历史和界面经常妨碍我们的工作。Capriole 正是当时我们想要的产品。
