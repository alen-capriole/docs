计费 token 是从 Capriole AI API 余额中扣除的单位。个人 Premium 每月包含 500 万，属于 USD 9 工作区会员的一部分。未缓存输入和输出按 100% 计算，缓存输入按 10% 计算，并向上取整到下一个整数 token。

计费 token 适用于公共 API 和编程智能体流量，这部分价格最多比官方 API 低 92%。无限 Premium 浏览器聊天不会消耗这份 API 余额。

## 计算公式

Capriole 会把每种受支持协议统一换算成输入 token 总数。如果所选提供商报告缓存输入，还会记录缓存输入数量。缓存输入是输入总数的一个子集。

```text
uncached_input = input_tokens - cached_input

charged_tokens =
  uncached_input
  + ceil(cached_input × 0.1)
  + output_tokens
```

如果提供商没有报告缓存输入，全部输入 token 都按 100% 计算。

| 协议 | 统一后的输入 | 缓存子集 |
|---|---|---|
| OpenAI Responses | `input_tokens` | `input_tokens_details.cached_tokens` |
| OpenAI Chat Completions | `prompt_tokens` | `prompt_tokens_details.cached_tokens` |
| Anthropic Messages | `input_tokens + cache_creation_input_tokens + cache_read_input_tokens` | `cache_read_input_tokens` |

对于 Anthropic Messages，缓存写入（cache creation）仍按 100% 输入计算。只有提供商报告的缓存读取（cache reads）才能按 10% 计算计费 token。

## 三个可复现示例

| 示例 | 输入总数 | 缓存输入 | 输出 | 计算 | 计费 token |
|---|---:|---:|---:|---|---:|
| 没有缓存命中 | 800 | 0 | 200 | `800 + 0 + 200` | 1,000 |
| 提示词大部分被缓存 | 10,000 | 8,000 | 500 | `2,000 + ceil(800) + 500` | 3,300 |
| 提供商报告大量缓存命中 | 228,807 | 228,224 | 90 | `583 + ceil(22,822.4) + 90` | 23,496 |

第三个请求的原始输入加输出 token 总数为 228,897。由于提供商报告其中 228,224 个输入 token 已缓存，它会扣除 23,496 个计费 token。

每条请求会单独对缓存部分取整。因此，一个缓存输入 token 在 `ceil(0.1)` 后计费一个 token，十个缓存输入 token 也计费一个 token。

```text
estimated_requests = floor(5,000,000 / average_charged_tokens_per_request)
```

## 计费 token 与提供商价格使用不同单位

官方提供商可能分别公布输入、缓存输入、缓存写入、输出、工具或长上下文价格。Capriole 的计费 token 余额是一种客户配额单位，在受支持的公共 API 路由中统一采用一种公式。

| 单位 | 它回答的问题 |
|---|---|
| 提供商输入和输出定价 | 提供商根据自己的价格表收取多少费用 |
| 原始 API 用量 token | 响应报告了多少输入、输出和缓存 token |
| Capriole 计费 token | Capriole 从账户 API 余额中扣除多少 |

不要用计费 token 乘以提供商公布的输入或输出费率。它们描述不同的计费系统。

[带日期的 API 成本对比](/zh/articles/ai-api-cost-comparison)把这套公式应用到一种固定的 500 万 token 工作负载，再比较各服务的现金成本。[Claude API 价格](/zh/articles/claude-api-pricing)、[OpenAI API 价格](/zh/articles/openai-api-pricing)和 [Gemini API 价格](/zh/articles/gemini-api-pricing)把当前每 100 万 token 的官方价格与 Capriole 每 500 万 token USD 8 的价格放在一起比较。

## API 记录什么

Capriole 会把经过协议统一的用量和计费用量记录为不同字段。一次成功的公共 API 请求可以记录以下数据。

- 统一后的输入 token
- 输出 token
- 统一后的输入加输出 token
- 提供商报告的缓存输入 token
- 从配额中扣除的计费 token
- 解析后的模型和请求状态

Responses、Chat Completions 和 Messages 端点保留各自的上游响应结构，不会返回 `charged_tokens` 字段。Capriole 会为账户用量记录相应的计费 token，你可以在 [API 页面](https://www.capriole.ai/zh?view=api)用量表格的 **计费 tokens** 列中查看。

## 确认缓存输入是否减少了扣费

打开 Capriole AI [API 页面](https://www.capriole.ai/zh?view=api)，再使用 **密钥名称**、**模型** 和 **状态** 筛选条件找出请求。比较用量表格中的这些列。

| 列 | 它确认的信息 |
|---|---|
| **输入 tokens** | 划分缓存输入前，经过协议统一的输入 |
| **缓存 tokens** | 提供商报告为已缓存的输入 |
| **计费 tokens** | 应用缓存输入公式后扣除的配额 |
| **总 tokens** | 经过协议统一的输入加输出 |

缓存 token 大于零，可以确认兼容的提供商用量元数据报告了缓存命中。提供商路由、缓存时限、请求结构和模型行为都可能改变结果。

API 响应会保留上游 schema，因此账户用量表是跨路由比较请求的一致位置。

## 常见问题

### 缓存输入总能获得 90% 的配额折扣吗

提供商用量记录中标为缓存读取的输入 token 享受 90% 折扣，其余输入 token 按标准费率计算。

### Reasoning tokens 会被重复计算吗

不会。提供商报告的输出用量已经包含路由采用的输出计量。Capriole 不会在此公式的输出之外另加一笔 reasoning-token 费用。

### Premium 如何计算 API 和编程智能体的用量？

Premium 每月含 5,000,000 个 API token，可用于应用和编程智能体。额外 5,000,000 个 token 的充值价格为 USD 8。
