一个 Capriole AI 账户和 API Key 可以用于多个受支持的模型家族，价格最多比官方 API 低 92%。同一份 USD 9 Premium 会员还包含 GPT-6.2 Astra、Claude Fable 5.1、Claude Opus 5.5 和 Gemini 4 Carbon 的无限浏览器聊天，因此一个账户就能覆盖应用、编程智能体和日常聊天。

Capriole 维护三条公共路径：OpenAI Responses、兼容 OpenAI 的 Chat Completions 和 Anthropic Messages。

共享账户和账单层位于这些协议特定路由之上。

## 这套设计为什么让 Capriole 更实用

一份 USD 9 Premium 会员覆盖受支持 Premium 模型范围内的无限浏览器聊天、每月 500 万 API 计费 token 和 10 条有文档说明的编程智能体路径。应用继续使用原有协议，用户则只需管理一个 Capriole 账户、密钥、余额和账单页面。

相较于分别组装多个提供商账户，这是一项实际优势。[带日期的成本对比](/zh/articles/ai-api-cost-comparison)采用个人 Premium 每月 USD 9 的订阅价，其中包含 5,000,000 个 API token。在同样 500 万 token 的工作负载下，采用官方直连付费 Standard 定价时，成本在 USD 6.75 至 USD 90 之间。通过 OpenRouter 并计入其公开充值手续费后，成本则在 USD 7.55 至 USD 94.95 之间。个人 Premium 加购 5,000,000 个 token 的单包价格为 USD 8。各旗舰模型的官方费率见 [Claude API 价格](/zh/articles/claude-api-pricing)、[OpenAI API 价格](/zh/articles/openai-api-pricing)和 [Gemini API 价格](/zh/articles/gemini-api-pricing)。

## 公共路径

| 路径 | 接口约定 | 典型用途 |
|---|---|---|
| `POST /v1/chat/completions` | 兼容 OpenAI 的 Chat Completions | 兼容的客户端和智能体 |
| `POST /v1/responses` | OpenAI Responses | 基于 Responses 的应用和 Codex |
| `POST /v1/messages` | Anthropic Messages | Claude 原生客户端和 Claude Code |

成功路由的响应和流式事件会保留客户端所请求的协议。Responses 的响应内容在返回时不会转换成 Chat Completions，Anthropic Messages 的流也不会重新包装成 OpenAI 输出。

这样可以保留 Responses、Messages 和 Chat Completions 客户端预期的协议特定行为。

共享层处理访问和计量，每条公共路由则保留对应客户端期望的请求与响应约定。模型分组是针对不同路由的兼容集合，并没有层级关系。一个模型如果实现了多种接口约定，就可能出现在多条受支持路由上。

## 为什么一个端点不够

各模型家族的差异不限于字段名称。

OpenAI Responses 用带类型的事件和条目（items）表达输出。Anthropic Messages 使用自己的内容块（content blocks）和流式事件，Chat Completions 又有另一套请求与响应结构。推理控制、工具调用、用量数据、错误和 token 计数方式也不相同。

简单适配器可以让基础文本提示词工作。编程智能体和生产客户端很快就会暴露缺少的细节，因为它们依赖流式顺序、工具结果轮次、用量元数据和模型特定控制。

因此，Capriole 在同一套身份验证和账单层背后维护多条保留协议的路由。

## 一个密钥，明确选择模型

所有公共生成路由共用同一个 Capriole API Key 和账户余额，所请求的模型仍须属于所选协议。

例如，Responses 路径接受持续维护的 OpenAI 别名和受支持的兼容 Responses 的 OpenAI 模型，也接受带 `xai/` 前缀发送的 Grok 模型。Messages 路径接受持续维护的 Claude 别名和受支持的 Claude Messages 模型 ID。兼容聊天路径则可以提供范围更广的公共聊天模型。

每个路由都会在转发前校验模型 ID。若 ID 不符合该端点的要求，客户端会收到校验错误，可更正模型或端点后重试。

## latest 别名与可复现 ID

Capriole 在支持它们的公共路径上提供 `openai-latest`、`claude-latest` 和 `google-latest` 等持续维护的别名。

别名会在上游分发之前解析。用量、配额和回退记录会关联到解析后的规范模型，不会落在含义模糊的“latest”分组中。

希望 Capriole 的持续维护默认值随受支持版本更新时，可以使用别名。如果精确版本属于结果的一部分且必须可复现，则应使用具体的模型 ID。

[列出模型端点](/zh/api-reference/endpoint/get)提供当前公开清单。

## 回退只在响应开始前发生

对于受支持的路由，如果第一个来源在发送任何响应字节前失败，Capriole 可以尝试另一个已配置来源。

流式响应开始后，来源保持不变。

通过受支持的来源回退时，请求的模型 ID 保持不变。Capriole 更改的是交付来源，不会改变用户明确选择的模型。

浏览器聊天还可以单独提供可选的自动模型切换，以及[在对话中手动更换模型](/zh/articles/switch-models-mid-chat)。这些属于工作区行为，不是原始 API 的回退约定。

## 用量始终可见

程序化工作负载会被计量。Capriole 根据对应协议提供的元数据记录用量，在可获得用量信息时也包括已经完成的流式响应。

Premium 当前每月包含 **5,000,000 API 计费 token**。对于这份余额，Capriole 按 100% 计算未缓存输入和输出，按 10% 计算缓存输入。还可以通过充值购买额外 token 包。

[计费 token 文章](/zh/articles/charged-tokens)提供准确公式、取整规则和可复现示例。

浏览器聊天与自动化 API 工作负载使用不同额度。编程智能体处理数百万 token 时，会消耗可见的计费 token 余额。

## 统一层实际提供什么

共享层提供的是下面这些外围产品约定，不会把各协议改成同一种响应结构。

- 一个 Capriole 账户和 API Key
- 一份可见的 API 余额
- 持续维护的模型别名
- 根据所选协议进行验证
- 在输出开始前通过受支持的来源回退
- 按解析后的模型记录用量
- 为应用和编程智能体提供设置文档

协议仍然明确存在，因为客户端依赖它。

## 我们如何测试兼容性

一条路由只有在协议约定与具有代表性的真实客户端流程均通过后，才会被 Capriole 记录为受支持。一条简单文本提示词请求成功只是初步检查。流式响应、工具结果轮次、别名解析、用量计量和协议反向测试共同提供其余证据。

针对公共路由和文件转换的集中测试套件，已经在受控的上游响应上完成 **68 项自动化测试**，这些并非生产环境实时调用。另有本地上游和编程智能体运行，用于检查模拟端点无法证明的行为。

| 测试路径 | 已验证证据 | 当前边界 |
|---|---|---|
| OpenAI Responses | 非流式输出、SSE 完成、函数调用、无状态的函数结果后续请求和 `openai-latest` | OpenAI 模型，以及带 `xai/` 前缀的 Grok 模型 |
| Chat Completions | 非流式输出、SSE 完成、工具调用、工具结果后续请求和全部三个持续维护的 latest 别名 | 所选模型必须支持兼容路由 |
| Anthropic Messages | 非流式输出、Anthropic SSE、`tool_use`、`tool_result` 和 `claude-latest` | 仅限 Claude Messages 模型 |
| latest 别名 | 端点准入检查、规范模型解析、规范模型用量记录和具有代表性的客户端运行 | 别名只是输入选择器，不会创建独立的用量模型 |
| 网页聊天中的文件 | 对图片、PDF、文本、DOCX、PPTX、CSV、XLS 和 XLSX 进行文件类型检测、转换和模型请求体组装 | 这项证据属于网页聊天工作区 |

流式检查会读取完整响应，并要求出现各协议自己的结束事件。Responses 以自己的完成事件结束，Chat Completions 到达 `[DONE]`，Messages 则到达 `message_stop`。工具测试会把工具结果发回，并要求返回最终的 assistant 回合。

校验测试会检查每个端点对应的模型别名。`google-latest` 用于 Chat Completions，`openai-latest` 用于 Responses 或 Chat Completions。

在浏览器聊天中上传附件时，可查阅[支持的文件类型和上传步骤](/zh/guides/files-web-search)。
