当应用、SDK 或代理需要 OpenAI Responses 请求与响应格式时，请使用此端点。

发送包含 `model` 和 `input` 的标准 Responses 请求体。Capriole AI 会在转发给上游前，把 latest alias 解析为所选上游模型 ID；继续转发 `instructions`、`tools`、`reasoning`、`previous_response_id` 和 `stream` 等兼容字段；并原样返回上游 JSON 或 SSE 流。

`POST /v1/responses` 接受 `openai-latest`、`openai/gpt-6-astra`、`openai/gpt-6.1-sol`、`openai/gpt-6-sol`、`openai/gpt-6-luna`、`openai/gpt-5.6-terra`、`openai/gpt-5.6-luna` 和 `openai/gpt-5.5`。使用 `openai-latest` 可以让 Capriole AI 选择当前推荐的 OpenAI Responses 旗舰模型。

也可以发送不带 `openai/` 前缀的原生 OpenAI ID，例如 `gpt-6-astra`。原生 ID 与带前缀的 ID 使用同一模型记录进行路由、计价和额度扣减。

此端点也接受 Grok 模型 `xai/grok-4.7`、`xai/grok-4.6` 和 `xai/grok-4.5`。Grok ID 必须带 `xai/` 前缀发送；`grok-4.7` 这类不带前缀的 ID 会被视为原生 OpenAI ID 并被拒绝。Grok 请求会直接转发到 xAI 自己的 Responses API，不做格式转换。

此端点不支持 Claude 和 Google latest alias，也不支持通过 Chat Completions 调用的 GLM 5.2 和 Kimi K3。如果需要通过一个 OpenAI 兼容端点调用全部公开模型，请使用 `POST /v1/chat/completions`。

## 网页搜索

添加内置的 `web_search` 工具，即可让 GPT 或 Grok 模型搜索网页：

```bash
curl https://api.caprioletech.com/v1/responses \
  -X POST \
  -H "Authorization: Bearer YOUR_CAPRIOLE_AI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "xai/grok-4.7",
    "input": "Summarize the latest AI news.",
    "tools": [{"type": "web_search"}],
    "stream": true
  }'
```

网页搜索会把检索到的搜索结果计入请求的输入 token，因此一次带搜索的回答使用的输入 token 可能远多于提示词本身。

`POST /v1/chat/completions` 不提供网页搜索。

## 长任务

网页搜索、长时间推理等长任务请设置 `"stream": true`。不使用流式传输时，连接可能在约 2 分钟后超时。
