Use este endpoint quando seu aplicativo, SDK ou gateway esperar o formato de solicitação e resposta do OpenAI Chat Completions.

Envie um payload padrão de Chat Completions com `model` e `messages`. A Capriole AI resolve os aliases latest para o ID de modelo do provedor selecionado antes do despacho ao upstream, encaminha campos compatíveis como `messages`, `tools`, `tool_choice`, `response_format` e `stream`, e devolve o JSON ou o stream SSE do upstream sem alteração, exceto pela correção de SSE para GLM e pelos comentários de heartbeat descritos abaixo. Em solicitações com streaming, a Capriole AI define `stream_options.include_usage=true` antes de encaminhar, para que o uso possa ser registrado.

Em algumas respostas SSE com `model="zai/glm-5.3-flash"`, a Capriole AI remove apenas o campo legado vazio `function_call={"name":"","arguments":""}` dos deltas. Chamadas reais ou parciais, `tool_calls`, texto e uso são preservados. Essa exceção não altera respostas sem streaming nem outros modelos.

`POST /v1/chat/completions` aceita `openai-latest`, `claude-latest`, `google-latest` e IDs públicos de modelo concretos retornados por `GET /v1/models`. Use um alias latest para deixar a Capriole AI escolher o modelo principal que recomendamos para aquele provedor.

Os aliases latest são atalhos de entrada. O uso é registrado no modelo resolvido, enquanto o corpo da resposta mantém o comportamento de nomeação de modelo do endpoint compatível selecionado.

## Kimi K3.1 Pro

O Kimi K3.1 Pro fixa `temperature` em 1 e `top_p` em 0.95. Omita `temperature`, `top_p`, `n`, `presence_penalty` e `frequency_penalty` para este modelo e envie as instruções com o papel `system` em vez de `developer`.

## Gemini 4 Carbon

`google-latest` é resolvido para `google/gemini-4-carbon`. Este endpoint encaminha o restante da sua solicitação sem alteração, então o Gemini 4 Carbon raciocina no nível padrão do Google, `medium`, que no nosso teste usou cerca de 3 a 4 vezes os tokens de saída do Gemini 4 Argon para o mesmo prompt. O `reasoning_effort` da OpenAI não altera o nível de raciocínio do Carbon. Para defini-lo, envie o campo do Google com `low`, `medium` ou `high`:

```json
"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}
```

Com o SDK Python da OpenAI, passe `extra_body={"extra_body": {"google": {"thinking_config": {"thinking_level": "low"}}}}`. O Google observa que prompts difíceis no Carbon podem levar vários minutos, então use streaming neles, como descrito em [Tarefas longas](#tarefas-longas); para esperar menos, defina `thinking_level` como `low` ou use `google/gemini-4-argon`.

## Gemini 4 Neon

Use `google/gemini-4-neon` para selecionar o Neon. O Google documenta uma janela de 1.048.576 tokens compartilhada entre entrada e saída, um limite padrão de saída síncrona de 65.536 tokens e suporte a JSON Schema. Os níveis de raciocínio são `low`, `medium`, `high` (padrão) e `xhigh`. Veja a [documentação do modelo do Google](https://aistudio.google.com/docs/models/gemini-4-neon).

## Pesquisa na web

Este endpoint não oferece pesquisa na web. Para modelos Grok, uma solicitação com um campo `web_search_options` ou `search_parameters` diferente de null falha com HTTP 400:

```json
{
  "detail": "Web search is not supported for xai/grok-4.7 on /v1/chat/completions. Use POST /v1/responses with tools: [{\"type\": \"web_search\"}]."
}
```

Ferramentas de função definidas pelo seu cliente, mesmo uma chamada `web_search`, são encaminhadas sem alteração. Para pesquisar na web com GPT ou Grok, use [`POST /v1/responses`](/pt-br/api-reference/endpoint/responses) com `"tools": [{"type": "web_search"}]`.

## Tarefas longas

Para tarefas longas, como raciocínio extenso, defina `"stream": true`. Sem streaming, a conexão pode expirar após cerca de 2 minutos. Enquanto uma solicitação com streaming espera pelo modelo, a Capriole AI envia um comentário SSE `: heartbeat` a cada 15 segundos, e solicitações `google/*` com streaming podem esperar até 20 minutos pelo primeiro token. Se o modelo não tiver respondido em 60 segundos, a resposta 200 já terá começado, então um erro posterior do upstream chega como um último evento SSE com um objeto `error`.
