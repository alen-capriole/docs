## O que é OpenClaw

O OpenClaw é um assistente pessoal de IA e gateway de código aberto e auto-hospedado que conecta canais de chat como WhatsApp, Slack, Discord, Telegram, iMessage e WebChat a agentes de IA. Ele pode enviar solicitações de modelo suportadas pela Capriole AI ao configurar provedores de modelo personalizados compatíveis com OpenAI e Anthropic.

## Pré-requisitos

Antes de começar, confira se você tem:

- Uma conta Capriole AI ([Cadastre-se aqui](https://capriole.ai))
- Uma API key da Capriole AI ([Obtenha sua key](https://capriole.ai?view=api))

## Instalação

```bash
curl -fsSL https://openclaw.ai/install.sh | bash -s -- --no-onboard
```

## Configuração

### Validação dos modelos

OpenClaw 2026.4.21: `anthropic/claude-fable-5-1`, `google/gemini-3.8-flash` e `zai/glm-5.3-flash` passam nas verificações locais de leitura de arquivo e resposta final. `claude-latest` resolve para Fable 5.1. Os IDs concretos anteriores continuam disponíveis.

As configurações de capacidade abaixo seguem as especificações publicadas de [Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-1/overview), [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash) e [GLM 5.3 Flash](https://docs.z.ai/guides/vlm/glm-5.3-flash).

São configurações de capacidade do modelo no cliente, não metas de saída por solicitação nem limites verificados do VectorEngine. As verificações locais de tarefas usaram `contextWindow=200000` e `maxTokens=2048`; solicitações com capacidade máxima não foram validadas. Fable 5.1 também passa pela rota Anthropic Messages.

`xai/grok-4.6` aceita solicitações de Chat Completions, mas não passou nas verificações de tarefas de agentes e não está na configuração abaixo. Testes diretos no provedor também encontraram uso inconsistente de ferramentas no Grok 4.5; concluir uma solicitação API não comprova uma resposta correta do agente.

Configure o provedor GPT:

```bash
export CUSTOM_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export CAPRIOLE_OPENAI_BASE_URL="https://api.caprioletech.com/v1"

openclaw onboard --non-interactive \
  --accept-risk \
  --mode local \
  --auth-choice custom-api-key \
  --custom-base-url "$CAPRIOLE_OPENAI_BASE_URL" \
  --custom-model-id "openai-latest" \
  --custom-provider-id "capriole-ai-openai" \
  --custom-compatibility openai \
  --secret-input-mode ref \
  --gateway-port 18789 \
  --gateway-bind loopback \
  --skip-channels \
  --skip-search \
  --skip-skills \
  --skip-health \
  --no-install-daemon

openclaw config set models.providers.capriole-ai-openai.request.auth \
  '{"mode":"authorization-bearer","token":"${CUSTOM_API_KEY}"}' \
  --strict-json

openclaw config set models.providers.capriole-ai-openai.api \
```

## Executar OpenClaw

Inicie o gateway:

```bash
export CUSTOM_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
openclaw gateway --force --port 18789
```

Abra o TUI em outro terminal:

```bash
export CUSTOM_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
openclaw tui
```

## Solução de problemas

### Por que as solicitações GPT falham?

Confirme que `models.providers.capriole-ai-openai.api` está definido como `"openai-responses"` e que `baseUrl` é `https://api.caprioletech.com/v1`.

### Por que as solicitações Grok, GLM ou Kimi falham?

Confirme que `models.providers.capriole-ai-compatible.api` está definido como `"openai-completions"` e que `baseUrl` é `https://api.caprioletech.com/v1`.

### Por que as solicitações Anthropic falham?

Confirme que `models.providers.capriole-ai-anthropic.api` está definido como `"anthropic-messages"` e que o `baseUrl` da Anthropic é `https://api.caprioletech.com` sem `/v1`.

### Por que a autenticação falha?

Exporte `CUSTOM_API_KEY` no terminal que inicia `openclaw gateway` e no terminal que inicia `openclaw tui`.

### Por que o OpenClaw informa que um modelo não é permitido ou não está disponível?

Execute `openclaw models list` e confirme que o modelo selecionado e qualquer lista de permissão de `agents.defaults.models` incluem a referência de modelo da Capriole AI, como `capriole-ai-openai/openai-latest`, `capriole-ai-compatible/xai/grok-4.5`, `capriole-ai-compatible/moonshot/kimi-k3` ou `capriole-ai-anthropic/claude-latest`.

Se um modelo da Capriole AI aparecer como ausente, atualize a entrada do modelo com o objeto completo mostrado acima. As versões atuais do OpenClaw precisam de mais do que `id` e `name` para modelos de provedor personalizado.

### Por que o gateway não inicia?

Execute `openclaw status`, `openclaw gateway status`, `openclaw logs --follow` e `openclaw doctor`. Corrija problemas de schema, `gateway.mode` ou serviço antes de tentar de novo.

### Por que a porta `18789` falha?

Escolha outra porta local e use a mesma porta para o gateway e a configuração do cliente. Em instalações no modo serviço, execute `openclaw doctor --fix` ou `openclaw gateway install --force` depois de alterar a porta.

## Observações

- Os provedores personalizados do OpenClaw exigem que o modo de API do provedor corresponda à família de endpoint da Capriole AI.
- O OpenClaw 2026.4.21 conclui fluxos de ferramenta `exec` locais com Grok 4.5, GLM 5.2 e Kimi K3 por `openai-completions`.
- A Capriole AI trata a solicitação de modelo. O OpenClaw ainda pode moldar o comportamento final do assistente pelo gateway, pelos canais e pelas configurações do agente.
