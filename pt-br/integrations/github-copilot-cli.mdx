Com uma única API key da Capriole AI, você usa GPT-6 Astra, Claude Fable 5.1 e Opus 5.5 no GitHub Copilot CLI pagando até 92% menos que os preços oficiais da API.

## O que é GitHub Copilot CLI

O GitHub Copilot CLI é o agente de programação do GitHub para o terminal. O modo bring-your-own-key (BYOK) dele envia solicitações de modelo para um provedor que você define com variáveis de ambiente. Esta configuração o aponta para a Capriole AI.

## Pré-requisitos

Antes de começar, confira se você tem:

- Uma conta Capriole AI ([Cadastre-se aqui](https://www.capriole.ai/pt-br))
- Um plano Premium (USD 8 por mês, também inclui chat na web ilimitado) ou um plano Team, necessário para a API key ([Assine](https://www.capriole.ai/pt-br?view=api))
- Uma API key da Capriole AI ([Obtenha sua key](https://www.capriole.ai/pt-br?view=api))

## Instalação

Instale o GitHub Copilot CLI com npm:

```bash
npm install -g @github/copilot
```

Verifique a instalação:

```bash
copilot --version
```

Você não precisa entrar no GitHub quando `COPILOT_PROVIDER_BASE_URL` está definida.

## Configuração

### Validação dos modelos

O GitHub Copilot CLI 1.0.100 passa nas verificações de leitura de arquivo, escrita de arquivo e resposta final pela Capriole AI com todos os modelos da seção Modelos suportados, usando os perfis abaixo.

O Copilot CLI usa um provedor por vez, então escolha o perfil da família de modelos que você quer usar. Cada perfil define dois valores de modelo:

- `COPILOT_PROVIDER_WIRE_MODEL` é o ID de modelo da Capriole AI que o Copilot envia.
- `COPILOT_PROVIDER_MODEL_ID` é um modelo que o Copilot conhece. O Copilot o usa para escolher as ferramentas, os prompts e os limites de tokens.

### Modelos GPT

Os modelos GPT usam a API Responses:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

Para GPT-6.1 Sol, defina `COPILOT_PROVIDER_MODEL_ID="gpt-6.1-sol"` e `COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-6.1-sol"`.

### Modelos Claude

Os modelos Claude usam Anthropic Messages:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="anthropic"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com"
export COPILOT_PROVIDER_BEARER_TOKEN="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"
export COPILOT_PROVIDER_WIRE_MODEL="claude-latest"
```

Para Opus 5.5, defina `COPILOT_PROVIDER_WIRE_MODEL="claude-opus-5-5"`.

- `COPILOT_PROVIDER_BEARER_TOKEN` envia a key como Bearer token. `COPILOT_PROVIDER_API_KEY` a enviaria em um cabeçalho `x-api-key`, que a Capriole AI não aceita.
- A URL base não tem `/v1`, porque o próprio Copilot adiciona `/v1/messages`.
- Mantenha `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`. Com um perfil mais antigo, como `claude-sonnet-4`, o Copilot envia um orçamento de thinking, e o Opus 5.5 o rejeita com `requires adaptive thinking`.

### Modelos Gemini, Grok, GLM e Kimi

Esses modelos usam Chat Completions:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
export COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"
export COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3"
```

Para os outros modelos, altere `COPILOT_PROVIDER_WIRE_MODEL` para `google/gemini-3.8-flash`, `xai/grok-4.7` ou `zai/glm-5.3-flash`.

Mantenha `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`. Com um perfil GPT, como `gpt-5.4`, o Copilot envia tipos de ferramenta que esses modelos rejeitam.

Para o Kimi K3.1 Pro, defina `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"` e `COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3.1-pro"`. O perfil `claude-sonnet-4` envia `temperature: 0`, que o Kimi K3.1 Pro rejeita.

Para manter um perfil, adicione as linhas dele a `~/.zshrc` ou `~/.bashrc` e abra um novo terminal.

## Executar GitHub Copilot CLI

Inicie o Copilot CLI no diretório do projeto:

```bash
copilot
```

Para uma execução não interativa, passe um prompt com `-p`:

```bash
copilot -p "Explain this repository." --allow-all-tools
```

## Solução de problemas

### Por que o Copilot CLI retorna um erro de autenticação?

Confirme que `CAPRIOLE_AI_API_KEY` está exportada no mesmo shell. Para modelos Claude, use `COPILOT_PROVIDER_BEARER_TOKEN`, e não `COPILOT_PROVIDER_API_KEY`.

### Por que as solicitações falham com erros de endpoint?

Para modelos GPT, Gemini, Grok, GLM e Kimi, `COPILOT_PROVIDER_BASE_URL` é `https://api.caprioletech.com/v1`. Para modelos Claude, é `https://api.caprioletech.com` sem `/v1`.

### Por que o Opus 5.5 falha com `requires adaptive thinking`?

Defina `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`.

### Por que as solicitações Gemini, Grok, GLM ou Kimi falham com um erro de ferramentas?

Defina `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`, ou `"claude-opus-4.6"` para o Kimi K3.1 Pro. Um perfil GPT envia tipos de ferramenta que só os modelos OpenAI aceitam.

## Observações

- O Copilot CLI executa ferramentas de programação no seu computador. A Capriole AI só trata as solicitações de modelo.
- Execute `copilot help providers` para ver todas as variáveis de ambiente BYOK.
- Para usar a mesma key nos seus outros agentes de programação, veja [Usar uma API key com agentes de programação](/pt-br/guides/one-api-key-coding-agents).
