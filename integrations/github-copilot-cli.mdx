## What is GitHub Copilot CLI

GitHub Copilot CLI is GitHub's coding agent for the terminal. Its bring-your-own-key (BYOK) mode sends model requests to a provider that you set with environment variables. This setup points it at Capriole AI.

## Prerequisites

Before you begin, make sure you have:

- A Capriole AI account ([Sign up here](https://capriole.ai))
- A Capriole AI API key ([Get your key](https://capriole.ai?view=api))

## Installation

Install GitHub Copilot CLI with npm:

```bash
npm install -g @github/copilot
```

Verify the install:

```bash
copilot --version
```

You do not need to sign in to GitHub when `COPILOT_PROVIDER_BASE_URL` is set.

## Configuration

### Model validation

GitHub Copilot CLI 1.0.100 passes a file-read, file-write, and final-answer check through Capriole AI with every model in [Supported models](#supported-models), using the profiles below.

Copilot CLI uses one provider at a time, so pick the profile for the model family you want. Each profile sets two model values:

- `COPILOT_PROVIDER_WIRE_MODEL` is the Capriole AI model ID that Copilot sends.
- `COPILOT_PROVIDER_MODEL_ID` is a model that Copilot knows. Copilot uses it to choose its tools, prompts, and token limits.

### GPT models

GPT models use the Responses API:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="responses"
export COPILOT_PROVIDER_MODEL_ID="gpt-6-astra"
export COPILOT_PROVIDER_WIRE_MODEL="openai-latest"
```

For GPT-6.1 Sol, set `COPILOT_PROVIDER_MODEL_ID="gpt-6.1-sol"` and `COPILOT_PROVIDER_WIRE_MODEL="openai/gpt-6.1-sol"`.

### Claude models

Claude models use Anthropic Messages:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="anthropic"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com"
export COPILOT_PROVIDER_BEARER_TOKEN="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"
export COPILOT_PROVIDER_WIRE_MODEL="claude-latest"
```

For Opus 5.5, set `COPILOT_PROVIDER_WIRE_MODEL="claude-opus-5-5"`.

- `COPILOT_PROVIDER_BEARER_TOKEN` sends the key as a Bearer token. `COPILOT_PROVIDER_API_KEY` would send it in an `x-api-key` header, which Capriole AI does not accept.
- The base URL has no `/v1`, because Copilot adds `/v1/messages` itself.
- Keep `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`. With an older profile such as `claude-sonnet-4`, Copilot sends a thinking budget, and Opus 5.5 rejects it with `requires adaptive thinking`.

### Gemini, Grok, GLM, and Kimi models

These models use Chat Completions:

```bash
export CAPRIOLE_AI_API_KEY="YOUR_CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_TYPE="openai"
export COPILOT_PROVIDER_BASE_URL="https://api.caprioletech.com/v1"
export COPILOT_PROVIDER_API_KEY="$CAPRIOLE_AI_API_KEY"
export COPILOT_PROVIDER_WIRE_API="completions"
export COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"
export COPILOT_PROVIDER_WIRE_MODEL="moonshot/kimi-k3"
```

Change `COPILOT_PROVIDER_WIRE_MODEL` to `google/gemini-3.8-flash`, `xai/grok-4.7`, or `zai/glm-5.3-flash` for the other models.

Keep `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`. With a GPT profile such as `gpt-5.4`, Copilot sends tool types that these models reject.

To keep a profile, add its lines to `~/.zshrc` or `~/.bashrc`, then open a new terminal.

## Run GitHub Copilot CLI

Start Copilot CLI from your project directory:

```bash
copilot
```

For a non-interactive run, pass a prompt with `-p`:

```bash
copilot -p "Explain this repository." --allow-all-tools
```

## Supported models

| Model | `COPILOT_PROVIDER_WIRE_MODEL` | `COPILOT_PROVIDER_MODEL_ID` | Protocol |
| --- | --- | --- | --- |
| OpenAI latest | `openai-latest` | `gpt-6-astra` | Responses |
| GPT-6.1 Sol | `openai/gpt-6.1-sol` | `gpt-6.1-sol` | Responses |
| Claude latest | `claude-latest` | `claude-opus-4.6` | Anthropic Messages |
| Opus 5.5 | `claude-opus-5-5` | `claude-opus-4.6` | Anthropic Messages |
| Gemini 3.8 Flash | `google/gemini-3.8-flash` | `claude-sonnet-4` | Chat Completions |
| Grok 4.7 | `xai/grok-4.7` | `claude-sonnet-4` | Chat Completions |
| GLM 5.3 Flash | `zai/glm-5.3-flash` | `claude-sonnet-4` | Chat Completions |
| Kimi K3 | `moonshot/kimi-k3` | `claude-sonnet-4` | Chat Completions |

`openai-latest` and `claude-latest` always point to our latest flagship in each family.

## Troubleshooting

### Why does Copilot CLI return an authentication error?

Confirm that `CAPRIOLE_AI_API_KEY` is exported in the same shell. For Claude models, use `COPILOT_PROVIDER_BEARER_TOKEN`, not `COPILOT_PROVIDER_API_KEY`.

### Why do requests fail with endpoint errors?

For GPT, Gemini, Grok, GLM, and Kimi models, `COPILOT_PROVIDER_BASE_URL` is `https://api.caprioletech.com/v1`. For Claude models, it is `https://api.caprioletech.com` without `/v1`.

### Why does Opus 5.5 fail with `requires adaptive thinking`?

Set `COPILOT_PROVIDER_MODEL_ID="claude-opus-4.6"`.

### Why do Gemini, Grok, GLM, or Kimi requests fail with a tools error?

Set `COPILOT_PROVIDER_MODEL_ID="claude-sonnet-4"`. A GPT profile sends tool types that only OpenAI models accept.

## Notes

- Copilot CLI runs coding tools on your computer. Capriole AI only handles the model requests.
- Run `copilot help providers` to see every BYOK environment variable.
- Official references: [Install GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli) and [Use BYOK models in Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models).
