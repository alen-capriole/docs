One multi-model subscription can reduce the cost and setup involved in using models from several providers. The original ChatGPT, Claude, and Gemini products remain separate subscriptions with their own features.

Capriole AI is an alternative workspace. Its Premium plan costs **USD 8 per month** for unlimited browser chat across the supported Premium model set, including supported models from OpenAI, Anthropic, Google, xAI, Z.AI, and Moonshot AI. Premium also includes **5 million charged API tokens per month**. It does not include official provider subscriptions, and it does not reproduce every provider-native feature.

Capriole puts supported models, chat history, API access, and coding-agent setup under one account.

## The problem is larger than the monthly bill

Using several AI products usually means several browser tabs, billing pages, histories, interfaces, and sets of controls. A conversation that begins in one product may need a different model later. Moving it then becomes a small migration: copy the useful context, reattach files, explain the task again, and learn which controls the next interface exposes.

API work adds provider accounts, keys, balances, model names, and incompatible request formats. Coding agents add another configuration layer. None of these steps is individually difficult, but together they turn model choice into account administration.

Capriole AI brings the common parts into one workspace. You can chat with a supported model, change models inside the conversation, work with files or web search, and keep the thread in the same interface. The product handles the protocol and context differences behind that switch.

## What the USD 8 plan includes

| Part of the plan | What is included | Important boundary |
|---|---|---|
| Premium browser chat | Unlimited chat across the supported Premium model set | This is Capriole's web workspace, not access to provider-native apps |
| Monthly API allowance | 5 million charged API tokens | API usage consumes the allowance; it is not unlimited |
| API top-ups | Additional token packs can be purchased | Top-ups are separate from the monthly subscription |
| Coding agents | A Capriole API key can be used with documented integrations | Support is limited to the maintained protocol and model paths |
| Free access | Limited browser chat before upgrading | Free access does not include the public API |

The browser and API have different usage models. Premium browser chat has no per-message token balance for the user to manage. API requests are metered because programmatic workloads can grow far beyond normal chat use.

The plan suits someone who chats every day and also needs occasional or moderate API access. A developer with a large production workload should compare metered costs and limits against a dedicated gateway or direct provider contract.

## Team access uses a shared balance

The Team plan costs **USD 70 per month** and includes five seats plus a shared monthly pool of **50 million charged API tokens**. Active roles are owner, admin, and member. Owners and admins can manage invitations, roles, member usage thresholds, billing, and Team top-ups.

Team members use their own API keys, while successful Team-billed requests draw first from the shared monthly quota and then from the Team top-up wallet. This is a separate entitlement from personal Premium, not five individual Premium subscriptions.

## One conversation, different model strengths

Different model families are useful for different parts of the same task. A thread may start with research, move into careful writing, and end with code or structured analysis. Separate products make the user carry the context between them.

Capriole lets the conversation stay in one workspace while the selected model changes. The visible action is a model choice. Underneath it, message formats, context limits, reasoning controls, files, tools, streaming events, token accounting, and errors may all need different handling.

Capriole maintains that adaptation as part of the product. A unified workspace therefore does more than place several model buttons on one page.

Capriole also provides latest-model aliases for supported API and agent workflows. They allow a configuration to follow Capriole's recommended current model for a provider family without requiring the user to update every exact model identifier immediately.

Eligible paid access unlocks Capriole's public API as well as browser chat. The [API quickstart](/quickstart) covers the first request, while maintained guides support six coding agents: [Codex](/integrations/codex), [Claude Code](/integrations/claude-code), [Kilo Code](/integrations/kilo-code), [GitHub Copilot CLI](/integrations/github-copilot-cli), [OpenCode](/integrations/opencode), and [OpenClaw](/integrations/openclaw).

## Choose where chat history lives

Not every conversation deserves the same storage policy.

| Mode | Where chat history remains | Across devices | Uploads |
|---|---|---|---|
| Synced | Capriole account storage | Yes | Available |
| Local | This browser's local storage | No | Disabled |
| No Storage | Memory for the current page session only | No | Disabled |

Local history survives a refresh until that browser's site data is cleared. No Storage history is lost when the page refreshes or the user leaves, and enabling it first asks for confirmation before deleting existing server and local chat history.

All three modes still send each request through Capriole and the selected model service. They control chat-history persistence; they do not promise zero operational records or replace the selected provider's data policy. Read the [chat storage guide](/guides/chat-storage) before using sensitive or regulated data.

## When one workspace is the right trade-off

Capriole AI is a good fit when the main problems are subscription cost, repeated setup, interface switching, and carrying context between models. It is also useful when browser chat and coding-agent access need to live under the same account.

Keep a provider's official subscription when you depend on features unique to that provider, need its exact product controls, or want access to models and tools outside Capriole's supported set. Use a broad gateway or direct API contract when model breadth, BYOK, provider selection, or high-volume infrastructure control matters more than an included browser workspace.

The original products still matter when their native features are required. Capriole covers the common multi-model workflow with fewer accounts and less repeated setup.
